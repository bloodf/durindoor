---
title: VPS and cloud
description: Run DurinDoor on a VPS with systemd, HOSTNAME, and a reverse proxy in front.
---

A VPS or home server that should stay up across logouts. Docker on that host is [Docker](./docker.mdx). This page is a source install under systemd, loopback bind, and a proxy on the same machine.

Do this before the process is reachable from the internet:

1. Set `JWT_SECRET` (`openssl rand -hex 32`). Fresh data dirs fail closed without it. An existing `DATA_DIR/jwt-secret` file is reused with a warning.
2. Set `API_KEY_SECRET` the same way if minted keys must survive recreate.
3. Set `INITIAL_PASSWORD` to something other than `123456`. Remote login with the built-in password is refused.
4. Set `DATA_DIR` to a disk you back up.
5. Plan TLS at a reverse proxy. DurinDoor itself speaks HTTP.
6. Restrict the dashboard: VPN, firewall, proxy auth, or a trusted network.
7. Back up `DATA_DIR` before every upgrade.

Full lists: [Environment variables](../reference/environment.mdx), [Security](../operations/security.mdx).

<Callout type="warn">
`HOSTNAME=0.0.0.0` binds every interface. The dashboard can start tunnels and other host commands. Leave `HOSTNAME` unset so `custom-server.js` pins `127.0.0.1`, then proxy to that loopback port. Set `0.0.0.0` only when the proxy is not on this host, and put authentication in front of it.
</Callout>

<Steps>
<Step>
Install Node.js 20.20.2 and npm 10.8.2. Clone the repo, then:

```bash
npm install --no-audit --no-fund
npm run build
```

`npm run start` is `node .next/standalone/custom-server.js`. Port default is 20128.

</Step>
<Step>
Write an env file the unit will load, for example `/etc/durindoor.env` mode `0600`:

```bash
NODE_ENV=production
PORT=20128
HOSTNAME=127.0.0.1
DATA_DIR=/var/lib/durindoor
JWT_SECRET=replace-me
API_KEY_SECRET=replace-me
INITIAL_PASSWORD=replace-me
BASE_URL=https://durindoor.example.com
NEXT_PUBLIC_BASE_URL=https://durindoor.example.com
AUTH_COOKIE_SECURE=true
```

`BASE_URL` / `NEXT_PUBLIC_BASE_URL` are the public HTTPS origin. `custom-server.js` strips `X-Forwarded-Host` and `X-Forwarded-Proto` on every request, so OIDC and cookies cannot take those from the client. Point them at the proxy's origin.

</Step>
<Step>
Install a systemd unit. Paths below are examples; point `WorkingDirectory` at the clone and `DATA_DIR` at the volume you created.

```ini
[Unit]
Description=DurinDoor
After=network.target

[Service]
Type=simple
User=durindoor
Group=durindoor
WorkingDirectory=/opt/durindoor
EnvironmentFile=/etc/durindoor.env
ExecStart=/usr/bin/node /opt/durindoor/.next/standalone/custom-server.js
Restart=always
RestartSec=5

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now durindoor
curl -fsS http://127.0.0.1:20128/api/health
```

Expect `{"ok":true}`. Logs: `journalctl -u durindoor -f`.

</Step>
<Step>
Put nginx or Caddy on 443, proxy to `http://127.0.0.1:20128`. Overwrite `X-Forwarded-For` with the client address; do not append. Snippets: [Reverse proxy and static assets](./reverse-proxy-and-static-assets.mdx). After `npm run build`, `npm run verify:static` checks that `/dashboard` hashed assets return 200.

</Step>
</Steps>

## `HOSTNAME=0.0.0.0`

| How you start | Default bind |
| --- | --- |
| `npm run start` / systemd `custom-server.js` | `127.0.0.1` if `HOSTNAME` is unset |
| `npm run dev` | `127.0.0.1` if `HOSTNAME` is unset |
| CLI `durindoor` | `0.0.0.0` (`--host` overrides) |
| Docker image / Compose | `0.0.0.0` |

Same-host proxy: keep `127.0.0.1` so `custom-server.js` treats the proxy as a loopback hop and can trust `X-Forwarded-For`. Other-host proxy or a raw public bind: `HOSTNAME=0.0.0.0`, firewall the port, and do not skip the [security](../operations/security.mdx) list.

## Health and restart

```bash
curl http://127.0.0.1:20128/api/health
sudo systemctl restart durindoor
```

Restart after changing `PORT`, `HOSTNAME`, `DATA_DIR`, `JWT_SECRET`, `API_KEY_SECRET`, proxy env, or OAuth URL overrides. Dashboard settings stored in SQLite do not need a process restart.

Upgrade: back up `DATA_DIR`, `git pull`, `npm install --no-audit --no-fund`, `npm run build`, restart the unit. [Upgrading](../operations/upgrading.mdx). Docker tag moves: [Docker](./docker.mdx).
