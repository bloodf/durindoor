Image: `ghcr.io/bloodf/durindoor`. Builds are linux/amd64 and linux/arm64. Node 20.20.2 is already in the image. Persist `DATA_DIR`.

Tags come from `.github/workflows/docker-publish.yml`. A `v*` git tag (or a manual `workflow_dispatch`) builds and pushes `ghcr.io/bloodf/durindoor`. Semver tags use `{{version}}` (tag `v4.3.0` publishes `4.3.0`). `latest` is added only when that tag is on the default branch. Pin a version tag in production. `latest` moves.

<Callout type="warn">
Without a bind mount or named volume, SQLite lives in the container writable layer and disappears when the container is removed. Mount something at `/app/data` and set `DATA_DIR=/app/data`.
</Callout>

## docker run

Localhost-only publish, host bind at `$HOME/.durindoor`:

```bash
docker run -d \
  --name durindoor \
  -p 127.0.0.1:20128:20128 \
  -v "$HOME/.durindoor:/app/data" \
  -e DATA_DIR=/app/data \
  -e JWT_SECRET="$(openssl rand -hex 32)" \
  -e INITIAL_PASSWORD="$(openssl rand -hex 16)" \
  ghcr.io/bloodf/durindoor:latest
```

`$HOME/.durindoor` on the host is not the native default (`~/.9router`). Inside the container, `DATA_DIR` is `/app/data`. Open `http://localhost:20128/dashboard`. Sign in, change the password, add a provider, mint a DurinDoor API key.

`JWT_SECRET` is required on a fresh data dir. An older `DATA_DIR/jwt-secret` file is reused with a warning. DurinDoor does not write a new one.

To listen on all host interfaces, change the publish to `-p 20128:20128` and put a reverse proxy in front. See [VPS and cloud](cloud.mdx) and [Security](../operations/security.md).

## Compose

Copy `docker-compose.yml` from the repo, or:

```bash
curl -fsSL https://raw.githubusercontent.com/bloodf/durindoor/main/docker-compose.yml -o docker-compose.yml
```

The `durindoor` service in that file:

| Key | Value |
| --- | --- |
| `image` | `ghcr.io/bloodf/durindoor:latest` |
| `container_name` | `durindoor` |
| `restart` | `always` |
| `ports` | `20128:20128` |
| volume | named volume `durindoor-data` at `/app/data` |
| `env_file` | `.env` |
| `DATA_DIR` | `/app/data` |
| `PORT` | `20128` |
| `HOSTNAME` | `0.0.0.0` |
| `NODE_ENV` | `production` |

`HOSTNAME=0.0.0.0` is required inside the container so the process accepts traffic from Docker's port publish. The image Dockerfile sets the same `PORT`, `HOSTNAME`, and `DATA_DIR`.

Put secrets in `.env`. Compose also forwards optional `DURINDOOR_PG_URL`, `DURINDOOR_PG_SSLMODE` (default `prefer`), and `DURINDOOR_PG_PREFERRED_VERSION` (default `18`). Postgres is opt-in: `docker compose --profile postgres18 up` (or `postgres17` / `postgres16`). Cutover is Settings, then Database. Operator runbook: [Postgres](../operations/postgres.md).

```bash
docker compose up -d
```

`.dockerignore` keeps `.env`, `node_modules`, `.next`, and the `website/` docs site out of the build context. Inject env at run time with `--env-file` or `env_file`.

## Volumes and `DATA_DIR`

| Place | Path |
| --- | --- |
| Host bind (run example) | `$HOME/.durindoor` |
| Named volume | `durindoor-data` (volume name `durindoor-data`) |
| Container data root | `/app/data` |
| SQLite | `/app/data/db/data.sqlite` |

Bind:

```bash
-v "$HOME/.durindoor:/app/data"
```

Named volume:

```bash
-v durindoor-data:/app/data
```

The image entrypoint `chown`s `/app/data` to `node` then `exec`s `node custom-server.js`. `EXPOSE 20128`. Backup and restore for both mount styles: [Data management](../operations/data-management.md).

## Image layout

The runtime stage copies `public/`, `.next/static/`, the Next standalone tree, `custom-server.js`, `open-sse/`, and the MITM sources the tracer drops. If you fork the Dockerfile, keep those `COPY` lines or the dashboard 404s hashed chunks. Confirm a source build with `npm run verify:static` before you change the image; see [Reverse proxy and static assets](reverse-proxy-and-static-assets.mdx).

## Health and logs

```bash
curl http://localhost:20128/api/health
docker logs -f durindoor
```

`{"ok":true}` means the HTTP listener is up. Compose does not ship a `healthcheck` on the `durindoor` service.

## Upgrade

1. Stop and back up `DATA_DIR` ([Data management](../operations/data-management.md)).
2. Record the current tag: `docker inspect durindoor --format '{{.Config.Image}}'`.
3. Change the image tag in Compose, or pull a pinned tag.
4. `docker compose pull` then `docker compose up -d`.
5. `curl http://localhost:20128/api/health`.

One-container replace:

```bash
docker pull ghcr.io/bloodf/durindoor:latest
docker stop durindoor && docker rm durindoor
# re-run the docker run command with the same volume and env
```

If a schema migration already ran, restore the pre-upgrade backup before starting an older image. Release notes: [Upgrading](../operations/upgrading.md).

Keep `JWT_SECRET` and `API_KEY_SECRET` stable across recreate. A new `API_KEY_SECRET` invalidates minted key checksums. [Environment variables](../reference/environment.md) is the full list.
