---
title: "ChatGPT Web Codex"
---

ChatGPT Web Codex uses your signed-in ChatGPT web session to access the performance lanes exposed by the Codex web provider. It is a browser-session integration: create a ChatGPT Web connection and supply your own session cookies. DurinDoor encrypts stored connection credentials using its normal provider connection storage.

## Setup

1. Sign in to [chatgpt.com](https://chatgpt.com) with the account you want to use.
2. In DurinDoor, add **ChatGPT Web Codex** and choose the cookie capture extension or dashboard import.
3. Capture the `chatgpt.com` session, or paste a Cookie header, a cURL command containing a Cookie header, or a local HAR export that contains a `chatgpt.com` request.
4. Save the connection and select one of `luna`, `think`, `instant`, `medium`, `high`, `extra-high`, or `pro`.

The import accepts the `__Secure-next-auth.session-token` cookie, including its numbered chunks. Do not share or publish the Cookie header: it grants access to your signed-in account. To renew an expired connection, capture or import the current session again.

## Request behavior and limits

The provider uses the ChatGPT Web session exchange, Sentinel requirements and conversation endpoint implemented by DurinDoor's ChatGPT Web transport. Requests use a fresh conversation with the selected lane. The session endpoint validates credentials; 401 and 403 responses indicate an invalid or expired session, while 429 is preserved as a quota or rate-limit response. Model availability, plan access and rate limits are controlled by OpenAI and may change.

The Codex lanes are mapped to DurinDoor's supported ChatGPT Web model performance lanes. This compatibility integration does not provide native Codex `/v1/responses` thread continuity or Codex-specific tool execution. Images and ordinary chat are supported to the extent supported by the shared ChatGPT Web conversation transport.
