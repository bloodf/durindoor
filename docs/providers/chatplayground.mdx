ChatPlayground uses the signed-in session cookie from `web.chatplayground.ai`. It does not use an API key. The gateway uses `https://web.chatplayground.ai/api/models` for discovery and sends every chat model to `https://web.chatplayground.ai/api/chat`. ChatPlayground does not publish a reference for these web-app endpoints.

## Setup

Sign in to ChatPlayground, then capture the `Cookie` request header from an authenticated request to `web.chatplayground.ai`. Import it with the cookie capture extension, paste the `Cookie:` header copied from cURL, or extract the request cookie from a HAR export. Keep the `__client` and `__session` cookies. Treat them as passwords.

The gateway resolves a short-lived Clerk session token and picks the model by its catalog id. Model availability and session expiration are controlled by ChatPlayground.

## Request limits

The upstream route accepts one message per request. The gateway sends a single-turn request as is. It renders a longer conversation as a plain-text transcript followed by the last turn.

- Each message, and the rendered transcript, is limited to 15,000 characters.
- Inline images and other content without text are rejected with HTTP 400.
- Sampling fields such as `temperature` and `max_tokens`, and `tools`, are not sent upstream.
- The gateway asks ChatPlayground not to save the conversation.

An upstream error event, or a reply that ends early, is reported as an error.

If you saved model ids from the earlier catalog, refresh the model list. Ids now come from the current catalog.

Sources: [ChatPlayground](https://web.chatplayground.ai/).
