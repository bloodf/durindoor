A provider is a registry upstream such as OpenAI, Claude Code, or Ollama Local. A connection is one saved credential for that provider; you can keep several and DurinDoor will try another account when the current one fails. A provider node is a custom OpenAI-compatible or Anthropic-compatible endpoint you add yourself, with its own prefix and base URL.

Open Dashboard, then Providers. Registry cards group OAuth, API key, cookie, free, and custom nodes. Account fallback stays on the same provider and model; combo fallback is a different chain.

| Term | Meaning |
| --- | --- |
| Provider | A registry id (`openai`, `claude`, `ollama-local`) or a node id (`openai-compatible-chat-...`). |
| Connection | One credential row: OAuth tokens, API key, or cookie. Priority decides fill-first order. |
| Provider node | A user-added OpenAI-compatible, Anthropic-compatible, or embedding endpoint. |
| Account fallback | Next connection for the same provider and model after a fallback-worthy error. |
| Combo fallback | Next model in a combo after every account for the current member has failed. |

| Credential | Typical providers | Where it is documented |
| --- | --- | --- |
| OAuth | Claude Code, Codex, Gemini CLI, GitHub | [Connecting accounts](./connecting-accounts.mdx) |
| Cookie | Grok Web, Kimi Web, and other `webCookie` ids | [Web cookie providers](./web-cookie.mdx) |
| API key | OpenAI, Anthropic, Groq, Azure | [API key providers](./api-key-providers.mdx) |
| Compatible node | Your own `/v1` gateway | [OpenAI-compatible nodes](./openai-compatible-nodes.mdx) |
| Local / no-auth | Ollama, LM Studio, Horde | [Free and local](./free-and-local.mdx) |

## Add and test a connection

1. Open **Providers** and choose a visible provider card. For a custom gateway, use **Add OpenAI Compatible** or **Add Anthropic Compatible**. Embedding-only nodes are under **Media Providers**.
2. Follow the credential guide for OAuth, cookies, an API key, or a local server.
3. Save the connection and check its active state and model selection.
4. List models from `GET /v1/models`, then send a [first request](../getting-started/first-request.mdx).
5. Confirm the selected provider and account on **Usage**.

A saved credential or successful probe does not prove chat, streaming, tools, or media work. The [catalog](./catalog.mdx) includes registry metadata, including hidden or unsupported entries. The dashboard and a real request establish what your instance can use.

If an account is unavailable, routing can try another eligible connection for the same provider and model. A [combo](../features/combos.mdx) can then try another model. Priority controls fill-first order; other strategies are optional. Scope client keys when only selected accounts should be reachable.
