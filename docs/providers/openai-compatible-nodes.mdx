title: OpenAI-compatible nodes
description: Add custom chat, Responses, Anthropic, or embedding endpoints and verify their model IDs.

A provider node is an endpoint DurinDoor does not ship as a registry provider. Use it for an internal gateway, a self-hosted vLLM, a vendor that only speaks OpenAI or Anthropic routes, or an embeddings-only server.

Open Dashboard, then Providers. The Custom Providers section has Add OpenAI Compatible and Add Anthropic Compatible. Give the node a stable prefix so clients can request `prefix/model`.

## OpenAI-compatible

<Steps>
<Step>
Click Add OpenAI Compatible. Name and prefix are required. Prefix is the client-facing provider token in `prefix/model` strings, for example `oc-prod/llama-3.1-70b`.
</Step>
<Step>
Pick Chat Completions or Responses API. Default base URL is `https://api.openai.com/v1`. Point it at your gateway, including the `/v1` suffix the upstream expects.
</Step>
<Step>
Save, then open the node and add a connection. The API key is optional. Leave it empty when the upstream does not check auth, and save one when it does. DurinDoor sends no `Authorization` header when no key is saved.
</Step>
<Step>
Add model names, or enable passthrough if the node should forward unknown ids. An empty saved model list exposes no models for that node. Use Import on the node page to discover `/v1/models` from the upstream, then save the rows you want.
</Step>
</Steps>

`GET /v1/models` on DurinDoor is the list clients should trust. Discovery against the node needs `providerSpecificData.baseUrl`; a token is optional.

### Delegated Devin inference through CLIProxyAPI

Deploy and authorize CLIProxyAPI separately. The operator manages its upstream Devin authorization and decides which model IDs the proxy exposes. In DurinDoor, add an OpenAI-compatible **Chat Completions** node with a prefix such as `devin-proxy` and a base URL such as `http://127.0.0.1:8317/v1` if both services run on the same host. Use an address reachable from DurinDoor when they run separately.

Add a connection using a CLIProxyAPI gateway key. Import models from that connection and save the IDs you want to expose. Keep the full ID returned by the proxy, including any slashes. Call DurinDoor with a DurinDoor API key and `devin-proxy/<advertised-id>` as the model. To select an account, send its DurinDoor connection ID in `X-Connection-ID`. When issuing separate client keys, scope each one to its allowed connections. The public model catalog can include live discoveries from the node’s active connection. The connection scope governs request dispatch.

At the pinned CLIProxyAPI revision, `GET /v1/models` returns an OpenAI list object with model entries in `data`. `POST /v1/chat/completions` accepts `model`, `messages`, and `stream`, returning JSON for non-streaming requests or `text/event-stream` with `data:` frames ending in `[DONE]`. Both routes accept a configured proxy key in `Authorization: Bearer`. [Route registration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/api/server_routes.go#L68-L77) · [Key authentication](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/access/config_access/provider.go#L55-L104) · [OpenAI handlers](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/api/handlers/openai/openai_handlers.go)

The closed fixture verifies connection-specific discovery, selected-account chat, gateway key enforcement, and local token accounting for JSON and SSE. Devin CLI ACP runs a local subprocess for agent-protocol messages. Hosted Devin agent sessions use session operations for agent tasks. This proxy setup exposes chat inference. Direct hosted inference and live upstream authorization remain unverified.

### JSON schema response formats

On a custom OpenAI-compatible connection, DurinDoor changes `response_format: json_schema` to `json_object` and writes the schema into the system message. Many gateways accept only that form. If your upstream supports native structured output, open the connection's Edit dialog on a Chat Completions node and turn on **Native JSON schema support**. DurinDoor then sends the `json_schema` format and the messages unchanged. The setting is stored as `providerSpecificData.nativeJsonSchema` and is off by default.

## Anthropic-compatible

Same Providers page, Add Anthropic Compatible. Default base URL is `https://api.anthropic.com/v1`. If you paste a URL that already ends in `/messages`, DurinDoor strips that suffix so runtime does not double it.

DurinDoor translates OpenAI-shaped client requests to Claude Messages when the node needs it. Tools, images, reasoning, and streaming do not always map. Test those before you put the node in a combo.

Third-party Anthropic gateways that are not `api.anthropic.com` get both `x-api-key` and `Authorization: Bearer` so either header style works.

## Custom embeddings

Embedding-only nodes live under Dashboard, Media providers, embedding. Create an embedding-only node there. A trailing `/embeddings` on the base URL is stripped. Default base URL is `https://api.openai.com/v1`. Clients call `/v1/embeddings`.

## Quota display for compatible connections

OpenAI-compatible and Anthropic-compatible connections have no fixed billing endpoint, so DurinDoor cannot show Provider Limits for them out of the box. Set `providerSpecificData.quotaEndpoint` on the connection (via `PUT /api/providers/{id}`) to describe where the quota lives and how to read it:

```json
{
  "providerSpecificData": {
  "quotaEndpoint": {
    "url": "https://api.example.com/v1/credits",
    "method": "GET",
    "auth": "bearer",
    "headers": { "X-Org": "acme" },
    "quotas": {
      "credits": {
        "used": "$.data.used_usd",
        "total": "$.data.limit_usd",
        "resetAt": "$.data.renews_at",
        "currency": "usd"
      }
    }
  }
  }
}
```

`auth` is `bearer` (default), `x-api-key`, or `none`. The connection's saved API key is sent as the credential; `none` sends no auth header. `used`/`total`/`resetAt` are dot/bracket paths into the JSON response (`$.a.b[0].c`), not full JSONPath. A quota only shows up once `total` resolves; a path that cannot resolve is left out rather than reported as 0/0.

Some providers publish only what is left. Map `remaining` instead of `total` for those:

```json
{
  "quotas": {
    "credits": { "remaining": "$.credits", "currency": "credits" }
  }
}
```

A remaining-only quota is reported as a balance with no known total, so it has no usage percentage and counts as empty only when the balance reaches exactly zero. If you map `total` as well, `total` wins and the balance is ignored; if `total` is mapped but missing from the response, the quota is left out instead of falling back to the balance.

## Aliases and naming

Keep the prefix lowercase and stable. Leave the upstream model id after the slash alone. Avoid spaces.

```text
oc-lab/llama-3.1-70b
ac-internal/claude-sonnet
emb-search/text-embedding-model
coding-default
```

`coding-default` is a combo or a model alias, not a node prefix. Model aliases map a short client name to an existing model ID. They do not create an additional top-level catalog row for that short name. Combos are a fallback chain; see [Combos](../features/combos.mdx).

Dedicated local registry ids (`ollama-local`, `lm-studio`, `vllm`) are usually a better fit than a generic node when one exists. Those ids omit `Authorization` when no key is saved. Compatible nodes omit it too when no key is saved. See [Local router providers](./local-router-providers.mdx), [Free and local](./free-and-local.mdx), and [Network LLM servers](./network-llm-servers.mdx).

If DurinDoor runs in Docker, `localhost` inside the container is the container. Use a compose service name or the host gateway for a server that runs on the machine.

Validate the URL before saving the node. Only `http` and `https` are accepted. The probe is SSRF-guarded and stops after 10 seconds. Connection refused, DNS failure, and certificate errors come back as that 400/403 payload rather than hanging the dashboard.

Icon URLs are optional and validated before saving. A missing name or prefix is rejected with 400.

Custom nodes may reject content-part arrays, tool calls, or unknown OpenAI fields. Prefer one node per upstream behavior rather than mixing incompatible models behind the same prefix.

Before you put a node in a combo: confirm `GET /v1/models` lists the names you expect, send a small chat request, then test streaming and tools if your clients need them. Test images, audio, or embeddings only when those routes are in play. Usage logs show provider name, model name, latency, and errors.
