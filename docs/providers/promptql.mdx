# PromptQL (experimental)

PromptQL is staged as an unofficial, experimental integration for a user's own signed-in playground session. It calls the playground GraphQL operations with the project-scoped `enrich-token` JWT and project ID. This is reverse-engineered web application behavior and is not a documented third-party API. Use it only while it works with your account; PromptQL can change the web app, auth flow, model catalog, or limits without notice.

## Setup

Sign in at [prompt.ql.app](https://prompt.ql.app), open browser developer tools, and inspect a playground GraphQL request to `data.prompt.ql.app`. Copy the `Authorization: Bearer …` value without the `Bearer` prefix. It must be the playground `enrich-token` JWT (claims include the PromptQL Hasura project ID), not a DDN/project token. Supply that JWT and the project ID in the connection's provider-specific data (`token` and `projectId`).

Import the PromptQL session cookies through DurinDoor's cookie import. The integration uses those cookies only to refresh a near-expiry token through the playground's project-token endpoint; if refresh is unavailable, re-import the session and token. The cookie-import capture profile permits the PromptQL playground and its `ql.app` auth domain. You can also paste the `Cookie` header from a request, copy cookie values from browser storage, or import a HAR/cURL capture. Treat the imported session, JWT, and project ID as credentials: do not include real values in logs, issues, or test fixtures.

## Models, limits, and errors

Model discovery reads the signed-in project's `FetchLlmConfigs` GraphQL catalog. The staged model list is an offline fallback. Chat starts a roomless PromptQL thread, sends the latest user message, and polls thread events until it can return an OpenAI-compatible completion or stream. Follow-up requests may pass `promptql_thread_id` or `X-PromptQL-Thread-Id` to continue a thread.

Usage and billing follow the PromptQL account/project. DurinDoor maps expired/unauthorized sessions to 401 and quota/rate limiting to 429. This web session flow has not been independently verified as a supported vendor API contract; model availability, billing, refresh behavior, and limits may vary. No separate usage endpoint is exposed by this staged module.
