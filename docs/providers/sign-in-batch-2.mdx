---
title: Qwen, iFlow, Kiro and Copilot sign-in
description: Sign in to Qwen Code, iFlow, Kiro, GitHub Copilot and GitHub Enterprise Copilot, and know when to reconnect.
---

Use **Providers → Add connection** and choose the provider that issued your
credential. Each connection keeps its own account and selected proxy. Choose
the proxy before you start sign-in: the connection keeps using the route that
carried its sign-in.

## Qwen Code (`qwen`, alias `qw`)

1. Choose **Qwen Code** and start sign-in.
2. Open the verification URL shown in the dashboard and enter the code.
3. Keep the dashboard open until the connection appears.

The terminal CLI offers the same device sign-in. Qwen Cloud API keys
(`qwen-cloud`) are a separate provider with their own regions. Do not import
them into Qwen Code.

## iFlow (`iflow`, alias `if`)

1. Choose **iFlow AI** and start OAuth.
2. Sign in on the iFlow page and let it redirect back to the dashboard.

To import a session instead, paste one `BXAuth` cookie from your own iFlow
session. Import rotates the platform API key once. If the response is lost,
check your connections before you import again. Responses never show the
stored key.

## Kiro (`kiro`, alias `kr`)

1. Choose **Kiro AI**, then choose **AWS Builder ID** or your organization's
   **AWS IAM Identity Center**.
2. For IAM Identity Center, enter your organization's start URL and region.
3. Open the device page and approve the request.

When you reconnect an organization account, use the same start URL and region.

## GitHub Copilot (`github`, alias `gh`)

1. Choose **GitHub Copilot** and start device sign-in. The terminal CLI offers
   the same flow.
2. Open the GitHub device page, enter the code, and approve it with the
   account that holds the Copilot subscription.

## GitHub Enterprise Copilot (`ghe-copilot`, alias `ghe`)

1. Choose **GitHub Enterprise Copilot** in the dashboard.
2. Enter your enterprise HTTPS origin, for example
   `https://github.example.com` (GitHub Enterprise Server) or
   `https://tenant.ghe.com` (GHE.com).
3. Open the device page on that host and enter the code.

The connection is bound to that host, the sign-in client and the proxy you
selected. Requests, model discovery, connection tests and token refresh all
use that host and proxy, and redirects are refused. The terminal CLI cannot
start enterprise sign-in because it cannot send the enterprise origin.

**Reconnect when:**

- An older connection has only an API URL and no enterprise origin. An API URL
  cannot show which host issued the credential, so the connection is refused
  until you sign in again with the enterprise origin.
- An older connection's Copilot session cannot be renewed and states no expiry.
- You change the connection's proxy. The new route must match the route used
  at sign-in.

## Cancelled, expired and refused sign-in

A cancelled or expired code, or a refused authorization, saves nothing. Start
a new sign-in. A finished sign-in cannot be completed a second time.

Public GitHub, GitHub Enterprise and Microsoft 365 Copilot Web are separate
identities. Credentials from one cannot be used for another.
