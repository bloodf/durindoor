# Tencent AI Studio Web

Tencent AI Studio Web routes chat requests through your signed-in [aistudio.tencent.ai](https://aistudio.tencent.ai) browser session. DurinDoor stores the Cookie header and replays it to the site. No API key is involved.

## Setup

1. Sign in at [aistudio.tencent.ai](https://aistudio.tencent.ai).
2. Capture the session cookie one of these ways:
   - **Cookie capture extension.** Open the extension on the signed-in tab and send the cookies to DurinDoor.
   - **Pasted Cookie header.** In DevTools, open a request to `aistudio.tencent.ai`, copy the `Cookie` request header, and paste it into **Import cookies** or the add-connection dialog. A leading `Cookie:` is ignored.
   - **Pasted cURL command.** Use *Copy as cURL* on a request to `aistudio.tencent.ai`. The command is read, never run.
   - **HAR file.** Export a HAR from the Network tab. It is parsed in your browser and never uploaded. Remove unrelated requests first.
3. Use the models as `tasw/<model>`, for example `tasw/hy3-g`.

Only cookies for `aistudio.tencent.ai` are imported. The import profile requires the `sessionid` cookie.

## Models

| Model | Upstream route |
| --- | --- |
| `hy3-g` | `/api/chat/HunyuanDefault` |
| `hunyuan-default` | `/api/chat/HunyuanDefault` |
| `hunyuan-3d` | `/api/chat/Hunyuan3D` |

The same models are served on `/v1/chat/completions` and `/v1/messages`, as JSON or as a stream. Tool calling is not supported.

## Session and error handling

- **Validation.** A `GET /api/user/info` with the cookie must answer `200`. `401`, `403` or a redirect to sign-in means the session expired; sign in again and replace the cookie. `429` or a network failure is reported as unavailable, not as a bad cookie.
- **Chat.** A rejected session returns `401 authentication_error`. A rate limit or quota response returns `429 rate_limit_error` and keeps any `Retry-After`. Other failures keep their status.
- **Isolation.** Each connection sends only its own cookie, and the cookie is redacted from logged headers.
- **Response shape.** The upstream is treated as OpenAI Chat Completions compatible, as in the source. If it answers JSON to a streaming request, or SSE to a non-streaming one, DurinDoor reshapes it to what the caller asked for.

## Limits

Availability, quotas and rate limits are set by Tencent and can change. A cookie session is tied to your account and may be revoked at any time. DurinDoor sends `stream` in the request body in addition to the `model` and `messages` fields the source sends.

Live capture is unverified. The pinned OmniRoute source forwards the whole Cookie header and names neither a session cookie nor a validation request, so the `sessionid` allowlist that **Import cookies** and the extension use, and the `GET /api/user/info` validation request, are this port's assumptions. Neither was confirmed against a real signed-in capture. If an import with only `sessionid` fails to chat, paste the full Cookie header in the add dialog instead; the executor forwards it unchanged.
