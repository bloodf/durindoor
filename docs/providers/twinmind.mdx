title: TwinMind
description: Experimental TwinMind app API with Firebase tokens; the provider is registered but chat dispatch is not ported yet.
---

The pinned OmniRoute integration uses TwinMind's app API rather than an OpenAI-compatible API. Chat is a provider-specific envelope at `https://api2.twinmind.com/api/v3/chat`; credentials are Firebase ID tokens and may require refresh. DurinDoor registers the provider so a connection can be saved, but its executor is not ported yet: a chat request returns HTTP 501 with `type: "provider_port_pending"`, and Validate and Test Connection never send the saved token to TwinMind.

## Setup and limits

The app API is experimental and the provider-specific authentication lifecycle is not covered by a vendor public API contract. The pinned integration uses fallback models and attempts authenticated model discovery. Do not treat this entry as a generally supported API-key connection.

## Cookie capture

Cookie capture is not the authentication mechanism in the pinned integration. Do not share Firebase tokens, cookies, pasted cURL headers, or HAR files without removing credentials.
