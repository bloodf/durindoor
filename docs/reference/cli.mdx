The `durindoor` npm package starts the bundled standalone server. Its `admin` command reads local gateway data. The package requires Node.js `>=24.22.2 <25`; the repository pins Node.js `24.22.2` (`.nvmrc`) and pnpm `12.18.0`.

```bash
npm install --global durindoor
durindoor --host 127.0.0.1
```

`npx durindoor` runs the same launcher without a global install. The default dashboard URL is `http://localhost:20128/dashboard`; the client base URL is `http://localhost:20128/v1`. Source `npm start` has a separate [startup path](../operations/startup.mdx).

## Runtime and artifact evidence

The engine range is a declared requirement, not a claim that every version or platform in it has been exercised. Use the pinned Node.js `24.22.2` for source work; versions below `24.22.2` and Node 25 or later are outside the declared range. The Docker image supplies its own Node runtime.

| Platform and artifact | Evidence | Limit |
| --- | --- | --- |
| Linux x64, Node 24.22.2, source CLI helper | Offline `unit/1143-runtime-compat.test.js` runs launcher-generated heap arguments in real Node child processes. | Covers heap precedence only; it does not start the server or validate a packaged artifact. |
| Linux x64, Node 24.22.2, staged fixtures | Offline `unit/1143-artifact-compat.test.js` runs copied CLI help/version paths with a machine-ID stub, loads copied standalone sidecars, and checks artifact entry validation. | Run with a minimal Vitest configuration; the linked dependencies could not resolve `vite` from the repository configuration. No built or packed artifact, server startup, database, worker, tray, or web session was exercised. |
| Source standalone server | `scripts/smoke-installed-artifact.mjs` provides a standalone artifact check. | Availability of a check is not evidence that it passed on a particular platform. |
| npm package | `scripts/smoke-npm-pack.mjs` provides a packed artifact check. | No packed artifact or installation was validated by the offline test above. |
| Docker image | The Dockerfile builds a standalone server into an image with a Node runtime. | No image, architecture, or container runtime was tested by the offline test above. |
| macOS, Windows, other architectures and other Node versions | Platform-specific launcher paths exist. | No execution evidence is claimed here. |

For a runtime change, record the exact Node version, operating system, architecture and artifact, then run the appropriate smoke check on that target. See [Upgrading](../operations/upgrading.mdx) for backup, migration and rollback steps.

## Flags

| Flag | Default | Effect |
| --- | --- | --- |
| `-p, --port <port>` | `PORT` or `20128` | Listen port, an integer from `1` through `65535`. |
| `-H, --host <host>` | `0.0.0.0` | Bind address. Requires a value. `127.0.0.1` restricts access to this machine. |
| `-n, --no-browser` | off | Accepted for compatibility. Startup does not automatically open a browser with either value. |
| `-l, --log` | off | Show server stdout and stderr. Without it, stdout is hidden and stderr retains a 50-line crash buffer. |
| `-t, --tray` | off | Start in tray mode and skip the terminal menu. |
| `--headless` | off | Run without browser, tray or interactive menu; overrides `--tray`. |
| `--skip-update` | off | Skip the npm registry version check. Without a TTY, this also selects tray mode. |
| `-h, --help` | | Print usage and exit `0`. |
| `-v, --version` | | Print the installed package version and exit `0`. |

`--host` and `--port` require a value. Missing values, a next argument beginning
with `--`, or a port outside the stated range exit with status `2`.

## Admin command

With the gateway running, retrieve a local combo by ID:

```bash
durindoor admin combos get <id>
durindoor admin combos get <id> --port 20129
durindoor admin --help
```

The command prints the existing combo API response as JSON. It uses loopback HTTP
and the local management token from the server's `DATA_DIR`; it does not start
the gateway or contact model providers. Invalid arguments exit `2`; API or
connection failures exit `1`. Launcher flags such as `--host` are not accepted.

<Callout type="warn">
The default bind accepts connections on all interfaces. Remote access requires the settings in [Security](../operations/security.mdx).
</Callout>

## Heap and DNS

The server prefers IPv4 DNS results. The default V8 heap cap is `6144` MB.

| `NINEROUTER_MAX_OLD_SPACE_SIZE` | Effect |
| --- | --- |
| unset | Add `--max-old-space-size=6144`. |
| `0` | Add no heap flag; Node selects the heap size. |
| positive integer | Set the heap cap to that many MB. |
| other value | Print a warning and use the unset behavior. |

When the dedicated setting is unset or invalid, an existing `--max-old-space-size` or `--max_old_space_size` in `NODE_OPTIONS` prevents the default flag. A positive dedicated setting supplies a command-line flag that takes precedence over `NODE_OPTIONS`; `0` adds no flag, leaving any `NODE_OPTIONS` setting in effect. The launcher leaves `NODE_OPTIONS` intact.

```bash
NINEROUTER_MAX_OLD_SPACE_SIZE=8192 durindoor
```

## Persistent data and optional dependencies

`DATA_DIR` defaults to `~/.9router` on macOS and Linux, or `%APPDATA%\9router` on Windows. Windows ignores a Unix-style configured path. An unwritable configured directory falls back to the platform default. See [Data management](../operations/data-management.mdx) for files and backups.

Optional dependencies live under `DATA_DIR/runtime/node_modules`. A missing bundled WASM triggers installation of `sql.js@1.14.1`. Postinstall can install `better-sqlite3@12.10.1`; startup does not wait for a native build. macOS and Linux use `systray2@2.1.4`; Windows uses PowerShell `NotifyIcon`. Optional-install failure does not prevent server startup.

## Tray and terminal menu

Readiness probes `http://127.0.0.1:<port>/api/health` for up to 60 seconds. The tray can attach even when readiness fails; the terminal menu waits for readiness.

The tray supports macOS, Windows, and Linux with `DISPLAY` set. Other environments run the server without an icon. Its menu opens the dashboard, toggles login autostart, or quits. Quit stops MITM, Headroom, tunnels, and the server.

The terminal menu offers **Web UI**, **Terminal UI**, **Hide to Tray**, and **Exit**. An available update adds **Update**. Terminal UI manages providers, keys, combos, CLI tools, and settings through the local API.

**Hide to Tray** keeps the same process on macOS. On Windows and Linux, it replaces the current server with a detached tray launcher using `--tray --skip-update -p <port>`. The first hide enables autostart once; `DATA_DIR/autostart-decided` records that choice. Tray mode ignores `SIGHUP` so closing the terminal does not stop it.

Login entries retain compatibility names:

| Platform | Entry |
| --- | --- |
| macOS | `~/Library/LaunchAgents/com.9router.autostart.plist`; logs at `/tmp/9router.log` |
| Windows | `%APPDATA%\Microsoft\Windows\Start Menu\Programs\Startup\9router.vbs` |
| Linux | `~/.config/autostart/9router.desktop` |

## Updates

Startup checks `https://registry.npmjs.org/durindoor/latest` unless `--skip-update` is set. The request timeout is 3 seconds, with an 8-second safety timeout. Check failure does not prevent startup.

**Update** prints the install command, cleans up, and exits `0`; it does not execute npm. Back up `DATA_DIR`, review [Upgrading](../operations/upgrading.mdx), then install and restart:

```bash
npm i -g durindoor@latest --prefer-online
durindoor
```

`npm update --global durindoor` is another manual update path.

In the dashboard, manual **Copy & Shutdown** copies the install command and a restart command. When the launcher is in tray mode, the restart command includes `--tray`.

## Process lifecycle

Before startup, the launcher recovers stale MITM ownership, removes leftover app processes, and tries to free the listen port. If MITM cleanup cannot be confirmed, startup stops to preserve redirect ownership. A missing bundled server exits `1` with a reinstall message.

Foreground `SIGINT`, `SIGTERM`, and `SIGHUP` trigger cleanup. Cleanup keeps the server alive if MITM ownership cannot be released safely.

The launcher restarts a crashed server up to twice. A run lasting 30 seconds resets the counter. Repeated crashes trigger one MITM recovery worker before exit `1`; failed recovery can retain that worker for a cleanup retry.
