# AI Studio Build and hosted Devin delegation

Reviewed DurinDoor integration base `875900d9b79526ecff37b5a3a6d264b7e9e004dd` on 2026-11-20. Its existing `cliproxyapi` (`cpa`) registry entry already sends OpenAI Chat Completions to the loopback sidecar with each saved connection's bearer key. This change supplies its missing `/v1/models` discovery descriptor. The same descriptor enables the existing dashboard fetch and sync surfaces and the gateway's live catalog resolver. The provider keeps its empty static catalog, so model IDs come from the operator's deployment.

CLIProxyAPI assigns a transient `aistudio-*` session identity on upgrade and registers the logical provider `aistudio`. The executor correlates replies and streaming frames to the active relay and request. Disconnect tears down pending requests and removes the registration. The contract is in `sdk/cliproxy/service_auth.go`, `internal/wsrelay/{manager,session,message}.go`, and `internal/runtime/executor/aistudio_executor.go`. Application identity is the proxy-assigned channel. A channel name is neither a Google principal nor an upstream account ACL. DurinDoor selects the model by the unique alias exposed by the authenticated proxy and leaves relay lifecycle and upstream selection there. Gemini CLI uses Cloud Code Assist HTTP independently. DurinDoor's Devin cloud-agent and ACP paths are independent of delegated hosted inference.

`tests/unit/aistudio-relay-provider.test.js` exercises the local routes against a closed in-process sidecar fixture. Its lifecycle is a contract model for the behavior visible from DurinDoor. The fixture covers relay admission, disconnect and discovery, gateway connection scoping, provider routing, JSON and SSE usage, and provider errors. No upstream code was copied.
