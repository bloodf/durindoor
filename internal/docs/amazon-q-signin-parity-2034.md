# Amazon Q sign-in comparison (#2034)

The reviewed snapshots are [CLIProxyAPI `6faa8d20`](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d), [EasyCLIProxyAPI `e4223d5e`](https://github.com/router-for-me/EasyCLIProxyAPI/tree/e4223d5eefa22a3301ca7e2a28d05897432b07f9), and [OmniRoute `e3c1531a`](https://github.com/cheaper-inference/OmniRoute/tree/e3c1531afd07d5e06f7ffab658584a7ae2e3627e). CLIProxyAPI's [executor registration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/cliproxy/service_executors.go) does not register Amazon Q or Kiro. EasyCLIProxyAPI's [guided setup](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx) does not offer a named Amazon Q or Kiro login; request dispatch is delegated to its core or plugins, whose deployed version is not fixed by this snapshot. OmniRoute implements the related Kiro contract in its [OAuth provider](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/lib/oauth/providers/kiro.ts), [import route](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/app/api/oauth/kiro/import/route.ts), [refresh provider](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/services/tokenRefresh/providers/kiro.ts), and [EventStream executor](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/executors/kiro.ts). These Kiro paths do not establish a separate Amazon Q account identity.

OmniRoute omits the fixed registration issuer for enterprise Identity Center and probes profile regions separately from the token region. DurinDoor currently supplies its configured issuer at registration, discovers a profile in the selected region and retains the selected region for requests. Neither cross-region probing nor changing issuer handling is justified by the synthetic tests here; those changes require evidence that preserves the existing issuer and regional egress boundaries. DurinDoor offers Kiro imports but does not expose them as Amazon Q imports; no credential extraction was performed.

`tests/unit/amazon-q-signin-parity.test.js` uses synthetic tokens and a closed fetch mock to exercise Builder ID and Identity Center registration, polling and profile selection, reject a malformed region, and inspect the separate executor identity and regional bearer headers. The existing Amazon Q route and provider tests cover route forwarding and adapter wiring. This evidence does not establish live AWS acceptance, token-import authorization, refresh isolation, EventStream request/response parity, or full account persistence separation. Those remain open for this work order.
