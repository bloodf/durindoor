# Antigravity contract comparison for #2034

Compared on 2026-11-19, without provider credentials or account traffic. These are source comparisons, not evidence that Google currently accepts any particular client, model, or account.

- [CLIProxyAPI at 6faa8d20b2673404cff70a2f2d9537ae0d0e684d](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d): [OAuth constants](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/auth/antigravity/constants.go) and [authentication and project provisioning](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/auth/antigravity/auth.go). Its client is embedded; DurinDoor deliberately requires operator-supplied client settings. Both request cloud-platform, userinfo email/profile, cclog and experimentsandconfigs; CLIProxyAPI also requests aicode. Both use Google authorization and token endpoints; CLIProxyAPI uses v2 userinfo and daily Cloud Code for project provisioning, while DurinDoor uses v1 userinfo and production Cloud Code. CLIProxyAPI loads a project first, then polls onboarding when missing and takes the returned project; this repair follows that control flow without copying credentials or adding scopes.
- [EasyCLIProxyAPI at e4223d5eefa22a3301ca7e2a28d05897432b07f9](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) is a desktop console managing a CLIProxyAPI core for this OAuth/proxy path, rather than an independent provider implementation. Its separate official-CLI ACP bridge is not the OAuth proxy path compared here.
- [OmniRoute release/v3.8.55 at fbd339668384803bc3a9d42370fc413a55e013d5](https://github.com/cheaper-inference/OmniRoute/tree/fbd339668384803bc3a9d42370fc413a55e013d5): [OAuth configuration](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/constants/oauth.ts), [OAuth provider](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/antigravity.ts), and [project bootstrap](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/antigravityProjectBootstrap.ts). It uses the same five scopes as DurinDoor, production bootstrap, and bounded onboarding when the project is missing. Its bootstrap also distinguishes a completed response without a project as requiring manual project setup; this change fails the sign-in instead of persisting an empty project.

[CLIProxyAPI's executor](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/antigravity_executor.go) and [OmniRoute's endpoint configuration](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/antigravityUpstream.ts) use daily Cloud Code generation endpoints. DurinDoor's registry and executor do likewise, sending bearer authorization and the configured IDE user agent; its bootstrap uses production Cloud Code. CLIProxyAPI uses separate header profiles for load and onboarding; OmniRoute defines profiles in [antigravityHeaders.ts](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/antigravityHeaders.ts). No header fingerprint changes are included here.

[CLIProxyAPI's model registry](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/registry/models/models.json) contains IDs including `claude-opus-4-6-thinking` and `claude-sonnet-4-6`. [OmniRoute's aliases](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/antigravityModelAliases.ts) map the 3.7 Flash display tiers to `gemini-3.7-flash-tiered`, and 3.1 Pro High to `gemini-pro-agent`. DurinDoor's registry maintains its own aliases and catalog; differences are not changed without a reproduced failure. OmniRoute's [usage service](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/usage/antigravity.ts) queries available-model quota and its weekly quota service adds group data; DurinDoor uses the corresponding available-model and weekly-summary calls in `open-sse/services/usage/google.js`.

For responses, CLIProxyAPI's [Claude translator](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/translator/antigravity/claude/antigravity_claude_response.go) and OmniRoute's [stream collector](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/antigravity/sseCollect.ts) handle Cloud Code response envelopes. The local flow test exercises wrapped candidate text and usage through both public chat formats in JSON and SSE; it does not establish parity for every tool, image, thought, or error response.
