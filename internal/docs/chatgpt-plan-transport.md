# Private ChatGPT plan transport

This unregistered module is an integration boundary, not an enabled provider. Future wiring must authenticate the caller, select the OAuth connection, validate its account grant and pass `{ id, accountId, credentialClass: "chatgpt-plan-oauth", accessToken }` and `{ allowed: true, connectionId, accountId }`. Both identifiers must match the selected connection. The grant is a trusted authorization decision, not client input; this module cannot validate a forged grant or establish token ownership. Refresh and revocation are the caller's responsibility. Never pass API keys or credentials from another OAuth flow.

`listChatgptPlanModels` fetches the current account catalog; `executeChatgptPlan` rechecks eligibility against that catalog before sending a Responses request. Both accept an abort signal and an optional fetch implementation for closed tests. The origin and paths are fixed, redirects are rejected, and no catalog or credentials are persisted. Streaming callers must consume the stream through its terminal event and distinguish completed, failed, incomplete and interrupted responses. The JSON facade returns the terminal Responses object, including usage; upstream HTTP errors pass through and terminal failures return 502 with their structured payload.

The protocol follows [OpenAI's models and inference guide](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference). Request normalization and the private descriptor are adapted from OmniRoute commit `b748429cf5b3aeb142a708fd3e8751b6918b9dc8`, `open-sse/executors/chatgpt.ts` and `open-sse/config/providers/registry/chatgpt/index.ts`.
