# ChatGPT Web compatibility — #2034

Comparison pins match [the #2034 source snapshot](antigravity-2034.md). This is a source and mock comparison, not a live provider validation.

- [CLIProxyAPI `6faa8d2`, `internal/auth/codex/siwc_auth.go`](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/auth/codex/siwc_auth.go) defines Sign in with ChatGPT as an OAuth authorization, token and refresh flow for Codex. Its [Codex executor](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/codex_executor_execute.go) and [model registry](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/registry/models/codex_client_models.json) implement a different contract from a user-supplied web session. The pinned source tree does not provide a comparable ChatGPT Web cookie executor; OAuth tokens and web cookies are not interchangeable.
- [EasyCLIProxyAPI `e4223d5`, README](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) describes Codex OAuth, management of the CLIProxyAPI core and requests through its unified endpoint. It delegates the proxy contract to that core, not an independent ChatGPT Web session implementation.
- [OmniRoute `fbd3396`, provider registry](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/chatgpt-web/index.ts), [credential validation](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/providers/validation/chatgptWeb.ts), [executor adapter](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/utils/chatgptWebExecutorAdapter.ts), and [first-party request](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/utils/chatgptWebFirstParty.ts) establish cookie/storage-state input, first-party origin checks, static model lanes and browser response adaptation. The pinned executor is browser-based. DurinDoor also retains its existing HTTP fallback and probes a pasted session with the session endpoint; browser cookie rotation is written back to the originating connection.

DurinDoor now exposes the pinned GPT-6 browser picker lanes and maps them to the corresponding first-party conversation models. Browser SSE is an OpenAI-formatted response produced after the browser turn completes, not incremental upstream token streaming. The HTTP fallback has not been validated for these new lanes; use browser transport for them. Availability, account entitlements, live model names, session expiry and provider policy were not tested. No browser, real credentials or provider requests were used for this comparison.

## Saved-cookie lifecycle (#2034)

Offline lifecycle evidence is `tests/unit/provider-cookie-lifecycle-chatgpt-grok.test.js`. It uses the real database, provider routes, `/v1/models`, `handleChat`, account fallback, executors and the usage route; only credentials and outbound bytes are synthetic. Source pins are the ones above, taken in the 2026-11-20 snapshot; they were reused here and not re-fetched. No ChatGPT account, browser, provider request or Docker was used.

Verified and covered: create with unordered chunked cookies, read-only session validation (chunks ordered, access token never returned, `{}` rejected), discovery of the GPT-6 lanes, JSON and SSE dispatch through the gateway, per-connection credential isolation, rotation written back only to the originating connection, HTTP-transport expiry as 401 before any conversation request, 401 fallback to a sibling and recovery after re-import.

Gaps found and fixed in DurinDoor (not ports; no upstream file was copied):

- `PUT /api/providers/[id]` ignored `apiKey` unless `authType` was `apikey`, so the Edit dialog silently dropped a re-pasted cookie for every cookie provider. It now replaces the cookie and clears model cooldowns, 401 backoff and `errorCode` recorded against the old one.
- The browser transport reported an upstream `conversation failed with status 401/403` as HTTP 502, which the fallback treats as a network error. `open-sse/executors/chatgpt-web.js` now maps it to 401/403 with the re-paste message, matching the HTTP transport.
- Non-streamed browser replies carried no `usage`, so they never reached Usage. They now carry the same four-characters-per-token estimate as the HTTP transport. `GET /api/usage/[connectionId]` returns local 30-day history for saved `chatgpt-web` and `grok-web` cookies instead of "not available".

Known limits, unchanged: no remote plan or quota API, browser SSE is produced after the turn, the HTTP transport cannot solve Turnstile, and no attestation is emulated.
