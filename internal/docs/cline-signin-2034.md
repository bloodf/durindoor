# Cline and ClinePass sign-in and request comparison (#2034)

This comparison uses the same pinned revisions as [the Antigravity comparison](./antigravity-2034.md). It does not use real credentials or call a provider.

- [CLIProxyAPI at `6faa8d20`](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d): its [README](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/README.md) and [example configuration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/config.example.yaml) describe supported OAuth providers and generic OpenAI-compatible providers. The pinned tree has no Cline-named implementation; generic API-key configuration is not evidence of a Cline account OAuth, refresh, catalog, or quota contract.
- [EasyCLIProxyAPI at `e4223d5e`](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) manages the CLIProxyAPI core and routes provider requests through its endpoint. Its listed OAuth entries do not include Cline; it does not establish an independent Cline OAuth implementation.
- OmniRoute at `fbd339668384803bc3a9d42370fc413a55e013d5`: [Cline OAuth provider](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/cline.ts) accepts URL-encoded embedded callback data and falls back to a JSON code exchange. Its [Cline](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/cline/index.ts) and [ClinePass](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/clinepass/index.ts) entries use separate identities, direct API keys or account OAuth, the same chat endpoint and distinct model namespaces. The [refresh implementation](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/tokenRefresh/providers/cline.ts) posts a JSON refresh grant; its [auth helper](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/shared/utils/clineAuth.ts) distinguishes OAuth from direct ClinePass keys.

DurinDoor keeps `cline` and `clinepass` connections separate. Both account flows accept URL-encoded embedded callback data and retain the JSON exchange fallback. The executor now applies Cline's credential normalization after generic bearer authentication: JWT-shaped account tokens receive `workos:` once, while opaque direct keys remain unchanged. This follows OmniRoute's OAuth callback decoding in `src/lib/oauth/providers/cline.ts` and its request-header intent in `src/shared/utils/clineAuth.ts`; the implementation preserves this fork's existing token-shape rules. Refresh and ClinePass percentage quota handling remain in `open-sse/services/tokenRefresh/providers.js` and `open-sse/services/usage/clinepass.js`.

Catalogs differ: [OmniRoute discovery](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/clinepassModels.ts) uses public recommended and full feeds; this fork uses authenticated `/api/v1/models`, keeps Cline live discovery opt-in, and maintains separate registry fallbacks. OmniRoute forces streaming for both providers; this fork does not. Neither difference was validated against a live account in this work, and no catalog or streaming behavior was changed. The pinned [usage implementation](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/usage/clinepass.ts) maps the same five-hour, weekly and monthly percentages; presentation and error handling differ.

`tests/unit/cline-signin-parity.test.js` exercises both OAuth entry points and outbound executor calls with fake credentials and closed mocks. Existing prefix, refresh, catalog and quota tests cover additional local behavior. These tests do not prove provider acceptance, every callback encoding, streaming conversion, model availability, billing or real-account quota behavior.
