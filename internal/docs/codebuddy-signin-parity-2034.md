# CodeBuddy sign-in and request comparison (#2034)

Snapshots: CLIProxyAPI `6faa8d20b2673404cff70a2f2d9537ae0d0e684d`, EasyCLIProxyAPI `e4223d5eefa22a3301ca7e2a28d05897432b07f9`, and OmniRoute `e3c1531afd07d5e06f7ffab658584a7ae2e3627e`.

OmniRoute's [CN OAuth adapter](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/lib/oauth/providers/codebuddy-cn.ts) uses [device auth](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/lib/oauth/providers/codebuddyDeviceAuth.ts): POST state with the platform in query and JSON, accept `authUrl` or `url`, then GET token with the state. DurinDoor now sends the platform and accepts either URL, retaining its existing pending-code handling. The mock regression exercises the public OAuth entry points and does not use a provider account. Token refresh is exercised with two distinct fake credentials, including refresh-token retention when rotation is omitted.

OmniRoute's [CN registry](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/config/providers/registry/codebuddy-cn/index.ts) and [CN executor](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/executors/codebuddy-cn.ts) use the Tencent chat host and forced streaming. DurinDoor retains its own server-aligned static catalog, including its existing alias, rather than replacing it with OmniRoute's fallback catalog; OmniRoute also documents authenticated discovery. The regression checks OAuth and API-key authorization, forced streaming and an upstream error; it does not validate stream aggregation or account-specific model discovery. Usage error coverage preserves the CN billing error message.

OmniRoute's [international OAuth adapter](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/lib/oauth/providers/codebuddy-intl.ts) uses separate configuration, and its [registry](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/config/providers/registry/codebuddy-intl/index.ts) targets `www.codebuddy.ai`. This is a distinct candidate, not an alias for the CN connection; it is not implemented here.

CLIProxyAPI's [executor registration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/cliproxy/service_executors.go) contains no built-in CodeBuddy executor. EasyCLIProxyAPI's [management API](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs) delegates OAuth and status to its core; it does not establish a CodeBuddy contract itself. Plugin or operator-defined support is not ruled out.

No provider calls or account credentials were used. The mocks do not establish live server acceptance, full session isolation, catalog discovery parity, stream reassembly, or international login and refresh compatibility. Further work requires independently sourced fixtures and the existing review and full-gate requirements.
