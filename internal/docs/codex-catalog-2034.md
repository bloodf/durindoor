# Codex catalog refresh

C4 compares CLIProxyAPI at [f5c5681](https://github.com/router-for-me/CLIProxyAPI/blob/f5c5681a8361c9da53e93c60b6507816eee7468b/cmd/fetch_codex_models/main.go) with DurinDoor's Codex models request. The pinned upstream fetches the first-party ChatGPT Codex models endpoint with a client version and account credential; its catalog tooling also synthesizes a baseline model. That synthetic entry does not establish account entitlement and is not added here.

Auto-sync uses the existing bounded refresh and the fixed first-party endpoint for each active saved Codex connection. Supported, visible entries compatible with the configured client version replace that connection's last successful roster. A failed or empty refresh retains it. Old provider-wide Codex snapshots are ignored because their account cannot be established. With auto-sync disabled or no successful scoped roster, existing static and live discovery behavior remains available. Existing aliases and custom models are not rewritten. The account header is derived from the selected credential; redirects are rejected for the refresh request. The comparison and tests use mocks and do not establish live account availability.
