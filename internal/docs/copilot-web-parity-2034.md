# Copilot Web session comparison (#2034)

Compared against DurinDoor base `835e22b37d2c3bcf0d9d4c4023589e3f241c0478` with synthetic credentials and closed request/socket mocks. GitHub Copilot is outside this comparison.

- **CLIProxyAPI**, pinned at [`6faa8d20b2673404cff70a2f2d9537ae0d0e684d`](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d): its [built-in auth implementations](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/auth) and [runtime executors](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor) have no named Microsoft personal Copilot Web or M365 Copilot Web adapter. Generic compatible endpoints and plugins do not establish either native session contract.
- **EasyCLIProxyAPI**, pinned at [`e4223d5eefa22a3301ca7e2a28d05897432b07f9`](https://github.com/router-for-me/EasyCLIProxyAPI/tree/e4223d5eefa22a3301ca7e2a28d05897432b07f9): the [guided OAuth provider list](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx) lists neither session. Its [README](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) describes management of the CLIProxyAPI core; runtime is delegated to that core. Installed plugins and arbitrary compatible endpoints are not inventoried as built-in support.
- **OmniRoute**, pinned at [`fbd339668384803bc3a9d42370fc413a55e013d5`](https://github.com/cheaper-inference/OmniRoute/tree/fbd339668384803bc3a9d42370fc413a55e013d5): [personal executor](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/copilot-web.ts) parses session credentials, starts a conversation, and streams websocket events; it retains a token-keyed conversation for up to an hour. DurinDoor deliberately starts a fresh conversation on every request, so credentials and unrelated histories are not reused. Personal session tokens have no local refresh grant. Its [M365 connection](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/copilot-m365-connection.ts) supplies distinct individual, education and work profiles; the local work profile follows OmniRoute #6334. Its [M365 executor](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/copilot-m365-web.ts) detects rewritten streaming snapshots and refreshes eligible OAuth credentials.
- OmniRoute additionally implements [work/school PKCE sign-in](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/copilot-m365-web.ts), including token expiry, refresh credentials and tenant identity routing. DurinDoor has **manual session entry only**, not this native OAuth flow or automatic refresh. Its M365 executor accepts the pasted token and user/tenant path; personal and M365 connections remain distinct. This is an outstanding compatibility gap, not a validated port.

The regression tests reproduce structured personal token parsing, rejected unrelated cookies, origin-scoped HAR selection, expired-session failure without cross-account reuse, work/individual isolation, and M365 snapshot rewrites through executor entry points. Existing tests cover both socket protocols. These mocks do not establish present-day provider acceptance, live token lifetimes, native OAuth/refresh, full upstream M365 tool/image handling, or cross-process behavior. No live provider calls or real sessions were used.
