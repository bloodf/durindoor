Both upstream projects have since removed Gemini CLI. [CLIProxyAPI commit `78ba8ba731dd531437947a6e0aadda4c13817907`](https://github.com/router-for-me/CLIProxyAPI/commit/78ba8ba731dd531437947a6e0aadda4c13817907) removes its Gemini CLI OAuth, executor, translators and related support; the executor was last present at [`dd49a5200381f1849e489ed37f201c3741709634`](https://github.com/router-for-me/CLIProxyAPI/tree/dd49a5200381f1849e489ed37f201c3741709634). ## Local flow and change

Dashboard `/api/oauth/[provider]/[action]` binds the authorization flow and calls `src/lib/oauth/providers.js` to exchange the code, retrieve user information and call `loadCodeAssist`. Gemini CLI uses an authorization-code flow without PKCE and Google refresh tokens. `open-sse/services/tokenRefresh.js` refreshes the CLI credential using its registry client. `src/sse/handlers/chat.js` lazily calls `open-sse/services/projectId.js` for a missing project; the latter can onboard and caches by connection ID. The CLI executor sends a Cloud Code HTTP envelope and the translators bridge OpenAI and Anthropic messages. The provider model resolver calls `fetchAvailableModels` and has a static registry catalog fallback. Gemini API-key, Vertex and Antigravity remain separate provider entries and transports.

Previously, a `loadCodeAssist` object without an ID was stored as `projectId`; its truthiness suppressed request-time discovery. Sign-in now accepts only a nonempty string or an object with a nonempty string `id`, trimmed, matching the existing discovery helper's parsing. Missing or malformed values remain empty. Existing stored credentials are not rewritten; reconnecting can refresh their project metadata.

`tests/unit/gemini-cli-signin-parity.test.js` uses fake credentials and closed mocks for sign-in exchange, refresh, project lookup/onboarding, catalog and OpenAI/Anthropic translation through the executor. The tests establish local wiring, not upstream acceptance. Live OAuth consent, token refresh, account provisioning, current model availability, streaming and gateway interoperability remain unverified. The initial exploratory executor test accidentally reached Google through the environment proxy with a fake bearer token and received HTTP 401; the test now mocks the proxy boundary and rejects unexpected outbound calls. No real credentials were used.
