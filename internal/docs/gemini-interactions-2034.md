DurinDoor uses separate connections for `gemini-interactions` and `gemini`. Existing Gemini GenerateContent, Gemini CLI, Vertex, Antigravity and media transports retain their own credentials and routing. The new native create handler adapts a single text turn through the existing chat gateway. Client-key admission, connection scopes, failover, proxy selection and usage recording therefore run through the same plumbing. The executor sends only a newly built foreground request with `store: false` to Google's fixed endpoint. Local response IDs have no retrieval or continuation semantics.

The implementation adapts CLIProxyAPI's native execution contract from [`internal/runtime/executor/gemini_executor.go`](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/gemini_executor.go), the revision header from [`internal/runtime/executor/helps/gemini_interactions.go`](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/helps/gemini_interactions.go), and the text/terminal mapping from [`internal/translator/openai/interactions/chat-completions/openai_interactions_response.go`](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/translator/openai/interactions/chat-completions/openai_interactions_response.go). Google model-list results are intersected with the static text subset from the overview. This deliberately limits discovery because the model-list response does not establish Interactions support on its own. Credential validation checks the list only and does not create an interaction.

Provider input, output, cached and thought tokens map onto the existing ledger. Chat completion tokens include thought tokens, while the native reply exposes Google's separate output and thought counts. Closed fixture coverage uses synthetic client and provider keys, a temporary SQLite database, and mocked model list and create responses. Live model availability and SDK interoperability have not been exercised.
