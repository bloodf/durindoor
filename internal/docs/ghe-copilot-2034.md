# Enterprise Copilot compatibility (#2034)

This comparison uses the revisions recorded in `antigravity-2034.md`.

- [CLIProxyAPI 6faa8d2 authentication implementations](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/auth) and [executors](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor) contain no Enterprise Copilot provider; its [README](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/README.md) describes supported authentication and compatible upstreams. There is no native enterprise device grant, scoped exchange, discovery or request contract to port from this revision.
- [EasyCLIProxyAPI e4223d5 README](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) describes a console managing the CLIProxyAPI core and lists its OAuth providers; it does not list an enterprise Copilot sign-in. Its proxy requests delegate to the core rather than establishing an independent enterprise contract.
- OmniRoute fbd3396 has an [enterprise device grant and scoped exchange](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/ghe-copilot.ts), [tenant-specific request routing and refresh](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/ghe-copilot.ts), and [enterprise discovery](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/app/api/providers/%5Bid%5D/models/route.ts) using the exchanged API endpoint. The discovery change follows that route; it does not copy upstream's fallback catalog behavior.

DurinDoor retains its existing device flow, HTTPS host validation, scoped token exchange and refresh, and GitHub-derived request handling. Enterprise model discovery now uses the connection's scoped Copilot token and resolved enterprise API host. It refuses to substitute the GitHub OAuth token when the scoped token is missing; refresh or reconnect the connection first. The API host takes precedence over the legacy proxy and enterprise-host fallbacks, as for requests. Consumer GitHub discovery remains separate.

The offline fixtures exercise two enterprise identities, tenant discovery, token refresh and endpoint routing, but do not establish compatibility with a real enterprise deployment, every model or response format, or all upstream error and expiry cases. Discovery does not automatically refresh an expired scoped token; a failed discovery is surfaced to the caller.
