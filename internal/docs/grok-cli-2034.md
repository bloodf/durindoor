# Grok CLI device authorization comparison (#2034)

The local Grok CLI provider uses device authorization and the Build Responses endpoint, distinct from xAI API credentials and Grok web SSO. The bulk-import endpoint accepts explicitly supplied OAuth tokens and redacts those tokens from item errors. Device authorization now validates the returned codes and verification URLs before presenting them; HTTPS and loopback HTTP are accepted. This validation follows [OmniRoute's Grok CLI provider, #7358](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/grok-cli.ts). Its [browser PKCE helper](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/grok-cli-oauth.ts) and [paste validation](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/utils/grokCliAuthJson.ts) describe additional import and login contracts; this change does not port them.

[CLIProxyAPI's Grok Build client](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/client/grokbuild/grokbuild.go) formats its model catalog for Grok Shell; this file does not implement Grok CLI sign-in. [EasyCLIProxyAPI](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) manages the CLIProxyAPI core and routes requests through it; it lists xAI OAuth and Grok Build as a client, not an independent Grok CLI login contract.

Tests use fake credentials and mocked network calls. They do not establish live provider compatibility, complete catalog parity, browser PKCE or full auth.json import parity. Further comparison of refresh and request behavior across all pinned implementations remains necessary.
