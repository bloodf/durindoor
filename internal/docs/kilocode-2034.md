# Kilo Code parity investigation (#2034)

The comparison is incomplete; the evidence below does not establish full request or model-discovery parity.

At OmniRoute revision [`fbd339668384803bc3a9d42370fc413a55e013d5`, `src/lib/oauth/providers/kilocode.ts`](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/oauth/providers/kilocode.ts), the device flow posts for a code, polls it, maps pending/denied/expired responses and returns the approved token without a refresh token. DurinDoor's `src/lib/oauth/providers.js` follows that exchange and additionally requests the profile and selects its first organization. The latter difference has not been validated against an authoritative account-selection contract, so it is retained.

The pinned EasyCLIProxyAPI revision [`e4223d5eefa22a3301ca7e2a28d05897432b07f9`, `src/pages/EasyModePage.tsx`](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx) and its [README](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) describe guided setup and delegation to the CLIProxyAPI core; the deployed core revision is not established by this desktop revision. The repository's [provider inventory](provider-parity-easycliproxyapi.md) records that limitation.

`tests/unit/kilocode-signin-parity.test.js` uses fake credentials and a closed fetch mock to cover the local device exchange, poll statuses, and executor header construction. It also checks that the distinct Kilo Gateway executor uses its own key without the Kilo Code organization header. It does not exercise actual request dispatch, per-connection model discovery, refresh dispatch, account selection, or live provider behavior. CLIProxyAPI at `6faa8d20b2673404cff70a2f2d9537ae0d0e684d` and OmniRoute's request and catalog implementations still require source tracing before concluding parity or changing behavior.
