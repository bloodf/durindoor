## DurinDoor

- In Providers, select **Kimi Coding (International)** for `kimi.ai`. Route models through `kimi-ai/<model>` or `kimi.ai/<model>`. The existing `kimi-coding` connection still uses `kmc/<model>` and also accepts `kimi.com/<model>`. The plain `kimi` platform key and `kmca` Coding key retain their separate identities and endpoints.
- The dashboard posts to `/api/oauth/{provider}/device-code` and `/api/oauth/{provider}/poll`. The existing flow store binds the private device code, device ID and egress selection to the canonical provider and an expiring opaque flow ID. Public start responses contain verification fields and the flow ID. Pending and slow-down responses keep the flow open. Expired, mismatched and consumed flows cannot write credentials. A successful poll writes the tokens, expiry and device metadata through the existing OAuth connection model and active-claim guard.
- Start, poll and refresh use the corresponding `auth.kimi.com` or `auth.kimi.ai` host. Both refresh entry points use the same form grant, retain the old refresh token if the provider omits a replacement and carry the sign-in device ID when present. The existing `KIMI_CODING_OAUTH_CLIENT_ID` override applies to the `.com` grant and its refresh. Previously stored Coding connections can still refresh without stored device metadata.
- Both Kimi device poll adapters require a non-blank string access token on success. A refresh token may be omitted, but when supplied it must also be a non-blank string. The adapter returns `invalid_response` for malformed credentials before the shared poller can save them. Pending and provider error replies continue through the existing OAuth flow handling.
- Anthropic requests enter through `/v1/messages` and the shared chat core. The default executor sends `.com` traffic through the existing native Anthropic transport when the client uses Anthropic. For `.ai` OAuth the gateway translates Anthropic Messages to the regional bearer-authenticated `/coding/v1/chat/completions` endpoint and converts the reply back. Kimi documents both regional wire protocols for third-party **API-key** integrations. The regional OAuth port follows the upstream adapter's documented source path for inference. [Kimi endpoint and authentication guide](https://www.kimi.ai/help/kimi-code/membership-guide).

## Verification

The pre-change focused test failed all four assertions. The international start returned HTTP 400 for an unsupported provider, `kimi.ai` had no registered alias or request route, and the existing Coding start lacked the device identity used in the upstream lifecycle. The closed mock suite exercises the real OAuth handlers and chat core, substituting the storage write and outbound transport. It checks expiry, cross-provider rejection, replay, credential rotation and Anthropic request/response handling for both hosts.

Live account eligibility, provider acceptance of DurinDoor's client identity, direct Anthropic wire requests with a `.ai` OAuth token, regional quota/model discovery and the installed EasyCLIProxyAPI core build remain unverified.
