# Kimi Web comparison for #2034

Source comparison at the pinned revisions below; no account or provider traffic was used.

- [CLIProxyAPI `6faa8d2`: Kimi OAuth](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/auth/kimi.go), [token storage and expiry](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/auth/kimi/token.go), [executor](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/kimi_executor.go), and [static catalog](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/registry/model_definitions.go) establish regional device OAuth, expiry and API requests, not the consumer web session. Its regional Coding credentials must not be treated as web tokens.
- [EasyCLIProxyAPI `e4223d5` provider selector](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx) offers Kimi OAuth; its [management API](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs) delegates to the managed core. This does not establish an independent web-session contract.
- [OmniRoute `fbd3396` registry](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/kimi/web/index.ts) distinguishes web from Coding OAuth and supplies a static catalog. Its [executor](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/kimi-web.ts) accepts a web access token or legacy cookie, sends a bearer token and Connect-framed JSON, and converts the streamed response for streaming or non-streaming clients. Its [refresh implementation](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/kimi/tokenRefresh.ts) uses a different refresh endpoint from this tree. Its [validation](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/src/lib/providers/validation/webProvidersA.ts) probes the web model service. Its [model runtime](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/kimi/web/runtime.ts) also differs in K3 scenario and effort mapping. Source alone does not prove which currently works.

DurinDoor accepts an authorized pasted session, tracks no proactive web expiry, probes and discovers against the selected origin, and refreshes on 401. Existing focused tests cover request framing, refresh retry, discovery and proxy dispatch. The new offline regression reproduces cross-origin reuse of a cached rotation and access-token disclosure in streamed error trailers, then verifies isolation and redaction. The origin-bound marker intentionally does not trust older persisted rotation markers; re-pasting may be required. No stored secrets are rewritten by this change.

Live service acceptance, changing upstream model metadata, account expiry, real proxy behavior and regional Coding OAuth interoperability were not validated. The local full gate and independent security review remain required before integration; this comparison does not establish complete parity.
