# Muse Spark Web investigation — #2034

Status: request compatibility remains unfinished. The registered web-cookie provider accepts an `ecto_1_sess` session through the web-login adapter or manual connection input, but normal executor dispatch deliberately returns `provider_port_pending` without an upstream request. The existing GraphQL executor is not wired into dispatch; its parser tests do not establish request compatibility. Its three registered model IDs are a static catalog, not proof of live model discovery.

Reference pins used for this investigation:

- [CLIProxyAPI at 6faa8d20: README](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/README.md) describes its provider and interface scope. This bounded README inspection does not establish repository-wide absence of Muse support.
- [EasyCLIProxyAPI at e4223d5: README](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) describes its CLIProxyAPI core management and provider authorization entry points. It does not establish an independent Muse web request contract.
- [OmniRoute at fbd3396: executor](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/muse-spark-web.ts) uses a WebSocket request path and accepts session and authorization inputs; its [response parser](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/muse-spark-web/response-parser.ts) covers GraphQL response parsing. Its [fresh-token path](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/executors/muse-spark-web/fresh-access-token.ts) uses a browser and extracts a token, outside this work order's permitted methods.

The local `muse-code` device grant and `meta-llama` API key are separate provider identities from the web-cookie session. The focused mock regression covers web-login session expiry, static catalog identities, OAuth provider separation, fail-closed dispatch for both web aliases, and isolated parser snapshots and authentication errors. It does not verify live session validity, upstream protocol, model discovery, real expiry responses, or end-to-end sign-in. No live provider, browser, or account was used. A compatible authorized non-browser request contract and its closed-mock coverage remain necessary before enabling dispatch.

The response parser follows OmniRoute's `open-sse/executors/muse-spark-web/response-parser.ts` error-state and security-block classifications: an assistant `streamingState: ERROR` is a failure, and security-block text maps to 403. This parser is still not reached by normal Muse Spark Web dispatch while the provider remains guarded.
