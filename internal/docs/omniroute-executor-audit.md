# Executor classification in the OmniRoute audit

The registry's `executor: "default"` does not establish DefaultExecutor routing.
The audit reads the upstream executor table with the existing Babel parser, without
importing TypeScript. Built-in canonical ids and aliases take precedence over the
fallback. Existing web, OAuth and explicit specialized classifications retain their
precedence. Dedicated registration overrides a contradictory default registry field.
This changes audit classification only; it does not enable or implement a provider.

Absence is proven only for the reviewed index, registry and fallback byte hashes
from commits `61e07fb7e0d4e1e76111495d3718c9e4d06d2a62` and
`191dce8d534ceb56c28a08e71381284a9a87838f`. Missing, malformed or changed source
produces unresolved evidence and `unknown` for otherwise default candidates.
A new upstream contract requires source review before adding its hashes.
The newer fallback's `muse-code` override is specialized too. Re-registration and
runtime extensions are outside static audit evidence; this is not runtime support.
Include `/open-sse/executors/` when preparing a sparse audit source checkout.

Fixtures preserve actual full index, registry, fallback and provider sources for
both commits as text. Regression proposals cover nlpcloud, oneminai, the actual
agentrouter default control, and missing/malformed/changed resolution contracts.
No matrix is regenerated by this patch. Existing stored matrices remain historical.
Tests and gates for this proposal are UNRUN; runtime acceptance is not claimed.
