# OrcaRouter sign-in and request comparison (#2034)

Comparison uses the locally inspected pinned revisions below. No upstream code was ported.

- [CLIProxyAPI `6faa8d20`](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/cliproxy/service_executors.go) has no OrcaRouter-specific provider or browser sign-in in its source tree. Its [OpenAI-compatible configuration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/config.example.yaml) and [executor](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/openai_compat_executor.go) provide generic configured-key routing, rather than an OrcaRouter-specific refresh or catalog contract.
- [EasyCLIProxyAPI `e4223d5e`](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx) exposes generic OpenAI-compatible configuration, not a dedicated OrcaRouter sign-in. Its [management API](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs) delegates to its separately versioned core; it does not establish an OrcaRouter callback, refresh or execution contract.
- [OmniRoute `e3c1531a`](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/config/providers/registry/orcarouter/index.ts) registers API-key bearer authentication, the default OpenAI executor and namespaced model IDs. Its [discovery provider set](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/app/api/providers/%5Bid%5D/models/discovery/providerSets.ts) includes OrcaRouter. The inspected tree has no OrcaRouter-specific OAuth adapter or refresh grant. This does not establish parity with DurinDoor's additional browser sign-in.

DurinDoor's [OAuth adapter](../../src/lib/oauth/orcarouterProvider.js) requests out-of-band S256 and exchanges the code for a durable key and account ID. The [OAuth route](../../src/app/api/oauth/[provider]/[action]/route.js) binds state and verifier to the server flow and consumes it on completion. [Origin and catalog helpers](../../open-sse/providers/orcarouterCatalog.js) constrain origins and select capability-scoped models; the [registry](../../open-sse/providers/registry/orcarouter.js) retains API-key routing. [Refresh dispatch](../../open-sse/services/tokenRefresh.js) does not refresh OrcaRouter credentials. Existing lifecycle coverage checks persistent account separation and revoked-key handling; the sign-in parity test exercises route binding and selected credentials with closed mocks.

No local behavior delta against an upstream OrcaRouter browser flow was established. These offline fixtures do not validate the current vendor consent page, issued key format, live catalog, account billing, or real request behavior. Those remain unverified under the no-live-calls constraint.
