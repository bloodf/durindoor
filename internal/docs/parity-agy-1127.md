## Default desktop profile implementation

DurinDoor now uses the public client pair from CLIProxyAPI `internal/auth/antigravity/constants.go` at `47f18e4d82bd72f7d2b5ecf5ede93e4837a4625e` only when both override variables are absent. Blank/incomplete overrides fail locally. The default adds `aicode` to the existing five scopes; custom clients retain those five scopes. Expanded scopes require reconnect and fresh consent. Configuration is read once at startup.

The callback follows that revision's `internal/auth/antigravity/auth.go`: `http://localhost:51121/oauth-callback`. Dashboard authorization pins it even for hosted/remote dashboards, and the existing manual callback URL paste flow carries state back to the server. Custom-client redirects remain caller supplied. The CLI listener uses the same port/path. S256 PKCE remains enabled in DurinDoor; authorization stores the exact redirect for token exchange. Client bindings remain `v1:sha256(public clientId)` and refresh never stamps legacy rows. Switching clients requires reauthorization or reverting configuration; mismatches, and every row under an invalid override, stop before leases and outbound calls.

Closed-network fixtures exercise dashboard authorize/exchange and Google refresh, both local and remote input redirects, custom overrides, invalid configuration, state and PKCE, plus existing real-entry-point binding/preflight tests for lease immutability, client switches/revert and reauthorization. These mocks do not prove live Google acceptance. No provider credentials or live provider calls were used.
