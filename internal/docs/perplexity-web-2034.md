# Perplexity Web comparison (#2034)

This is an offline source comparison, not a claim that these private web endpoints or model preferences currently work. Only user-supplied sessions are in scope; Perplexity API keys use the separate `perplexity` provider.

- [CLIProxyAPI at 6faa8d20](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d): the source tree contains no Perplexity provider implementation; [README](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/README.md) mentions a separate third-party scraper, not a core sign-in contract.
- [EasyCLIProxyAPI at e4223d5](https://github.com/router-for-me/EasyCLIProxyAPI/tree/e4223d5eefa22a3301ca7e2a28d05897432b07f9): no Perplexity implementation was found. Its [management API](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs) delegates general OAuth to the managed core; that is not evidence of a Perplexity sign-in flow.
- [OmniRoute at e3c1531](https://github.com/diegosouzapw/OmniRoute/tree/e3c1531afd07d5e06f7ffab658584a7ae2e3627e): the [web registry](https://github.com/diegosouzapw/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/config/providers/registry/perplexity/web/index.ts) uses a session cookie and a separate web executor. Its [executor](https://github.com/diegosouzapw/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/executors/perplexity-web.ts) and [protocol](https://github.com/diegosouzapw/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/executors/perplexity-web/protocol.ts) define model preferences, streaming, citations and expired-session handling. Its catalog and preferences differ from this tree; its cookie rotation also persists refreshed credentials. Neither is ported here without service validation and authorization to rewrite stored secrets. The upstream continuation cache is history-only; DurinDoor scopes it to the outbound credential.

DurinDoor validates pasted sessions using the read-only `/api/auth/session` probe, and its web executor accepts the supplied session cookie or bearer token. The executor retains its existing model and citation behavior and reports HTTP 401/403 as possible session expiry. Continuation cache keys use a digest of the effective credential and structured history, so identical conversations from different credentials cannot share a cached upstream thread. No secret is stored in the cache key. Missing credentials do not use the continuation cache.

Validation is limited to closed mock requests; no live sign-in, account, model availability, network transport, cookie rotation or real provider stream was tested. Source differences alone do not establish current upstream service compatibility. The focused regression does not exercise the dashboard or OAuth connection persistence.
