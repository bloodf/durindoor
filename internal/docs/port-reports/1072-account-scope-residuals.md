# 9router account-scope residual audit

Reviewed 2026-11-20 against DurinDoor `c5e1d234408feef1dee6a6748999b4e50a52f34d` and the final diff of [9router #5754](https://github.com/decolua/9router/pull/5754), head `43d49d2258e6a9206476424ccca62b0b520c96b9` (open, not merged). The [dated #1072 triage](https://github.com/bloodf/durindoor/issues/1072#issuecomment-7022045448) identified it as a candidate; the [refreshed #800 report](https://github.com/bloodf/durindoor/issues/800) is an inventory, not proof of a missing implementation. The [subsequent #1072 qualification](https://github.com/bloodf/durindoor/issues/1072#issuecomment-7035674631) requested this audit. The upstream diff also includes account ordering and quota-window features, outside this account-scope work order.

**Disposition: existing enforcement; no account-scope port.** Upstream adds an independent `accountsRestricted` flag and account ID list to key access, management UI and credential selection. Its restricted empty list denies all accounts; DurinDoor deliberately has a different established contract: no relation rows, including an explicitly cleared list and legacy records, mean unrestricted. Importing the upstream representation or its empty-list semantics would change that contract. `src/lib/db/repos/apiKeysRepo.js` validates and atomically saves account relations with key creation/update; `apiKeyProviderConnectionsRepo.js` documents the zero-row invariant. `connectionsRepo.js` blocks deleting the last selected account rather than silently broadening a key. `src/app/api/keys/` and the keys dashboard expose management; `docs/operations/api-key-scoping.mdx` documents the behavior.

The upstream selector filters account IDs before selection and rejects virtual no-auth credentials for restricted keys. DurinDoor's `src/sse/services/auth.js` intersects key relations with combo allow-lists, denies an empty intersection, filters before quota selection and keeps the scope on reselection. Chat, embeddings, image, speech, search, fetch, System One and Gemini native handlers pass the authenticated key ID into selection; media routing also filters by that identity. Existing `api-key-provider-account-scope.test.js` exercises two or more synthetic accounts, disjoint and overlapping intersection, and denied fallback; management and storage tests cover create, update, rollback and deletion; `api-key-provider-account-noauth.test.js` exercises mock requests with temporary synthetic data. The authorization matrix and combo allow-list suites cover admission and combo boundaries. These checks support the scoped disposition, not a claim that every possible route is exhaustively proven.

Upstream additionally filters its model picker by selected accounts. The local key editor and model policy picker have different workflows; that presentation change is not required for credential enforcement and is not a complete compatible account-scope port here. No dashboard files or approval inventory changed. Upstream's account-ordering and quota-window additions are separate features and are not assessed as part of this disposition.
