Disposition: **BLOCKED**. Reviewed [9router #5420](https://github.com/decolua/9router/pull/5420), open head `13bdcdf2bd54353da68d35393f041279198fea6e`, base `1fe586bb1cf35e1ed0cb2150a8ef7d1db040b21d`, and the preliminary [combo/history report](1072-combo-history-residuals.md). Its final patch changes `cli/README.md`, `cli/cli.js`, and `tests/unit/cli-foreground.test.js`. It adds an explicit attached `--foreground` mode, inherited output, no UI, conflict rejection for `--tray`, and exit handling without automatic restart. Unexpected child signals map to status 1; intentional launcher shutdown maps to 0.

The local launcher has a stronger worker ownership contract. `cleanup()` first requires manager-confirmed MITM cleanup and retains the worker if that fails. Ordinary worker exits, including exit 0 and a rejected handoff with stale ownership, restart the worker; exhaustion starts an identity-verified recovery worker and retains it if cleanup fails. A handoff is accepted only when the reserved exit code is accompanied by absence of stale ownership. Startup also has a separate detached recovery worker for stale ownership. These paths preserve the ability to manage existing redirect state; the upstream patch does not cover them.

An attached worker shares the launcher's process group on POSIX. A supervisor or terminal can signal that group, allowing the worker to terminate independently before launcher-side manager cleanup has succeeded. The launcher cannot guarantee retention of that worker on cleanup failure merely by avoiding a process-group kill. In addition, exiting immediately on a normal or signalled worker exit bypasses the local recovery path when ownership remains. Retrying a worker after that exit conflicts with the requested no-silent-relaunch contract. This focused unit has no established cross-platform contract that resolves both cases while preserving recovery and predictable supervisor-visible termination. Implementing only the upstream branch would weaken worker safety. No foreground option or user-help change was made.

A future design must specify and verify how group-delivered signals are coordinated with worker ownership, how cleanup failure retains a usable authenticated recovery surface, and how that recovery is reported without silently relaunching after normal exit or user termination. It must also define exit and signal results for cleanup failure and worker handoff across supported platforms, while preserving startup recovery and existing modes.

Validation is offline: the focused handoff test checks the ownership predicate; `cli-headless-tray.test.js` exercises mocked worker restarts, rejected handoffs, and recovery success/failure. The other requested selectors cover existing tray startup and readiness behavior. No live supervisor, machine process, credential, daemon, provider, or browser was used.
