The adaptation deliberately uses a separate `comboPrompts` settings map instead of activating upstream's `comboStrategies.*.systemPrompt`: existing strategy maps can carry arbitrary keys, so activating that legacy key would change existing combos. The map defaults empty, is limited to the existing 8,000-character custom-prompt limit per entry, is writable only with dashboard or CLI proof, and is hidden from unprivileged settings and MCP control reads. MCP control writes cannot change it. The map is documented in [Combos](../../../docs/features/combos.mdx).

Fallback and fusion carry instructions outer-to-inner on each eligible chat attempt; model and combo admission remain in place. `chatCore` injects the resulting ordered block at the existing translated system boundary, independent of token-saver bypass. Kiro retains its user-content prefix shape and no unsupported `systemPrompt` field is invented. Jev classification, Network routing and legacy strategy prompt keys remain unchanged. No dashboard source was changed, so Storybook inventory regeneration was not applicable.
