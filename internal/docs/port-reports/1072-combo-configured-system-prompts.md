The System One criteria do not map to DurinDoor's Jev tier classifier. The prompt portion remains applicable but is **not ported** in this assessment.
- [9router #5570](https://github.com/decolua/9router/pull/5570) is closed without merging; #5574 is its open successor. The closed source is ineligible.

The current settings API validates the global custom prompt against `MAX_CUSTOM_PROMPT_CHARS` and hides its text from unprivileged readers. It accepts the combo strategy map independently, however, and currently does not protect a nested prompt field. The upstream `systemPrompt` key cannot simply be activated: existing strategy maps can contain arbitrary keys, and existing combos must remain no-ops. A complete adaptation needs an explicitly managed field with equivalent read and write restrictions, validation, and preservation on unrelated strategy updates. It must propagate through both fallback and fusion paths, including nested combos, without exposing prompt contents or changing Jev and Network behavior.

`open-sse/rtk/systemInject.js` handles translated OpenAI, Responses, Claude, Gemini, and Kiro shapes with established idempotence rules; `chatCore.js` currently injects the global custom prompt at that boundary. A combo implementation must preserve client and global prompt handling and verify outer-to-inner order on native bodies, including Kiro's prefix behavior. No implementation or dashboard changes were made, and no Storybook approvals were added. This residual needs implementation and focused coverage for persistence, authorization, nested ordering, empty defaults, and native shapes before it can be considered ported.
