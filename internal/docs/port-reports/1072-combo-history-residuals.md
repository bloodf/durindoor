# #1072 combo, history, credential and CLI residuals

Preliminary comparison on 2026-11-20 against local base `8b89c143262b0bffdca90ab362e2c5f1bdabe93d`, the dated [#1072 intake](https://github.com/bloodf/durindoor/issues/1072), and [refreshed #800 report](800-scan-reconciliation.md). The intake labels these candidates, not evidence of equivalence. All five sources were open and unmerged at inspection. The comparisons below are incomplete; none is a completed port disposition.

- [#5316](https://github.com/decolua/9router/pull/5316), head `c0cd9e8e5b68b7629f5151e484f9d6b50fe19678`: upstream proposes retaining a successful combo member and account for two hours, scoped by client key, including fallback. Local `open-sse/services/combo.js` has round-robin conversation affinity only when the sticky request limit exceeds one; `tests/unit/combo-rr-fallback-advance.test.js` covers request-count rotation and `tests/unit/provider-session-sticky.test.js` covers account affinity. This is not equivalent. The repeated-request distinction, competing designs and key isolation still need complete evaluation.
- [#5433](https://github.com/decolua/9router/pull/5433), head `4ee6fdc64eda9dd7e78d62324b49c52bfab7a1d7`: adds per-combo system prompts, schema and persistence. Local chat currently passes the global custom prompt; the combination, migration and format semantics remain to be assessed.
- [#5575](https://github.com/decolua/9router/pull/5575), head `341c8dc267452f373debfa623e1e0bf8dd054e92`, depends on #5574. Combo UI includes prompt and router policy features. Usage adds route-attempt metadata and a by-combo aggregate; local `usageRepo.js` already persists `comboId` and `comboName`, with historical rows left null, but its daily aggregates do not have the proposed `byCombo` bucket. Non-streaming changes propagate attribution to `saveUsageStats`; local `nonStreamingHandler.js` and `sseToJsonHandler.js` already pass combo ID and name. Route statistics and rollup compatibility need further assessment independently of prompt UI.
- [#5336](https://github.com/decolua/9router/pull/5336), head `8fb491fd3bfa022af6c419f394697028977f5087`: upstream broadens quarantine to OAuth and explicit invalid API keys and adds repair/sign-in changes. Local `auth.js` quarantines permanent Codex OAuth errors and rejected OrcaRouter durable credentials, with a stale-credential guard; `accountFallback.js` deliberately distinguishes key rejection from permission errors. Generic API-key quarantine and safe replacement require further assessment without changing sign-in.
- [#5420](https://github.com/decolua/9router/pull/5420), head `13bdcdf2bd54353da68d35393f041279198fea6e`: upstream adds attached foreground supervision. Local `--headless` suppresses menu, browser and tray, but `spawnServer` detaches and `attachServerEvents` restarts the child. The fork additionally has MITM ownership and recovery safeguards, so upstream process and shutdown handling cannot be copied without reconciling those safeguards.
