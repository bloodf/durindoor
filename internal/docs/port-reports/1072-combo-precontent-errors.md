# #1072: combo pre-content errors from upstream #2068

Source: [9router #2068](https://github.com/decolua/9router/pull/2068), reviewed head `25f5bec5f69e20e00998fe9dcc42524217adf390`; see [the composite residual review](1072-composite-open-residuals.md). The source distinguishes peek errors and retains a request-scoped result while advancing eligible members. This port adopts that outcome only. The fork retains its own bounded stream peek, fallback, lifecycle and account handling; the upstream deadline ladder and retry budget are not ported.

A typed request-scoped error before content is retained as the first request-scoped candidate, projected through the existing sanitized client error builder. The stream envelope does not carry an HTTP status through the existing extractor, so these request errors project to 400. Eligible later members still run and a successful response wins; a refusal does not degrade model health. Existing exhaustion selection, including retry-after precedence, remains in force. Transport errors and genuinely empty streams retain their existing fallback and health behavior. Content and native Responses streams continue through the existing replay path.
