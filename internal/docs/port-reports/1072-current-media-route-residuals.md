# #1072 Current 9router image and video route residuals

Audited against the exact public patch heads below and the installed DurinDoor tree at this branch. No provider request, browser, or runtime API call was made. Scope is the installed image-edit and video formats/routes; Grok Web browser/session media behavior is not inferred or proposed.

## 9router #5548 — image edits

Source: [#5548](https://github.com/decolua/9router/pull/5548), audited head [`03753fde62338efacf83deb9c8ecd18f651a110a`](https://github.com/decolua/9router/commit/03753fde62338efacf83deb9c8ecd18f651a110a). The patch adds `/v1/images/edits` to translate multipart uploads into the generations request contract, plus an OpenAI-shaped JSON path. It also rejects masks/file IDs, sniffs raster bytes, bounds image/request sizes, and checks API-key admission before parsing uploads.

**Disposition: endpoint-absence residual is already resolved; do not port this endpoint.** Current [`src/app/api/v1/images/edits/route.js`](../../../src/app/api/v1/images/edits/route.js) exposes correlated `OPTIONS`/`POST` and dispatches to [`src/sse/handlers/imageEdit.js`](../../../src/sse/handlers/imageEdit.js). The handler retains the image-edit path through account selection and [`open-sse/handlers/imageEditCore.js`](../../../open-sse/handlers/imageEditCore.js): multipart is forwarded to the selected adapter with its resolved model, while JSON sources are accepted only for a JSON-native adapter. The published xAI adapter declares `imageEditConfig` with `format: "json"` in [`open-sse/providers/registry/xai.js`](../../../open-sse/providers/registry/xai.js); other adapters use their published edit endpoint and format. This is materially different from rewriting every edit as image generation and keeps provider transport boundaries intact.

The offline fixtures cover the installed request, response, and discovery seams: [`tests/unit/image-model-kind.test.js`](../../../tests/unit/image-model-kind.test.js) verifies chat-model rejection before credentials and a successful edit response preserved from the adapter; [`tests/unit/image-generation.test.js`](../../../tests/unit/image-generation.test.js) exercises the existing edit path through mocked provider transport/accounting; [`tests/unit/media-catalog-audit.test.js`](../../../tests/unit/media-catalog-audit.test.js) ties published image rows to dispatchers and checks listed IDs route back to registry IDs; [`tests/unit/public-route-correlation.test.js`](../../../tests/unit/public-route-correlation.test.js) includes `images/edits` method coverage. These fixtures establish an installed supported path and valid adapter response handling, not the source patch's proposed byte-sniffing, pre-buffer size limits, or mask policy. No independent follow-up is raised here: those are additional ingress-policy requirements, not a demonstrated missing route/adapter behavior in this scoped reconciliation.

## 9router #5502 — video reference validation

Source: [#5502](https://github.com/decolua/9router/pull/5502), audited head [`b9bfa0bbf34f0d6c90b836364dc32b2e515ee4f0`](https://github.com/decolua/9router/commit/b9bfa0bbf34f0d6c90b836364dc32b2e515ee4f0). The patch rejects video reference images in the Grok Web executor before creating an upstream web job.

**Disposition: no matching installed Grok Web media route; do not port the executor change or its browser/session assumptions.** The installed [`open-sse/providers/registry/grok-web.js`](../../../open-sse/providers/registry/grok-web.js) publishes chat models and a chat transport, but no image/video service kind or media config. The installed video boundary is the asynchronous `/v1/videos` route backed by published `videoConfig` in [`open-sse/handlers/videoCore.js`](../../../open-sse/handlers/videoCore.js), while synchronous `/v1/video/generations` is separately limited by [`open-sse/handlers/videoGenerationCore.js`](../../../open-sse/handlers/videoGenerationCore.js). The published Grok Imagine video models and `/v1/videos` adapter belong to xAI in [`open-sse/providers/registry/xai.js`](../../../open-sse/providers/registry/xai.js), not `grok-web`.

Offline fixtures verify those installed boundaries: [`tests/unit/xai-video-proxy.test.js`](../../../tests/unit/xai-video-proxy.test.js) checks xAI model/config dispatch, request forwarding and valid async job response/polling; [`tests/unit/media-routes-handlers.test.js`](../../../tests/unit/media-routes-handlers.test.js) checks model selection, multipart edits and route behavior; [`tests/unit/media-catalog-audit.test.js`](../../../tests/unit/media-catalog-audit.test.js) checks video models are advertised only when a dispatcher exists and listed IDs map to registry model IDs. No Grok Web video model is honestly discoverable from its current registry entry, and there is no installed Grok Web video request to validate or reject. No independent follow-up is raised.

## Summary

Neither exact patch identifies an unimplemented supported media route in the installed tree. #5548's endpoint gap is superseded by the current provider-aware image-edit route and its adapter fixtures. #5502 targets Grok Web video behavior absent from the installed media catalog; the published Grok Imagine video path is xAI's asynchronous adapter and remains covered by its offline fixtures. No product, test, workflow, policy, or baseline changes are indicated.
