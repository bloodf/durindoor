# 1072: image quota reset disposition

Source: https://github.com/decolua/9router/pull/5782, pinned head `70c97b573158997921b1de8e1de4456d56d2fe5c` (base `1855aa44473e88feac9d3f131b9c0c5fc9706b68`).

Ported the Codex reset propagation with DurinDoor's existing bounded 429 evidence classifier. The final upstream diff extracts executor resets on image failures and forwards them to the account lock. Here, Codex native image dispatch uses the Responses endpoint; the existing executor recognizes `usage_limit_reached` and both reset fields. The shared parser already bounds deadlines and classifies exhaustion. Only a classified exhaustion with a valid bounded deadline reaches account health; ordinary 429s, missing or rejected deadlines retain the prior fallback. This avoids extending cooldowns based solely on unrelated reset hints. Existing executor-delegated image errors retain their prior behavior.

The credentialed image handler still performs quota preflight, selects and excludes accounts per attempt, and associates the health update with the selected connection and model. Accepted jobs and successful image accounting retain their existing paths. Account lock policy and classifier bounds are unchanged. The offline scoped test uses fake provider responses and checks absolute and relative reset hints, missing and out-of-bounds hints, unrelated rate limits, account fallback and a single successful charge. No provider or credentials are used.

## Follow-up: scoped persistence and final retry hint

Review of the first port found that the real persistence path widened a classified image exhaustion to the whole Codex account: the provider quota config marks Codex exhaustion as account-wide, so the runtime evidence landed on the account resource and unrelated chat and image models were skipped. The image handler now passes an explicit `exhaustionScope: "model"` with the proven evidence. `markAccountUnavailable` then keeps both the legacy lock and the runtime evidence on the failed catalog model, and the evidence writer uses the model resource key. Calls without that flag, including every ordinary Codex chat path, keep the account-wide exhaustion scope unchanged. Cooldown scope, classifier bounds and lock policy are unchanged.

Once failover is exhausted, the image handler previously rebuilt the final response from the last status and message only, dropping the bounded reset. It now remembers each attempted account's proven, bounded deadline and, when every attempted account ended in a 429 with a known deadline, returns the earliest as `Retry-After` and `retry_after`. Ordinary 429s, mixed statuses, missing deadlines, successful fallback, accepted-job charging and cancellation keep their existing responses.

The offline fixture runs the real local health policy against a throwaway data directory with fake provider responses and quota refresh. It checks that the persisted lock and evidence stay on the failed image model, that other chat and image models remain selectable, that explicit chat exhaustion stays account-wide, the final 429 header for two exhausted accounts, no header for ordinary 429s, and a single charge on successful fallback. No provider, credentials or network are used.
