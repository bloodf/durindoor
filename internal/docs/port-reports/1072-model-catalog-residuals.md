# #1072 model catalog and ceiling residuals

Reviewed 2026-11-20 against local base `c59127b18fd90a36154eb0f0fe143be25598df25`, the dated [#1072 intake](https://github.com/bloodf/durindoor/issues/1072), and the refreshed [#800 reconciliation](800-scan-reconciliation.md). The intake called all five port candidates, not proofs of missing behavior. Each upstream PR was still open and unmerged at review; the head SHAs below identify the inspected final diffs. No provider requests were made.

- [#5566](https://github.com/decolua/9router/pull/5566), `e2740cb98f51616f0b0fda84d668ec1e84f7cbca`: **partial adaptation**. The fork has no upstream `modelCatalog/sync.js`; `modelAutoSync/sharedMetadata.js` now maps models.dev `ollama-cloud` metadata to the hosted connection ID `ollama`. Metadata enriches existing models only and does not grant availability. `ollama-local` remains separate; `ollamaCatalog.js` and Network routing retain endpoint/account scope. The proposed static replacement is deferred: it removes existing entries and includes `systemone` models, while the fork's registry and service kinds differ. The upstream dated list alone does not establish that those IDs and request shapes work here.
- [#5560](https://github.com/decolua/9router/pull/5560), `4ff46a80543252fff232e8c857567f29f1162064`: **deferred, unverified metadata and routing**. The fork's Codex registry has the 6.1 base IDs but no upstream `[1m]` variant infrastructure. The source itself says 872k was not tested and reports `supports_experimental_context: false`. Adding an advertised variant or changing marker handling without proving its wire contract would invent a guarantee.
- [#5511](https://github.com/decolua/9router/pull/5511), `035e75c56c7990cf55bf9822f9b86ca59450e26a`: **deferred, distinct endpoint and account-scope conflict**. `getCodexModels` sends the account binding and live catalog request; `buildModelsList.js` materializes account results with capability metadata. The proposed separate `/v1/codex/models` and verbatim shape are not present. Its global merged, persisted last-good snapshot can retain models from accounts no longer active; static routability does not prove current account entitlement. A complete port needs an account-scoped persistence and authorization contract and offline tests before exposing that endpoint.
- [#5432](https://github.com/decolua/9router/pull/5432), `0bbba63894991a7e797e15aaae89b0946cc6afd5`: **already covered**. `buildModelsList.js` delegates Anthropic and Claude connections to `resolveLiveAnthropicModels`; `liveModelLimits.js` uses the Anthropic models endpoint and handles credentials and guarded fetching. `live-model-limits.test.js` and `model-auto-sync-buildModelsList.test.js` cover the resolver and listing integration. The fork preserves richer metadata and connection-specific behavior rather than replacing it with the source's ID/name-only resolver.
- [#5444](https://github.com/decolua/9router/pull/5444), `40eeea842fdfc39000cb0f9eba4ecfdd18fb04c9`: **already covered**. `aggregateComboCapabilities` uses `minKnownLimit` for both context and output, and `overlayComboCapabilities` applies operator ceilings without raising member limits. `combo-capability-ceiling.test.js` covers nested and member-safe ceilings. Unknown limits remain unknown rather than being fabricated.

No dashboard source or approved inventory records were changed. The upstream static registry refresh, Codex extended-context variant, and Codex snapshot endpoint remain outstanding; this report does not claim those scopes are ported.
