The #1072 follow-up calls for a scoped check against existing provider capabilities; #800 identifies model capability probing and asks for comparison with current filters and tests.

## Source disposition

[#5465](https://github.com/decolua/9router/pull/5465), head `5bc8e08ad0b329cde7520f9fc08f2641f1639f9a`, is open and unmerged against `master`, and is eligible for consideration. Its final diff adds a probe route and tool, vision and optional audio requests, persistent results, scheduling and retry rules, picker filters and dashboard badges. The upstream default branch inspected at `1855aa44473e88feac9d3f131b9c0c5fc9706b68` lacks the new probe and store directories. It is not already incorporated. The sweep, background scheduling, retries, persisted verdicts and picker filtering do not fit this work order.

**Disposition: blocked, no partial feature.** The existing `POST /api/models/test` action performs a user-requested single-model operation, and `connectionId` can pin it to an active account for an operator. `pingModelByKind` sends its request through the local chat gateway using an internal CLI token. The gateway's `open-sse/handlers/chatCore.js` can refresh credentials after a 401/403 and call `executeProvider()` again; other executor and routing behavior may also retry or fall back. One local `fetch` therefore does not establish one upstream operation or a no-retry guarantee. The inherited mock tests intercepted that local fetch and did not exercise provider dispatch. A new capability action needs an explicit, end-to-end single-attempt provider behavior contract before it can promise the requested semantics. It must also preserve account authorization: the existing route restricts explicit connection pins to operators because the internal token is unscoped, so adding an unpinned capability action for API keys cannot establish the caller's selected account scope.

A tools-only implementation in the inherited commits was removed: it claimed exactly one upstream request and classified generic 400/415/422 responses as unsupported, although those responses can have unrelated causes. The selected dashboard connection was merely the first active connection. The existing model-test action and its API contract are unchanged. No verdict is introduced into routing or admission.

Vision also needs a separate contract: `stripUnsupportedModalities` in `open-sse/translator/concerns/modality.js` removes image blocks based on declared capabilities before dispatch, so a gateway probe can measure the local declaration instead of provider behavior. A future design needs explicit account selection and authorization, a bounded normal operation with no internal retry or fallback, visible request and cost semantics, and offline end-to-end dispatch fixtures. It must distinguish inconclusive failures from capability evidence.

[#3842](https://github.com/decolua/9router/pull/3842) is a separate open Responses-format probe with routing gating, not a successor to #5465; gating is outside this work order. [#3841](https://github.com/decolua/9router/pull/3841) closed without merge and is ineligible.

No live provider calls, credentials, browser, Docker, background sweeps or full suite were used. Since the final diff changes only this report, there is no dashboard inventory change or new approval.

Offline verification: the four protected inventory, combo and account-scope files plus model-test routing, web-session skip, custom modality, provider readiness and compatible-model identity tests passed (89 tests in nine files). Documentation integrity passed. The full suite remains the integration gate.
