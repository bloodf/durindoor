## Upstream disposition

| Upstream behavior | Disposition |
| --- | --- |
| Isolated browser context and stored recovery password | Separate encrypted recovery table. Temp profile mode `0700`, removed on every exit. Global browser cap 1. |
| Types the Google password and clicks consent or a challenge | Not ported. The real browser path returns `challenge` when the callback is not already intercepted. Page URLs, HTML, and screenshots are not logged. |
| Callback prefix match and a local listener that receives the code | Browser worker intercepts an exact scheme, host, port, and path with one `code` and one `state`, before DNS or a local connection. The existing CLI `startLocalServer` remains for the operator CLI connect flow and was not switched to the browser worker. |
| Process-local scheduler that writes tokens on its own | KV flag `antigravityRotation` / `scheduler`, default off. A tick calls `refreshAndUpdateCredentials`, which takes the shared lease. It is not a second writer. `GET` does not start it. |
| Logs page details and raw provider bodies | API and OAuth exchange errors are allowlisted categories or status codes. The CLI exchange error is `Token exchange failed: <status>`. |

## Review corrections

1. **PKCE and subject.** Dashboard `flowType` is `authorization_code_pkce`. Missing challenge or verifier fails closed. Subject is userinfo `sub`, or v1 `id` when `sub` is absent. `openid` was not added. Sign-in still succeeds when the subject is absent. Enrollment and enablement refuse recovery until `providerSpecificData.antigravitySubject` is a non-empty string. Interactive reauth and a changed refresh token advance the generation. Email is not an identity check.
2. **One writer.** Both network dispatch sites use the lease: `open-sse/executors/antigravity.js` `refreshCredentialsDetailed`, and `refreshAntigravityProvider` for `antigravity` and `agy`. The handler commits inside the lease and sets `rotationCommitted`, so `checkAndRefreshToken` does not write again. The executor does not acquire a second lease. `checkAndRefreshToken` does not take the lease at the top. Public `refreshCredentials` and `refreshGoogleToken` still return `null` or `{error:"invalid_grant"}`.
3. **Encryption and export.** `masterKeyPresent` reads and does not mint. First enrollment may mint through `encryptField`. An existing recovery row with a missing key fails closed. AAD is `antigravity-recovery:v1:<connectionId>:recoveryPassword`. The recovery password is not stored in `providerSpecificData`. Export does not select the lease or recovery tables. Import rejects those payload keys and drops rotation rows whose connections are gone. A matching refresh-token revision keeps `dispatched`, `uncertain`, and `reauth`. A different token advances the generation.
4. **Browser boundary.** `classifyBrowserUrl` intercepts or blocks before DNS. `evaluateBrowserRequest` allows a resolution only when every address is public. Reviewed HTTPS port 443 hosts: `accounts.google.com`, `oauth2.googleapis.com`, `www.googleapis.com`, `openidconnect.googleapis.com`, `ssl.gstatic.com`, `www.gstatic.com`, `fonts.gstatic.com`, `apis.google.com`. `assertPublicUrlResolved` is not reused. Recovery launches only when `DURINDOOR_ANTIGRAVITY_BROWSER_RECOVERY=1` and `DURINDOOR_ANTIGRAVITY_EGRESS_ENFORCED=1`. Tests inject a browser with `boundary: "test"`. The management route does not accept a caller-supplied browser.
5. **Route, logs, packaging.** `/api/oauth/antigravity/rotation` is on `ALWAYS_PROTECTED`. The handler checks JWT or machine CLI, same-origin (CLI exception), and a rate-limited `x-9r-password` for enroll, replace, enable, and scheduler enable. The built-in default password is refused for those actions. Body limit 8192. `cli/package.json` does not depend on puppeteer.

## Lease details that the tests cover

- SQLite: parent `BEGIN IMMEDIATE` plus the quota write lock; two worker threads acquire; exactly one claim and one `busy`.
- Expired `dispatched` becomes `uncertain` on the next acquire and blocks reset, including `force`.
- Five non-consuming releases exhaust the pre-dispatch budget. `force` still acquires. Reset works only from `idle`.
- `invalid_grant` is `reauth`, not `uncertain`. HTTP 429 is non-consuming backoff. Documented shortcut: `ponytail: 429 treated as non-consuming; upgrade if a provider trace shows rotation on 429`.

Migration 37 creates both tables. PostgreSQL uses `translateCreateTable`, so epoch-millisecond columns are `BIGINT`. The generator wrote `src/lib/db/migrations/postgres/037-antigravity-rotation.js` and the postgres index. Those files are generated.
