- [#5487](https://github.com/decolua/9router/pull/5487), head `b08e943b2dfefecb8d6ee9341d623879d1f9d2c1`: **adapted**. Upstream retries explicit `unsupported_parameter` token-limit failures and remembers successful deployment URL preferences. Local `AzureExecutor.transformRequest` applies the fork's model-sensitive renames, and `BaseExecutor.execute` also stripped fields from some 400 responses; the combination could retry with no limit. The adaptation retains the existing initial model policy, prevents generic stripping of Azure token limits, negotiates the actually sent spelling once, scopes a bounded cache by URL, and returns unrelated errors to existing account handling. It preserves an explicitly supplied modern limit if the alternative would discard it. See `tests/unit/azure-token-limit-5487.test.js`, `tests/unit/param-support.test.js`, and `docs/providers/api-key-providers.mdx`. Upstream master did not contain the PR's preference cache when checked.
- [#5437](https://github.com/decolua/9router/pull/5437), head `37de46a1b866338f39ef98ca61e80e6f7b52`: **deferred, incomplete source behavior**. Despite its title, the final diff unwraps `tool_call` input `calls` by selecting only `calls[0]` and adds no tests. Local `completeKiroToolCallWrapper` validates nested name and arguments, buffers fragmented inputs, and returns a structured error for invalid wrappers; `kiro-toolcall-wrapper.test.js` protects that boundary and client-declared `tool_call` passthrough. Blindly choosing the first entry could silently discard additional tool calls, and the source does not establish identifiers or semantics for the others. No request-shape change is evidenced by this final diff. Upstream master lacked that unwrap when checked. A complete multi-call contract and offline fixtures are needed before changing this path.
