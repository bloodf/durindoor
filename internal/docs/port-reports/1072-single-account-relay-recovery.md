# #1072: single-account relay recovery (#2068)

Source: [decolua/9router#2068](https://github.com/decolua/9router/pull/2068), observed head `25f5bec5f69e20e00998fe9dcc42524217adf390`, compared with fork base `4f4455c9ce89`. The qualified composite review is at commit `389e7d871`, `internal/docs/port-reports/1072-composite-open-residuals.md`. This addresses residual 2068-B only. The upstream stream and combo changes have separate dispositions there.

Upstream skips account fallback for 502, 503, 504 and 524 whenever the provider has at most one active account, and projects 524 to 502 for clients. This port narrows the cooldown exception: a status alone, including 524, cannot prove where an HTTP response originated. Provider responses and untrusted error text do not establish relay provenance.

The existing executor classifies its own failed fetches as `network` or `connect_timeout` and carries that classification to the account decision. These indicate transport failure without a usable HTTP response; they do not prove that the origin did not receive the request. Caller aborts are excluded. For those classified failures with a gateway status, a direct request skips the credential cooldown only when exactly one persisted eligible account remains in request scope and it is the failing account. Eligibility excludes inactive, reauthentication-quarantined, model-locked and request-excluded connections. Missing or ambiguous connection state fails closed. Combo requests retain cooldown and fallback behavior because other combo members can serve; explicit rate-limit evidence retains its existing handling. Existing account, admission, quota, retry and multi-account behavior remains in force. Other runtime admission controls are not visible at the cooldown decision, so the persisted eligibility count can conservatively overcount.

A 524 response without transport provenance still cools the account. Client error projection maps 524 to 502 while retaining 524 for internal classification and recorded evidence.

Offline synthetic tests in `tests/unit/relay-account-cooldown-2068.test.js` cover provenance, account eligibility, cached states, limits, multiple accounts, combo preservation and client projection. The existing request-error tests and combo routing regression also cover unchanged behavior. No provider or credential is used by the new tests.
