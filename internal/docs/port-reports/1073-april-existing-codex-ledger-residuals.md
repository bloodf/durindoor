## Current behavior and offline fixture evidence

- **System prompt placement (#1346, #1400):** `CodexExecutor.transformRequest` converts input `role: "system"` messages to `developer`; translated instructions are inserted into `input` and top-level instructions become neutral. Native top-level instructions remain intact. `tests/unit/codex-translated-instructions.test.js` exercises the translated/native distinction. This covers the cache-placement behavior without changing native tool routing.
- **Stateless replay (#1397):** `normalizeStatelessResponseInput` drops stored references and `item_reference` rows, removes item IDs only from function/custom-tool call and output items, and preserves other items' IDs and stable `call_id`s. `tests/unit/codex-stateless-response-input.test.js` covers message history, call/output pairing, custom tools, and stored-reference removal. `tests/unit/azure-codex-request-compat-1072.test.js` additionally verifies that foreign sealed reasoning is dropped only with evidence of foreign provenance, while OpenAI-sealed and unknown-provenance reasoning remains. The merge's broader rule to remove all `rs_`/`msg_` IDs would erase information used by those current controls; it is not a safe residual to port. Local Codex explicitly sets `store: false` and removes `previous_response_id` in `open-sse/executors/codex.js`.
- **Effort and model normalization (#1617):** the executor parses recognized effort suffixes, strips the suffix from the wire model, and derives reasoning with priority `reasoning.effort` > `reasoning_effort` > model suffix > default. `tests/unit/codex-fast-capacity.test.js`, `tests/unit/codex-effort-wire.test.js`, and `tests/unit/codex-client-version-and-reasoning.test.js` cover suffix normalization, field normalization, and explicit effort handling. The existing fixtures cover the choices but do not assert all three competing sources in one request.
- **Response path and compact handling:** `buildUrl` adds `/compact` only from request-local compact context. `tests/unit/codex-executor.test.js` verifies regular and compact URLs, concurrent request isolation, retry, and base-URL fallback. This is the current relevant control for the supplied regex-revert head pins; no new endpoint passthrough behavior is inferred from them.
- **Native tools:** `normalizeCodexTools` preserves supported Responses-native tools and tool-search/namespace forms. `tests/unit/codex-tool-normalization.test.js` covers hosted and native tool forms alongside function tool normalization. No inventory row justifies changing this routing.
- **Transport and development rows (#1640, #1660, #1669, #1676):** current Codex execution uses `proxyAwareFetch`; no Codex-specific `wreq-js`, WebSocket transport selector, or WebSocket error response exists in `open-sse/executors/codex.js`. Those upstream transport changes have no current installed HTTP request/response control to reconcile. #1669's Turbopack and CORS changes are likewise outside this executor inventory.

## Residual and acceptance

No demonstrated request/response behavior gap warrants a product change. The narrow offline acceptance gap is fixture precision for the precedence contract and system-role conversion: extend ordinary `tests/unit` coverage to submit conflicting `reasoning.effort`, `reasoning_effort`, and model suffix values and assert the explicit nested effort wins; also assert `role: "system"` becomes `developer` on both translated and native input while native top-level `instructions` are preserved. These tests should use `CodexExecutor.transformRequest` fixtures only. No aliases, new profiles, endpoint passthrough, credentials/OAuth ownership, transport additions, or broad ID rewrite are supported by this evidence.
