## Current behavior and fixture evidence

- Antigravity request construction is null-safe (`body = { ...(body || {}) }`) and retains the credential project ID or generated fallback. The offline `tests/unit/antigravity-project-id-headers.test.js` fixture checks that Antigravity's auth/header identity remains scoped and that Gemini CLI provisioning keeps its distinct Cloud Code headers. The Antigravity transport uses its executor-owned request headers and normal base execution signal/timeout path.
- Gemini CLI remains a separate native executor route. Its provisioning header fixture above explicitly checks that the shared Cloud Code `User-Agent` remains intact rather than being replaced with Antigravity's identity. No compared named PR supplies a narrow Gemini CLI ordinary transport change.
- Local Ollama URL ownership remains explicit in `open-sse/executors/ollama-local.js`: `buildUrl` uses runtime transport path/query/suffix while substituting the configured local origin, or uses the configured local host's `/api/chat` endpoint when no runtime transport exists. `tests/unit/ollama-local-resolver.test.js` covers default localhost, host normalization, and custom host values. The executor sets its local connection timeout and disables repeated 502/503/504 retries; base execution receives the caller's `signal` unchanged and composes it with the connect timeout.
- Shared dispatch in `open-sse/executors/base.js` uses the already resolved URL, executor-built headers, POST body, and merged caller/connect-timeout signal. Caller abort is propagated distinctly from a connect timeout. This comparison found no reason to alter request destination ownership, authorization, timeout, or cancellation semantics.

No narrow gap was demonstrated by these four exact patches on the scoped existing executor transport paths. Therefore no product change or new acceptance test is proposed.
