## Codex

[OmniRoute #20464](https://github.com/cheaper-inference/OmniRoute/pull/20464), production commit [71d1e05](https://github.com/cheaper-inference/OmniRoute/commit/71d1e05edfadcca39cede4873df7ed2da74a7eda), prevents a larger synced API value from replacing the Codex registry context for `gpt-6.1-sol`: its test expects 872,000 on Codex and 1,050,000 on OpenAI, preserving persisted overrides. It calls 872,000 an OAuth window; this is a catalog policy, not independent proof of an inference-server rejection threshold.

The public [OpenAI Sol model page](https://developers.openai.com/api/docs/models/gpt-6.1-sol) specifies a 1,050,000 total context window, 128,000 maximum output and a 500,000 default in Codex and ChatGPT Work. The local 922,000 maximum input is the arithmetic remainder if reserving the entire 128,000 output from that total; it is not interchangeable with the total context or proof that every request may have 922,000 input plus any output. At pinned [Codex models.json](https://github.com/openai/codex/blob/bb5b9c6240136de8ff4d30215e2341c44559aa04/codex-rs/models-manager/models.json), both `gpt-6.1-sol` and `gpt-6.1-terra` have `context_window: 500000` and `max_context_window: 872000`. The [client override implementation](https://github.com/openai/codex/blob/6be2a6c/codex-rs/models-manager/src/model_info.rs) and [catalog selection](https://github.com/openai/codex/blob/6be2a6c/codex-rs/models-manager/src/manager.rs) distinguish client configuration and remotely supplied metadata. A [public issue](https://github.com/openai/codex/issues/41325) reports a catalog-driven clamp for another model, explicitly without establishing near-limit server rejection. Thus 872,000 is a published client catalog maximum for configuration, not proven to be the service's hard request ceiling, nor merely a user's preference. The reason, actual route enforcement, account-specific catalog and whether this bound represents input or total request capacity remain unverified. Do not substitute it as a hard total context limit without authoritative route-specific semantics.

Locally `open-sse/providers/vendorModelCapabilities.js` supplies 1,050,000 context, 922,000 input and 128,000 output across routes; `codex` and `cx` are aliases of the same provider, not independent API evidence. Effort/model suffix normalization is also local alias resolution, not proof of separate upstream models. `tests/unit/vendor-capability-parity.test.js` covers both provider aliases and review suffixes; `tests/unit/model-metadata-resolution.test.js` checks synced Codex materialization and discovery, including the Codex envelope. `open-sse/services/modelMetadata.js` preserves input and total separately; `src/lib/modelAutoSync/catalog.js` materializes curated and synced values. `resolveModelLimits` in `open-sse/providers/capabilities.js` gives explicit operator keys precedence over live and inherited values, with tests for both. `chatCore.js` uses the resolved total for estimated input plus output reservation and separately compares input to `maxInput`; `tests/unit/context-preflight-chatcore.test.js` covers boundaries generally, not an actual Codex service ceiling. Discovery advertising is not evidence of admission by the remote service. Keep public OpenAI API semantics and explicit operator overrides intact in any future change.

Disposition: retain the existing choice pending authoritative, route-specific documentation distinguishing hard input, output and total limits, including whether the CLI catalog maximum applies to direct OAuth gateway requests. A future route-specific change would need offline tests for both aliases, explicit overrides, live/synced precedence, request admission at each boundary and discovery projections, plus unchanged OpenAI behavior. Those tests alone cannot establish a service ceiling.

## Hydrogen

[OmniRoute #20268](https://github.com/cheaper-inference/OmniRoute/pull/20268) and its [production commit](https://github.com/cheaper-inference/OmniRoute/commit/7c044bd85226db9a374feac3ed9aa7e035eb00d5) claim 1,048,576 context, 65,535 output, low/medium/high/xhigh, a high bare alias and static prices. Its [follow-up](https://github.com/cheaper-inference/OmniRoute/commit/085427318d7d9267e046826d943fa14de718dd37) is part of the merged history. These are upstream implementation claims, not proof of Antigravity subscription limits.

The local registered IDs are Antigravity `gemini-4-hydrogen`, `-low`, `-medium`, `-high`, `-xhigh`, and `gemini-interactions/gemini-4-hydrogen`. Antigravity's bare ID maps to medium, unlike OmniRoute's high: the local alias and tier registrations originated in [ee4d540](https://github.com/bloodf/durindoor/commit/ee4d540e08026d86f54a3239b4da47faa0bc1517) and xhigh in [d75da9a](https://github.com/bloodf/durindoor/commit/d75da9a7704ff389d2d64c573e73c765c5d073cd). `tests/unit/antigravity-gemini4-hydrogen-port.test.js` covers the alias, tier IDs and xhigh intent. These wire aliases do not establish a Google API default or an Antigravity hard limit.

[Google's model documentation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/4-hydrogen) specifies a unified 1,048,576 input-plus-output budget and 65,536 output per foreground segment, with longer output via documented continuation; it specifies low, medium, high and xhigh with high default on its API. The [developer guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-4-hydrogen) specifies lowercase levels on Interactions. This does not establish that Antigravity uses identical limits or continuation semantics. Local generic `*gemini-4*` capability pattern declares 1,048,576 context and 65,536 max output, and low/medium/high, not a Hydrogen-specific proven Antigravity ceiling. Do not copy upstream's 65,535 as a universal cap.

A narrow, publicly supported protocol gap exists for the already registered Interactions ID: `open-sse/executors/gemini-interactions.js` builds `generation_config` with output and temperature but does not forward reasoning effort as `thinking_level`. The shared Gemini mapper in `open-sse/translator/concerns/thinking.js` also maps xhigh/max to high; the Antigravity named xhigh intent test only establishes alias intent, not the final native wire value. A separate implementation unit can add scoped Interactions effort mapping using Google's documented levels, with offline request-shape tests for low/medium/high/xhigh, max mapping if explicitly chosen, invalid values, omission/default and unaffected models and Antigravity aliases. Verify the complete execution path and precedence before choosing the mapping; no live provider test is needed to assert the local wire shape. Longer-output support and Antigravity native tier behavior require separate protocol evidence; do not infer them from this gap.

[Google's Developer API pricing](https://ai.google.dev/gemini-api/docs/pricing#gemini-4-hydrogen), observed 2026-11-20, lists $1.50 input, $7.50 output including thinking, and $0.075 cached input per million tokens. Local `open-sse/providers/pricing.js` has a generic `gemini-4-*` fallback of $2/$10/$0.10, plus its own cache-creation fallback; it is not a Hydrogen-specific published rate. This establishes a candidate pricing discrepancy for the registered API route, subject to verifying pricing resolver precedence and billing semantics. Subscription quota is not API per-token pricing; no Antigravity rate or cache-creation charge is established here. Do not introduce static subscription prices or additional provider registrations from the OmniRoute PR.

Verification for this discovery: source inspection only; no live provider calls, credentials or full suite. The report's required existence and source-link checks are run separately before commit.
