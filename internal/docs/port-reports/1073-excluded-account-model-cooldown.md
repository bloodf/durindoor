# Excluded account model cooldown

OmniRoute #20084 source head `2f6bdc590a2679e6390553da6d1ac78a7847662d`, composed through #20817 at merge `b254710df1645e32c192ac9f9a519fadb95e6d27`. The original and composed patches include the account-cooldown regression case. They report a shorter retryable model lock on an excluded account only when that account is not cooling down account-wide and its model quota permits it.

Disposition: adapted to DurinDoor's selection and quota snapshot contracts. Chat already retains per-attempt blockers and combines their retry hints with the selector result. The remaining selector summary now considers a scoped, active model lock on an excluded account when all remaining blockers have quota decisions with a known later retry. It does not reselect the account; account-wide locks, account cooldowns, authentication failures, quota, RPM and admission gates retain precedence. Unknown quota resets remain unknown. Existing scoped lock resolution supplies route and model isolation. The selector keeps its existing `allRateLimited` response shape and rate-limit message rather than introducing upstream's cooldown metadata.

The image generation handler separately keeps attempted rate-limit hints when no credentials remain. Its existing repair concerns image response aggregation; this change updates general selector output and does not change image handling. Offline synthetic selector tests cover quota resets, active and expired model locks, account locks and cooldowns, exhausted excluded quota, and exclusion preservation. No provider requests are involved.
