## Disposition rules used here

1. **Eligible** = a fix, a security change, a provider-runtime improvement, or a protocol improvement **on an existing surface**. New providers and sign-in/auth-flow changes belong to the Provider Sign-in lane. Other new features, CI-only work, and type-conversion-only work are out of scope.
2. **Mixed rows** are assessed for their existing-surface fixes independently of their new surfaces.
3. **Out of scope** requires a *specific* reason for the row, not a filename resemblance. A brand-new upstream file cannot be a fix target, because it introduces a surface rather than changing one.
4. **Already present** requires local code evidence of the same behavior, not merely a same-named file.
5. **Requires port** states the required existing behavior and makes **no product edit**. Focused unit gaps are named so a later port can be validated offline.
6. **Unresolved** names the precise missing evidence. Security-sensitive rows are described at a high level only: no exposure detail, no bypass payload, no credential material, no traffic.

## Narrow source-to-local comparisons

### PR #33

Two of the upstream changes target existing surfaces. Both were checked against local code, and neither is a port.

**Deterministic per-combo round-robin — already present locally.** Upstream replaced a time-derived tick (`Date.now() % normalized.length`, which makes every combo rotate in lockstep and is not reproducible) with a per-combo persistent counter, so consecutive requests advance a stable index instead of depending on wall-clock time. Local already keeps exactly that state: `open-sse/services/combo.js:327` declares `const comboRotationState = new Map()` keyed per combo, `open-sse/services/combo.js:687` `getRotationState()` reads the current index for a rotation key, `open-sse/services/combo.js:694` `advanceRotationState()` advances `(currentIndex + 1) % modelCount` and resets the sticky counter, and `open-sse/services/combo.js:710` `advanceRoundRobinPointerPastServedModel()` re-pins the served model for sticky rotation. Offline evidence references: `tests/unit/combo-rr-fallback-advance.test.js` and `tests/unit/combo-weighted-round-robin-port.test.js`. No upstream file was taken; the local rotation state is already the persistent, time-independent counter the upstream change introduces.

**Translator-initialization race — inapplicable locally.** Upstream replaced a boolean flag around an *asynchronous* `initTranslators()` with a promise-based singleton, so two concurrent first requests cannot both run the initializer. Local's initializer cannot race in the same way: `open-sse/translator/index.js:555` `initTranslators()` is synchronous, `open-sse/translator/index.js:40` `ensureInitialized()` is an empty guard, and the translator modules register through static side-effect imports below that point, so registration is complete at module load. The route-level pattern `src/app/api/v1/chat/completions/route.js:6-16` (and the identical pattern in `src/app/api/v1/completions/route.js`, `src/app/api/v1/responses/route.js`, `src/app/api/v1/messages/route.js`, `src/app/api/v1/api/chat/route.js`) looks like the upstream pre-fix shape, but because `initTranslators()` performs no asynchronous work, a concurrent double call is idempotent and cannot produce a partially registered registry. The upstream defect does not exist on this surface.

**Not compared as eligible:** `src/domain/policyEngine.js` (new), `src/lib/db/domainState.js` and the four new `domain_*` SQLite tables (new persistence feature), `src/shared/utils/requestTelemetry.js` (upstream fixes its own window filter, but local has no request-telemetry module — `src/lib/observability/` contains only `redact.js` — so there is no local surface), `src/proxy.js` (upstream removes an HTTP self-fetch of `/api/settings`; local `src/proxy.js` never performs that self-fetch and delegates to `src/dashboardGuard.js`), `src/server-init.js` (upstream logging/exit changes), and the `src/lib/oauth/providers/**` extraction, which is a sign-in-surface refactor belonging to the Provider Sign-in lane.

### PR #39

**Field-level encryption of stored provider credentials — already present locally as a superset.** The upstream change encrypts `apiKey`, `accessToken`, `refreshToken` and `idToken` on provider-connection rows with AES-256-GCM and decrypts them on read, keying the derivation from an environment secret. Local implements the same protection with a different key lifecycle and additional hardening:

- `src/lib/crypto/columnCrypto.js:1` documents field-level AES-256-GCM for credential columns under the local SEC-B-02 marker; `src/lib/crypto/columnCrypto.js:120` `encryptField()` and `src/lib/crypto/columnCrypto.js:152` `decryptField()` perform the cipher operations.
- The master key is a 32-byte random file under the data directory with `0o600` permissions and a `0o700` data directory, minted through a temp-file-plus-hardlink sequence so concurrent minters converge and no reader sees a partial key (`src/lib/crypto/columnCrypto.js`, `chmodQuiet`/`loadMasterKey`). Upstream instead derives the key from an environment secret with a fixed salt.
- The row id is bound in as Additional Authenticated Data, so a ciphertext cannot be replayed into a different row; upstream binds nothing.
- `src/lib/db/migrations/009-encrypt-credentials.js` encrypts existing plaintext credential rows idempotently and safely skips malformed or already-encrypted values; upstream's change only affects newly written rows through `src/lib/db/providers.js` and does not backfill.
- `src/lib/db/repos/connectionsRepo.js:22` `SENSITIVE_CONNECTION_FIELDS` names the encrypted fields, `:128` decrypts on read and `:171` encrypts on write, with an explicit guard against double encryption.
- `src/lib/crypto/columnCrypto.js` also carries a best-effort permission repair for the key and data directory that its own comment attributes to an OmniRoute-ported advisory, so the upstream lineage of this hardening is already recorded locally.

Offline evidence references: `tests/unit/column-crypto.test.js`, `tests/unit/column-crypto-master-key-race.test.js`, `tests/unit/db-quota-backup-roundtrip.test.js`.

This row is therefore **not ported**: the behavior the upstream change introduces is already present, and the local form is strictly stronger on key protection and per-row binding. The rest of the row is new modules and a CI job, and is out of scope. The row is described at a high level only; no key material, secret value or credential field content is reproduced here.

### PR #42

**Prefix-normalized pricing lookup for cost calculation — already present locally.** Upstream's `src/lib/usage/costCalculator.js` change exists because a cost lookup for a path-qualified model id failed to match any pricing row and the request was priced at zero. Upstream adds `normalizeModelName()` (keep the last `/` segment) and retries the pricing lookup with the normalized name when the exact lookup misses.

Local performs the same normalization, at a single central resolver rather than per call site:

- `open-sse/providers/pricing.js:574` `getPricingForModel(provider, model)` resolves provider overrides first, then computes `open-sse/providers/pricing.js:587` `const baseModel = model.includes("/") ? model.split("/").pop() : model;` and continues through canonical-alias resolution, exact rows and pattern fallbacks using both the normalized and the raw id.
