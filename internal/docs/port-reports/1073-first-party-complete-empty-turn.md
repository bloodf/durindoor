# #1073: first-party complete empty Claude turns

Disposition: do not port the exception at this boundary. OmniRoute [#15598](https://github.com/cheaper-inference/OmniRoute/pull/15598), merged at `09a1624fec351276a11e04103c21a57cb34b2d35`, accepts an empty Claude lifecycle in its combo quality gate when it can verify the served connection and official host. Its selected-connection header and planned-connection fallback are not a trusted local dispatch receipt.

[Anthropic's streaming documentation](https://platform.claude.com/docs/en/build-with-claude/streaming) describes named events with matching JSON types: `message_start`, zero or more content blocks, one or more `message_delta` events, and `message_stop`; pings and errors can occur. The [stop-reason documentation](https://platform.claude.com/docs/en/build-with-claude/handling-stop-reasons) places the final stop reason in `message_delta`. Thus a complete zero-block `end_turn` or `stop_sequence` is distinguishable in native framing, but that framing also can be generated by a translator or compatible endpoint.

Local evidence at `528cee867295d882cb7ccd75ebc243a629319450`:

- `src/sse/handlers/chat.js` selects accounts inside `handleSingleModelChat`; combo's callback returns only the resulting `Response`. `open-sse/services/combo.js` calls `peekStreamForContent` on that client-facing response and falls back when it has no meaningful frame. There is no authenticated served-connection/effective-host receipt passed to the peek.
- `open-sse/executors/base.js` builds the dispatch URL, including connection-supplied URLs for compatible providers; the built-in Claude and Anthropic registry entries default to the official messages URL. The URL, actual response origin across transport/redirects, and served connection are not bound together as provenance at the combo boundary. A provider label, planned connection, or HTTP header alone cannot prove that binding.
- `open-sse/handlers/chatCore.js` tracks the executor result and possible retries, while `streamingHandler.js` may translate the response before `createEmptyTerminalGuard` sees it. Its `terminalProvenance` concerns coherent terminal health cleanup, not verified host and served-connection identity. The guard and `buildOnStreamComplete` independently classify empty output for terminal repair and account cooldown; changing only combo would not preserve the turn end-to-end or its accounting.
- `streamContentPeek.js` classifies text, thinking and tool frames as content and retains consumed bytes for replay. Without trusted provenance a complete empty lifecycle remains empty, including when a response supplies a selected-connection-looking header. Failure, truncation and compatible/translated streams retain existing behavior.

A safe future port needs server-owned provenance tied to the actual successful dispatch and connection, including retries and redirects, carried separately from wire headers through native framing, terminal repair, accounting and combo/sibling fallback. It also needs a strict complete-lifecycle classifier that fails closed on malformed, interrupted or nonzero-output events. This inventory changes none of those paths, credentials or authentication. The scoped mock tests exercise existing peek behavior; snapshot-only Responses fixtures and generic empty-stream tests remain unchanged.
