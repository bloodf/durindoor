## Current local evidence

Gateway-generated client heartbeats are in [streamHandler.js](../../../open-sse/utils/streamHandler.js): `createDisconnectAwareStream` starts a keepalive interval only before the first client data byte, checks connectivity before enqueue, stops the interval on first data, terminal completion/error, disconnection, and reader `cancel()`, and clears it with `clearInterval`. The downstream `cancel(reason)` also calls `handleDisconnect` and cancels the upstream reader. `pipeWithDisconnect` wires this stream around the transformed provider response. This is the client-facing gateway heartbeat path, distinct from filtering empty provider keepalive frames.

The adjacent timeout lifecycle is also relevant: [earlyStreamKeepalive.js](../../../open-sse/utils/earlyStreamKeepalive.js) stops its timer and cancels its upstream reader on consumer cancellation. Neither path is the provider heartbeat transform from #19804.

The current connection circuit is local, in [connectionCircuitState.js](../../../src/lib/routing/connectionCircuitState.js), with dispatch recovery in [connectionRecovery.js](../../../src/lib/routing/connectionRecovery.js). It is keyed per connection and scope (model or account-wide), uses CLOSED/OPEN/HALF_OPEN states and bounded recovery leases, and fences stale settlements by generation. Cancellation releases the lease without recording provider failure or falsely closing the circuit. Existing tests include [connection-circuit-state.test.js](../../../tests/unit/connection-circuit-state.test.js) and [1108-circuit-recovery.test.js](../../../tests/unit/1108-circuit-recovery.test.js).

That architecture differs from #1485's source provider-wide shared breaker and cooldown guard. It also differs from the older constants fix, which corrected fixed circuit timing constants. Do not transplant either design as a new control or route: local #2135 work already establishes the per-connection circuit lifecycle. The #1473 dashboard optional-chaining patch has no gateway circuit implication.

## Disposition

No product change is indicated by these three exact heads. #19804 is a behavior-preserving helper extraction for a provider-side SSE heartbeat backpressure cap; it does not establish a missing queue limit in the current client heartbeat wrapper, and its interval cancellation semantics are not the same as empty-provider-keepalive filtering. The local wrapper already bounds itself to one pre-data timer and stops it on downstream abandonment. #1473 is unrelated. #1485's provider-wide cooldown guard should not replace the local per-connection state machine or be conflated with the constants fix / #2135.

Focused gap disposition: none found in the inspected existing gateway heartbeat teardown or connection circuit path. No focused test is added. Ordinary offline acceptance, if a later source change identifies a concrete gap, should exercise the existing stream helper with a fake clock and a cancellable reader: verify no heartbeat queue growth under backpressure, timer cancellation after reader abandonment, and no post-cancel enqueue; circuit acceptance should use the existing state-machine tests to verify cooldown behavior and cancellation releasing a recovery lease without a failure increment. Run only the affected existing unit test file(s) from `tests/`; no live provider or network fixture is needed.
