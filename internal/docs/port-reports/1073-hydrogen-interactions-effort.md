# 1073: Hydrogen Interactions effort

Sources inspected 2026-11-20: [issue #1073](https://github.com/bloodf/durindoor/issues/1073), [OmniRoute #20268](https://github.com/cheaper-inference/OmniRoute/pull/20268), its [production commit](https://github.com/cheaper-inference/OmniRoute/commit/7c044bd85226db9a374feac3ed9aa7e035eb00d5) and [follow-up](https://github.com/cheaper-inference/OmniRoute/commit/085427318d7d9267e046826d943fa14de718dd37), and [Google's Hydrogen developer guide](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/guides/gemini-4-hydrogen) and [model documentation](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/gemini/4-hydrogen). The earlier [capability bounds report](1073-codex-hydrogen-cap-bounds.md) records the limits and the distinctions between API and Antigravity claims. Google documents low, medium, high and xhigh, with high as the API default; its Interactions example uses `generation_config.thinking_level`.

Disposition: implement this documented effort enum only for the registered `gemini-interactions/gemini-4-hydrogen` route. The public native endpoint accepts an optional `generation_config` containing only a valid `thinking_level`; invalid or unsupported native fields are rejected under its existing strict field policy. The chat path normalizes explicit supported reasoning levels to the same executor wire field; unsupported, disabled, automatic or absent intent is omitted, leaving the provider default in effect. Explicit client effort wins over a provider level setting; the existing provider `none` policy strips it. The generic Gemini conversion and Antigravity aliases are unchanged. Output caps, pricing, endpoint and registrations are unchanged; no continuation support is inferred.

Offline coverage in `tests/unit/omni-hydrogen-interactions-effort.test.js` checks capability levels, normalization and executor body mapping, public request validation and forwarding, precedence, omission, another model, the Antigravity alias and output parameters. These mock shapes verify local behavior, not remote service acceptance.
