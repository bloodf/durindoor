## Current behavior and local fixture evidence

**#4615 — usage-only zero input.** `open-sse/utils/stream.js` forwards a `choices: []` chunk when `hasValidUsage` finds any positive token field, and records its usage. `hasValidUsage` deliberately considers positive `completion_tokens` sufficient (`open-sse/utils/usageTracking.js`). The branch does not estimate a zero `prompt_tokens` from the request body. Existing fixtures in [stream-completion-usage.test.js](../../../tests/unit/stream-completion-usage.test.js) prove forwarding and accounting of a positive prompt/completion usage trailer after `finish_reason`, in both passthrough and translated streams. [stream-usage-replaces-estimate.test.js](../../../tests/unit/stream-usage-replaces-estimate.test.js) establishes that actual reported usage replaces estimates and that estimates remain sticky-marked; it does not cover a positive completion count paired with a zero prompt count in a usage-only trailer. The exact upstream fixture demonstrates that narrow missing case.

**#4741 — public error details.** `formatProviderError` in [error.js](../../../open-sse/utils/error.js) already adds an allowlisted cause code and sanitized cause message to the formatted error string. This formatter is used by chat and other gateway failure paths. Existing [proxy-error-redaction.test.js](../../../tests/unit/proxy-error-redaction.test.js) checks that actionable cause detail survives while proxy credentials, query tokens, refresh tokens, and bearer credentials are redacted; [relay-account-cooldown-2068.test.js](../../../tests/unit/relay-account-cooldown-2068.test.js) pins the formatted `ECONNRESET` shape in relay accounting fixtures. Static review finds the upstream's raw cause-message interpolation is more permissive than local behavior: local cause codes must match `[A-Z0-9_]{1,64}`, and messages pass through `sanitizeErrorMessage`. No disclosure attempt or reproduction was performed.

**#4788 — disconnect/abort completion.** [streamHandler.js](../../../open-sse/utils/streamHandler.js) owns the client reader lifecycle: completion closes cleanly; error and cancel paths cancel the reader, notify the stream controller, and optionally synthesize a format-specific terminal. `pipeWithDisconnect` supplies the transformed readable directly to that lifecycle and does not construct or use the faux writable from the PR. [responses-abort-terminal.test.js](../../../tests/unit/responses-abort-terminal.test.js) supplies a writer stub whose `abort()` already returns a promise and verifies that upstream errors yield `response.failed` plus `[DONE]`; its second fixture verifies ordinary streams do not receive a Responses terminal. The local runtime therefore has no matching helper or demonstrated void-returning writer behavior to repair.

These are existing gateway lifecycle and public error contracts. The separately queued terminal tool-call work concerns when a tool-call stream may be finalized; early keepalive work concerns pre-content response commitment and its late errors. Neither is evidence for changing the three patches assessed here. See [Claude tool-use terminal report](1073-claude-tool-use-terminal.md) and [existing early keepalive report](1073-november-existing-early-keepalive.md) for those separate scopes.

## Dispositions

- **#4615 — narrow gap; accept a focused local port.** Add the same fallback only for a usage-only completion trailer with `completion_tokens > 0` and `prompt_tokens` absent or zero, deriving the prompt estimate from the request body. Preserve the provider's completion count and other usage fields; add estimated prompt tokens to `total_tokens` without replacing a nonzero reported input count. Ordinary offline acceptance: exercise the passthrough transform with a local SSE fixture containing content, a terminal chunk, then `choices: []` usage with zero prompt and positive completion; assert the forwarded trailer and completion callback carry a positive estimated prompt count and consistent total. Add controls for a nonzero provider prompt count (unchanged), zero completion count (no new estimate under this rule), and a request whose input cannot be estimated (provider usage remains intact). No credentials, live provider traffic, or retry policy is needed.
- **#4741 — already covered; no port.** Cause details are already exposed in the public error string, with local sanitization and code allowlisting. The local behavior is more defensive than the pinned patch and has fixture evidence for both useful transport detail and secret redaction. No source change is indicated.
- **#4788 — no port indicated.** The upstream patch corrects a mock writer's return contract, but the current local lifecycle has no corresponding faux writer; error/cancel handling acts on the reader and stream controller. The existing terminal fixture already uses a promise-returning abort stub. There is no demonstrated production behavior gap to accept.
