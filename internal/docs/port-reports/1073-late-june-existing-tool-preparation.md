## Current local behavior and fixtures

Claude function definitions are already folded by `prepareClaudeRequest` for non-native Claude routes. The fold maps `function.name`, `function.description`, and `function.parameters` to top-level `name`, `description`, and normalized `input_schema`, and carries a defined `function.strict` value. Non-function tool types are filtered unless the provider has an explicit supported-type list; native Claude and Anthropic-compatible routes preserve their complete tool definitions. This differs deliberately from #4650's `provider !== "claude"` condition: preserving the Anthropic-compatible route's native definitions also preserves its server tools and toolsets. Existing schema fixtures cover missing, null, non-object, empty, and valid schemas across the request translator and preparation paths in [`claude-tool-schema-1352.test.js`](../../../tests/translator/claude-tool-schema-1352.test.js); the conformance fixtures assert literal names, strictness, and keyword-named schema properties in [`v5-conformance-matrix-claude.test.js`](../../../tests/translator/v5-conformance-matrix-claude.test.js).

Claude's cache markers remain managed by the existing anchor policy: the last cache-eligible tool receives the 1-hour ephemeral marker, tools with `defer_loading: true` are excluded, and tool cache markers are budgeted with system/message markers. The offline coverage in [`claude-cache-budget-single-object.test.js`](../../../tests/unit/claude-cache-budget-single-object.test.js) exercises deferred tools and mixed marker budgets. No change to this policy or to literal property names is indicated by these patches.

Gemini request preparation validates/normalizes the tool schema, wraps a typeless bare parameter map as an object schema, then cleans unsupported JSON Schema constraints. Its recursive walkers traverse schema nodes through property values and `items`, leaving the `properties` name-map keys intact. Empty object schemas get the established synthetic `reason` property, with response-side removal tracked by inserted paths. Fixtures cover both Claude- and OpenAI-shaped Gemini inputs in [`gemini-bare-parameter-map.test.js`](../../../tests/unit/gemini-bare-parameter-map.test.js), and preserve literal parameter names such as `required`, `properties`, and `type` in [`gemini-schema-walkers-name-map-2884.test.js`](../../../tests/unit/gemini-schema-walkers-name-map-2884.test.js) and [`omni-gemini-synthetic-reason.test.js`](../../../tests/unit/omni-gemini-synthetic-reason.test.js).

The shared local [`safeParseJSON`](../../../open-sse/translator/concerns/json.js) already provides the exact #4735 contract: non-strings pass through, valid JSON parses, and malformed input returns the selected fallback. Gemini selects `null`; the OpenAI-to-Claude request path selects the original arguments string. That behavior is present in the call sites and is outside tool preparation.

## Dispositions

- **#4479 — Do not port in this tool-preparation comparison.** The exact patch changes model-aware thinking/signature selection, not tool definitions or Gemini schema handling. It supplies no evidence for changing the current tool-preparation or cache-marker policy.
- **#4650 — No code port; retain current preparation boundary.** The exact patch's function-wrapper conversion is already present for non-native Claude targets, with schema normalization and `strict` handling. Its broader rewrite on every provider other than `claude` would include this fork's Anthropic-compatible native routes, whose retained server tools/toolsets are explicitly preserved. The local fixtures support retaining that distinction. If a concrete Claude-wire passthrough case demonstrates an OpenAI-wrapped function reaching an Anthropic-compatible endpoint unnormalized, add an ordinary offline fixture at the existing preparation boundary: verify its normalized schema and literal property names, retain `strict` when supplied, preserve native/server tools, and assert existing deferred-tool/cache marker placement. No provider call is needed.
- **#4735 — No port; behavior is already covered locally.** The shared parser and both distinct fallback semantics exist in local source. This PR's utility extraction does not change tool definitions or Gemini schema normalization.

No product behavior or tests were changed for this comparison. No live-provider evidence is needed; existing offline fixtures establish the retained behavior. No new provider, caching mode, account profile, or translator route is proposed.
