## Local behavior and fixture evidence

### #2518 — non-streaming Gemini thought signatures

The pinned patch tracks `thoughtSignature`/`thought_signature` while walking Gemini response parts, then stores a pending signature against a later function call's id. DurinDoor's `open-sse/handlers/chatCore/nonStreamingHandler.js` encodes a signature found on the function-call part into the transport tool-call id (`partSignature` around the Gemini conversion branch). `tests/translator/bugs-antigravity.test.js` covers streaming and non-streaming same-part signatures and verifies that the next-turn request restores both the raw call id and signature; it also protects unsigned-call fallback behavior. `tests/translator/gemini-thought-signature.test.js` and `tests/translator/gemini-thought-signature-store.test.js` cover direct routes and persisted round trips.

The fixture evidence does not cover a signature on an earlier thinking-only part followed by an unsigned function-call part in the same non-streaming response. The local loop currently does not retain that pending value, so this is a demonstrated narrow gap. Ordinary offline acceptance for a separately authorized fix: add a non-streaming fixture with a thinking-only part carrying a signature before a function-call part without one; assert the next-turn Gemini request contains that signature and the original call id. Retain the current same-part and unsigned-call cases. No live Gemini request is required.

### #2625 — synced model view versus static registry

The public patch skips static `PROVIDER_MODELS` rows when a provider has a non-empty synced catalog. Locally, `src/app/api/v1/models/buildModelsList.js` reads synced catalogs only for enabled auto-sync providers, resolves them per active connection, and for those providers replaces the default id set with the effective synced ids (then applies the existing enabled-model allowlist). `src/lib/modelAutoSync/catalog.js` keeps the registry fallback when there is no successful catalog and retains the prior list on a failed refresh. `tests/unit/model-auto-sync-catalog.test.js` asserts exact synced ids plus derived registry variants, registry fallback when no successful sync exists, and retention on failure. These preserve the local model-view ownership and stale-catalog rules without globally hiding static entries. Compatible catalogs have a distinct merge path; the public patch does not justify changing that path or catalog endpoint ownership.

### #2866 — CLIProxyAPI fallback settings

The merged patch wires settings-backed CLIProxyAPI URL and fallback settings through executor, routing, and settings updates. Locally, `open-sse/executors/cliproxyapi.js` resolves `cliproxyapi_url` with environment/default fallback and a bounded cache; `open-sse/handlers/chatCore/executorProxy.js` applies provider-specific proxy configuration, configured `cliproxyapi_fallback_codes`, and the sentinel model mapping while preserving native executor behavior. `tests/unit/cliproxyapi-executor.test.js` covers the configured endpoint, manifest header, untrusted `Origin`, and sidecar proxy boundary. `tests/unit/chatcore-executor-proxy.test.js` covers native selection, explicit routing, fallback, mapped models, credential refresh, and auth inheritance. This is already implemented with local ownership boundaries; the upstream settings-table fanout structure does not require copying into the local settings model.

### #2868 — speculative combo modes

The pinned merge adds hedging/speculative execution, abort propagation, predictive TTFT skipping, and proactive compression of fallback bodies, with configuration fields in upstream `comboConfig.ts`. DurinDoor's combo path keeps its existing selected-target order and single-attempt/fallback behavior; there are no local `hedging`, `predictiveTtftMs`, or `fallbackCompressionMode` controls in `open-sse/services/combo.js`. Existing selection contracts are recorded by `tests/unit/combo-routing.test.js` (round-robin rotation and fallback order), `tests/unit/combo-context-requirements.test.js`, and `tests/unit/combo-smart-scoring.test.js`. The upstream `combo-hedging.test.ts` consists of placeholder assertions, so it is not evidence for equivalent behavior or sufficient acceptance. These are opt-in execution/configuration changes, not a narrowly established correction to current combo selection. Preserve the local selection and routing ownership; no new protocol fields or endpoint contract is established by this PR.

## Conclusion

Only #2518 demonstrates a narrow gap in an existing local handler: carry a signature from a thinking-only Gemini part to a later non-streaming function call. #2625's synced-list authority and #2866's CLIProxyAPI settings/fallback behavior already have local implementations and offline fixture coverage. #2868 introduces separate combo execution modes and configuration; the comparison does not justify changing current combo selection. No implementation is authorized by this report.
