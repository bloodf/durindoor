## Current behavior and fixture evidence

- **Responses → Chat:** `openaiResponsesToOpenAIRequest` trims a function name before accepting the call, and skips nameless/blank calls. It tracks skipped IDs so a result for a skipped call does not become an invalid standalone tool message; a later named call reusing that ID becomes live. The existing offline fixtures in `tests/translator/bugs-codexCli-responses.test.js` cover blank names, dropping the skipped call's output, preserving an output for a reused ID, and ordinary matching call/result IDs.
- **Chat → Responses:** `openaiToOpenAIResponsesRequest` retains the `tool_call_id` ↔ `call_id` identity mapping; the reverse path does not manufacture a new identity for a valid pair. The current `openai-responses.js` request path normalizes input, repairs missing call IDs, then strips outputs still orphaned from a declared `function_call`. A named call's real output is retained, including a call ID repaired from a dropped ID when the history permits an unambiguous pending-call match.
- **Claude → Chat / Chat → Claude:** Claude IDs are preserved as tool-call IDs on the OpenAI bridge (`tool_use.id` ↔ `tool_call.id`, `tool_result.tool_use_id` ↔ `tool_call_id`). Missing outputs for declared calls receive the compatibility result `[No response received]` on the Claude→OpenAI bridge. Orphan results are handled separately: `salvageOrphanedToolResults` folds their payload into ordinary text and removes the stale identity rather than dropping useful output or inventing a matching call. `tests/translator/port-2237-salvage-orphans.test.js` verifies paired Claude results remain paired, orphan payload survives as `[Tool result: …]`, and no synthetic ID is created. This is intentionally more preserving than #417's Chat→Claude filter, which deletes orphan result blocks (and now-empty messages).
- **Responses orphan distinction:** `tests/translator/port-2237-salvage-orphans.test.js` verifies an unrecognized Responses `function_call_output` is structurally stripped. A recognized call with no result is a different condition: the current Responses request repair pairs that call with an empty compatibility output rather than deleting the call or pretending a real result arrived. Existing call-ID repair is the later #2976 concern ([PR](https://github.com/cheaper-inference/OmniRoute/pull/2976)); it prevents an id-less but otherwise recoverable call/result history from being mistaken for an unrecognized orphan. This does not make an unrelated output valid.

The later #2937 Read comparison concerns **response-side** tool-name/argument handling, not this request-history identity path; it is not evidence for changing these request converters ([PR](https://github.com/cheaper-inference/OmniRoute/pull/2937)).

## Dispositions

- **#415 — Already covered; no port.** Current Responses→Chat rejects blank names and keeps names normalized for the accepted call. The related existing tests establish the behavior; no identity gap is shown.
- **#417 — No direct port; current behavior supersedes its lossy filtering.** Current Responses request handling drops genuinely unrecognized outputs while recovering missing IDs and supplying a compatibility output for a call missing its result. Claude/OpenAI cross-format handling preserves orphan result content as text while removing invalid identity. There is no narrow functional gap demonstrated by the pinned patch.
- **#518 — Out of scope; no port.** Its pinned patch does not alter named-tool identity or orphan-history handling.

## Ordinary offline acceptance

No implementation change is indicated, so no new test is required. Existing offline acceptance evidence is the focused fixture coverage in `tests/translator/bugs-codexCli-responses.test.js`, `tests/translator/port-2237-salvage-orphans.test.js`, and the request/response-format cases in `tests/translator/openai-anthropic-parity.test.js`. If a future concrete regression is found, add a deterministic fixture in `tests/translator/` for each distinction: preserved paired ID, recoverable missing ID, missing result for a known call, and unrecognized orphan output. Run the explicit fixture file(s) with the standard offline Vitest command from `tests/`.
