## Boundary and acceptance notes

The local CLIProxyAPI executor's target URL is resolved from the local setting, then environment/default configuration; its request carries the executor's bearer credential and provider manifest header to that configured delegate. The public PR changes do not authorize changing that ownership or destination. This is a static source comparison only: no reachability, redirect, remote-host, credential, or live-service behavior was exercised. Route selection, provider admission, and account selection remain as currently implemented.

The only plausible executor compatibility delta is Anthropic-shaped traffic through the already-installed local delegate (#2165/#2192). The current offline fixtures do not establish a failing local request/response contract, so this report records it as unproven and makes no behavior claim. If addressed in ordinary offline work, tests should use stubbed fetch and synthetic fixtures only; assert request path/body and response tool-name restoration, assert an OpenAI-shaped control, and assert the configured local delegate URL and existing authorization header remain unchanged. No sign-in flow, provider credential forwarding, executable installation/dispatch, or live provider request belongs in that acceptance.
