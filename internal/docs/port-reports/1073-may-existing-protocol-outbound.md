# #1073: May transport, protocol and outbound qualification

Static review on 2026-11-20 of DurinDoor [`fcc5d0be2184c9b730b735330e91f15ad9156832`](https://github.com/bloodf/durindoor/tree/fcc5d0be2184c9b730b735330e91f15ad9156832), following the [May scope report](1073-may-merged-source-scope.md) and [inventory issue](https://github.com/bloodf/durindoor/issues/1073). Upstream references below are merge commits, not moving branch tips. This is a source comparison; no traffic, credentials or runtime tests were used.

## Outbound policy: #2595

[OmniRoute #2595](https://github.com/cheaper-inference/OmniRoute/pull/2595), merge [`901827df7f03ae51b00a521a5076b4b041948741`](https://github.com/cheaper-inference/OmniRoute/commit/901827df7f03ae51b00a521a5076b4b041948741), adds a DB feature-flag lookup after its existing environment and legacy checks. A recognized true value enables the private-provider-URL opt-in; lookup failure falls back to the environment checks.

**Disposition: different configuration contract; no DB override to port.** Local [`runtimeConfig.js`](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/config/runtimeConfig.js) reads the private opt-in and legacy switch from the environment, not a stored feature flag. Explicit private opt-in selects `none`; otherwise local URLs default to enabled and select `block-metadata`, while disabling local URLs selects `public-only`. The first mode still parses HTTP(S) URLs and rejects embedded credentials; the active modes enforce their respective hostname and socket-address policy. [`outboundUrlGuard.js`](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/utils/outboundUrlGuard.js) checks DNS answers and IP literals for guarded probes and requests manual redirects. Provider validation's [route](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/src/app/api/providers/validate/route.js) and [probe helper](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/src/app/api/providers/providerProbe.js) use this policy for their validation URLs, including the helper's fallback. This does not establish coverage for every outbound entrypoint; some callers explicitly select their own guard mode.

## Antigravity: #2828

[OmniRoute #2828](https://github.com/cheaper-inference/OmniRoute/pull/2828), merge [`f1eb08c7b501c7d9691cb6bfde6e94d1dd911dca`](https://github.com/cheaper-inference/OmniRoute/commit/f1eb08c7b501c7d9691cb6bfde6e94d1dd911dca), changes request and response translation, textual tool-call recovery, stream handling, quota classification and auth. It cannot be dispositioned as one behavior.

**Existing stream and cooldown handling:** Local [`stream.js`](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/utils/stream.js) incrementally decodes and buffers stream data; the [Gemini response translator](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/translator/response/gemini-to-openai.js) emits native function calls and retains thought signatures. Local [rate-limit evidence](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/utils/error.js) distinguishes explicit Antigravity quota signals from generic content-rejection wording, and [account fallback](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/services/accountFallback.js) treats capacity as request-scoped. These are established local contracts, not a reason to import upstream's broad quota text patterns. Existing [rate-limit tests](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/tests/unit/provider-rate-limit-evidence.test.js) document the distinction. This is not a claim that every upstream stream branch is equivalent.

**Remaining protocol difference:** Upstream's [response translator](https://github.com/cheaper-inference/OmniRoute/blob/f1eb08c7b501c7d9691cb6bfde6e94d1dd911dca/open-sse/translator/response/gemini-to-openai.ts) parses textual tool-call representations into structured calls and normalizes JSON string arguments. Local native `functionCall.args` is directly JSON-stringified, so an already JSON-encoded string is encoded again; local text parts are not converted by that upstream parser. Upstream also adds buffering and conversion for textual calls in its stream and non-stream paths. This is an exact source-level difference, not proof that current providers emit those forms or that every upstream fallback is appropriate locally. The [local request translator](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/translator/request/openai-to-gemini.js) uses its own signature transport and native history handling; its request-side contract should be assessed independently before any adaptation. Sign-in and refresh changes belong to Provider Sign-in.

## Proxy: #2923

[OmniRoute #2923](https://github.com/cheaper-inference/OmniRoute/pull/2923), merge [`a800dc8e2e1f2375a19e51e274cb3ff9457e1495`](https://github.com/cheaper-inference/OmniRoute/commit/a800dc8e2e1f2375a19e51e274cb3ff9457e1495), guards `error.code` with a string type check before `startsWith` in its dispatcher retry classification. It also changes model parsing; this transport comparison does not qualify those separate model paths.

**Disposition: original type error absent; retry policy differs.** Local [`proxyFetch.js`](https://github.com/bloodf/durindoor/blob/fcc5d0be2184c9b730b735330e91f15ad9156832/open-sse/utils/proxyFetch.js) safely reads diagnostic codes inside a try block and only uses allowlisted strings; it does not call `startsWith` on the code. Its ordinary non-strict proxy branch makes one proxied dispatch and falls back to one direct dispatch on failure, rather than upstream's classified dispatcher retry followed by native fallback. Abort and quota-dispatch errors propagate, strict proxy fails closed, and the specialized proxied transport fails instead of direct fallback. Thus no identical retry parity is claimed. The separate [#5770 nonreplayable-body unit](1073-july-merged-source-scope.md#5770--avoid-direct-fallback-for-a-non-replayable-proxy-request-body) already records the remaining replay concern in the ordinary fallback path; it is not a second #2923 gap.
