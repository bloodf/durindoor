## Current source and fixture evidence

- `open-sse/providers/registry/opencode.js` registers OpenCode Free under id `opencode`, alias `oc`, with its own transport and catalog. `open-sse/providers/registry/opencode-zen.js` registers Zen separately under `opencode-zen`, preserving `ocz` as an additional alias. `open-sse/services/model.js` derives provider ID resolution from registry ids and aliases; it does not hard-map `opencode` to Zen.
- `open-sse/providers/registry/opencode-zen.js` contains `deepseek-v4-flash-free` with `supportsReasoning: true`, `qwen3.5-plus` with Claude target format and image stripping, and the currently retained catalog entries. The PR's removed `ling-2.6-1t-free` and `trinity-large-preview-free` have no matching local entries to remove. No new provider or catalog passthrough behavior is needed for this request.
- `tests/unit/port-4145-opencode-zen-catalog.test.js` proves the `ocz` alias is collision-free and resolves a registered Zen catalog model through the routable-model checker. `tests/unit/omniroute-missing-local-providers.test.js` exercises Zen endpoint selection for Claude, Qwen, Responses, and OpenAI model families, and verifies image stripping for the Qwen models. `tests/unit/omni-opencode-mimo-effort.test.js` also covers the registered Zen and OpenCode Free identities independently.
- `open-sse/providers/registry/pollinations.js` owns the current Pollinations primary URL and has it as its only configured URL. `open-sse/executors/pollinations.js` uses the registered base URL and the same `gen.pollinations.ai` fallback. `tests/unit/omniroute-specialized-executors.test.js` asserts the executor builds the `gen.pollinations.ai/v1/chat/completions` endpoint without making provider requests. The provider test helper in `src/app/api/providers/[id]/test/testUtils.js` also derives its Pollinations probe base from the registered provider config.
- The current local provider predicate is `isLocalOllamaProvider` in `src/shared/constants/providers.js`; broader local/router registration and optional-auth behavior are fixture-checked in `tests/unit/omniroute-missing-local-providers.test.js`. These are DurinDoor's current helpers and fixtures, not a missing `isLocalProvider` import port target.

## Narrow-gap acceptance

No demonstrated narrow behavioral gap remains in these three patches, so no product code or test change is proposed. If a future local validation regression demonstrates an equivalent missing helper reference, accept it with an ordinary offline unit fixture covering the affected provider classes and validation result; do not import upstream provider availability assumptions or make a live provider request. If a catalog repair is separately demonstrated, cover alias resolution, registered model metadata, endpoint/format selection, and existing provider identity in an offline fixture while preserving registry configuration.
