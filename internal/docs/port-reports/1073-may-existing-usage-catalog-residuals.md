## Local behavior and fixture evidence

- **Antigravity quota display:** `open-sse/services/usage/google.js` clamps grouped bucket fractions to `[0, 1]` at the newer bucket parsing path (around `parseAntigravityUsage`). The legacy per-model path later in that file reads `info.quotaInfo.remainingFraction || 0` and multiplies directly by 100. Values above 1 can therefore display above 100%; negative values remain negative. Existing `tests/unit/antigravity-weekly-quota.test.js` fixtures cover ordinary fractions, exhausted rows, weekly reconciliation, and disabled buckets, but do not pin out-of-range values on this legacy per-model path. This is display normalization only; it must not alter request admission or quota policy.
- **OpenCode Go quota display:** local registry metadata in `open-sse/providers/registry/opencode-go.js` supplies the existing `opencode.ai/inference/go/v1/usage` endpoint and marks usage enabled. `open-sse/services/usage/opencode-go.js` maps `usage.rolling`, `usage.weekly`, and `usage.monthly` percentages into display windows, bounds percent-used to 0–100, and derives `limitReached` from provider-reported rate-limit status or 100% used. `tests/unit/opencode-go-usage.test.js` provides offline parser, response, and status fixtures. The #2861 head instead adds a separate Provider Limits fetcher against `api.z.ai`, parsing `data.limits` into 5-hour, weekly, and monthly dollar-denominated totals. It is not the same endpoint, source payload, or display contract, so local OpenCode Go coverage does not establish parity with that row.
- **Combo metrics:** this checkout has no `comboMetrics` implementation or `recordComboRequest`/`getAllComboMetrics` symbols in `open-sse/`, `src/`, or `tests/unit/`. The #2965 memory-management change therefore has no shipped local combo metrics surface to repair. Its upstream counters, capacity and eviction behavior cannot be treated as an existing local contract.
- **Catalog alternatives / source-only evidence:** the local registry has distinct entries for `opencode` and `opencode-go`; the Go usage handler belongs only to `opencode-go`. Several existing providers (`ollama`, `deepseek`, `glm`, `minimax`, `kimi-coding`) have registry catalog entries and usage or usage-related handlers, but their usage representations are provider-specific. Provider catalog presence alone is not evidence of a common quota endpoint or interchangeable row schema. No source-only provider addition is justified by these patches. Keep provider registration, authentication, and sign-in out of this residual.
