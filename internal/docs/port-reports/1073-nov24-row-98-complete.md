### Behavior checked in the existing local self-service route

The upstream `GET /v1/me/usage` and `GET /v1/me/quota/{provider}` have a different contract from local `GET /api/usage/me` (`src/app/api/usage/me/route.js`), as [ob01](1073-nov22-verify-ob01.md) records. The safety fixes in those upstream routes were checked against the local route:

- **`78094c591a9200700575637dffdf2d499557c85b` and `778eb8cc26270b85ed76e1d2f0ea6d84385107fa`:** Upstream validates the key, and reads its metadata, from the key's row on every call. This is already present locally: `resolveClientApiKey(request, { required: true })` is followed by `getApiKeyById(auth.apiKeyId)` on each request. The route returns 401 when no row exists.
- **`56d48d56638fe66dabe95c26c78b22a840d6150b`:** Upstream limits account bars to the connections that the key may use. This is already present locally: `getApiKeyProviderConnectionIds(record.id)` filters the connections, and an unrestricted key gets `[]` rather than the operator inventory.
- **`6a2df0bacd792015eca2232f2f4d2bbe85acc674` and `52d5965b62299fe91d93295e5e82ca99320aa2f2`:** Upstream filters rows by `api_key_id` only. The local route reads only `getApiKeyUsageTotals(record.id)` totals and has no series builder, so the current route is not exposed. The series builder is part of G3, so these fixes are verified gaps pending port with G3.

The first three checks show that the existing local route already has equivalent safety behavior. They do not close G2 or G3: the upstream `/v1/me/quota/{provider}` and `/v1/me/usage` contracts are still missing, and a port of them must keep these checks.
