# #1073: Existing early keepalive failure handling

## Pins and patch scope

- [OmniRoute #18774](https://github.com/cheaper-inference/OmniRoute/pull/18774), PR head `2c70bade6e17f97313c0eba4e47445bbb5e7dcc1`, enclosing merge `09675f166d042c06b812040b1928c846b362a1cb`. The exact head patch changes `open-sse/utils/earlyStreamKeepalive.ts` and `tests/unit/early-stream-midstream-failure-17292.test.ts`. The implementation distinguishes a clean SSE event boundary after previously forwarded bytes from a cut event: on a read failure it appends one generic terminal error frame and closes at a boundary, while a cut frame still errors the stream. Added ordinary fixtures cover LF/CRLF, an event split between chunks, one trailing newline, and clean EOF.
- [OmniRoute #18890](https://github.com/cheaper-inference/OmniRoute/pull/18890), PR head `ba451ca835566992d7a2c28a47f1a68cd3a77cb2`, enclosing merge `2e4ab1961a4eb786381501d21e38bcfb058cd8fc`. The exact first-parent diff of that enclosing merge changes `withDeadlineSignal` in `open-sse/utils/earlyStreamKeepalive.ts` to rebuild foreign Undici requests from URL and public fields and add a body only for non-GET/HEAD requests; its fixture checks that foreign request-brand path. The merge contains many unrelated release changes, excluded here. This patch does not change early keepalive upstream SSE read-failure handling.

## Current local behavior and evidence

`open-sse/utils/earlyStreamKeepalive.js` is the slow-path wrapper. It commits a 200 SSE response after the threshold, emits keepalive frames, then owns the upstream SSE reader (`response.body.getReader()` and the read loop). Handler rejection and non-SSE error responses already become shaped client-format frames via `buildKeepaliveErrorFrame`, retaining route format and available status/retry metadata. This is the existing terminal-error path for failure before an upstream SSE body is being forwarded.

After the SSE read loop has forwarded bytes, the current broad `catch` at the wrapper boundary enqueues `fallbackErrorFrame` for any read error and `finally` closes. It does not count forwarded bytes, track SSE event boundaries, or distinguish a complete event from a partially forwarded frame. A complete-event failure therefore gets a terminal error frame already, while a cut-frame failure also gets a frame appended to the incomplete bytes. The wrapper does not rethrow the raw upstream read error in this path.

Fixture evidence is offline and local: [keepalive-error-frame-status.test.js](../../../tests/unit/keepalive-error-frame-status.test.js) checks shaped late-handler failures for Responses, Chat Completions, and Claude, including thrown errors, status and retry hints, plus fast-path status preservation. [omni-stream-buffering-response-headers.test.js](../../../tests/unit/omni-stream-buffering-response-headers.test.js) checks slow-path keepalive forwarding and close. These fixtures do not exercise an upstream SSE reader failure after a complete or partial event. [stream-early-eof-failover.test.js](../../../tests/unit/stream-early-eof-failover.test.js) exercises a different reader: content peeking before the gateway response is committed, where a pre-content read failure is replayed or retried. It does not establish post-content behavior of the early keepalive wrapper.

The provider-frame filter from #1146 is separate: [providerKeepalive.js](../../../open-sse/utils/providerKeepalive.js) and [omni-passthrough-empty-keepalive-block.test.js](../../../tests/unit/omni-passthrough-empty-keepalive-block.test.js) remove empty provider `event: keepalive` frames in passthrough. That filter does not own gateway-generated early keepalives, the early wrapper's upstream reader, or its terminal-error decision.

## Dispositions

- **#18774 — narrow gap; accept a focused local port.** Existing behavior already supplies a shaped fallback error after a late handler rejection and already closes the slow-path response, but its post-commit SSE read-error path does not preserve the valid-complete-event versus cut-event distinction. The upstream patch demonstrates that precise gap. Ordinary offline acceptance should exercise the real wrapper with a pull-controlled local `ReadableStream`: after forwarding a complete LF and CRLF event, then injecting a read error, assert exactly one generic protocol-shaped terminal error frame and clean EOF; split the event across chunks and assert the same boundary outcome; after only a single newline / partial frame, assert the body rejects rather than claiming clean terminal framing; on clean EOF assert no synthetic error. Also assert private upstream error text is not surfaced. No provider traffic is needed.
- **#18890 — no early-keepalive port.** The pinned first-parent PR diff addresses request-brand/body reconstruction in the deadline-signal wrapper, not early keepalive SSE failure handling. Its supplied ordinary fixture is scoped to foreign Undici request identity/body transfer. It supplies no evidence for changing this local wrapper's post-content terminal behavior, so no change is indicated for this audit.
