## Current local behavior and fixture evidence

- `open-sse/translator/formats/gemini.js` resolves references and normalizes/merges schema forms, strips unsupported schema-node keywords while traversing `properties` values as schemas, and then enforces Gemini's type predicates. `enforceTypeConstraints` keeps `items` only for arrays and `properties`/`required` only for objects. It descends through schema nodes rather than the property-name map, preserving literal names such as `items`, `required`, `format`, and `value`.
- Ordinary fixture evidence: `tests/translator/gemini-schema-stray-key.test.js` verifies literal `value` and `format` property names survive while the stray schema-node `value` and unsupported `format` constraint are removed. `tests/translator/v5-conformance-matrix-responses.test.js` verifies keyword-named properties survive Gemini conversion and string numeric `minimum`/`maximum` are coerced on the normal Chat-to-Gemini tool path. The same file confirms Gemini drops unsupported string-length constraints.
- Numeric coercion on the ordinary OpenAI tool path is supplied by shared schema normalization before the Gemini cleaner. The reviewed #19458 helper adds a separate conversion inside its Antigravity cleaner for surviving `minimum`, `maximum`, `minProperties`, and `maxProperties` string values; it intentionally leaves nonnumeric strings, existing numbers, and property names alone. The installed cleaner currently has no matching numeric-bound coercion phase. The existing ordinary matrix fixture does not establish that the separately normalized Antigravity-cleaner entry path receives those four bound conversions.
- The local cleaner already has type-based pruning, with case-insensitive `schemaTypeKey`, and does so after placeholder creation. The ordinary Gemini request matrix covers nested array conversion and object schemas, and `gemini-schema-stray-key.test.js` covers name-map preservation. The upstream #19458 added tests explicitly cover pruning each node type and nested nodes, and moved prior `allOf` merge assertions to a typed object case. This local implementation already contains the same substantive pruning and preserves `allOf` behavior through its pre-pruning merge phase.
- Thinking normalization is already model-family-specific. `tests/translator/thinking-unified.test.js` covers Gemini 3 `thinkingLevel`, Gemini 2.5 `thinkingBudget`, and Gemini CLI output. `tests/translator/gemma4-gemini.test.js` verifies Gemini 4 uses `thinkingLevel` and omits `thinkingBudget`. `tests/translator/port-7061-claude-gemini-budget-zero.test.js` covers legacy zero-budget behavior. The installed ordinary fixtures establish Antigravity Gemini 4 floors a minimal level to `low`, but do not exercise the exact Google Gemini 4 disabled-thinking request or a Zed adapter. The named source mirror includes the Zed executor patch, while the installed tree has no matching Zed executor path; do not infer that behavior from the unrelated Antigravity contract. The requested comparison excludes introducing aliases or changing unrelated model settings.

## Disposition

- **#18844 — Exclude / no port.** This patch adds explicit per-image media-resolution input aliases and validated Gemini part-level metadata for inline and remote images. It does not change schema cleanup or thinking normalization, and is outside this report's requested comparison.
- **#18958 — Partial narrow gap; document, then add an ordinary offline fixture before porting.** The Gemini 4+ behavior (`thinkingLevel: "low"` when thinking is disabled) is specific to the newer model family; legacy Gemini 2.5/3 budget settings must remain as they are. Existing local fixtures establish the Gemini 2.5/3 and Gemma 4 values, but do not establish Gemini 4+ disabled-thinking behavior or the Zed adapter's uppercase enum value. If the installed ordinary request/executor path lacks either behavior, the narrow acceptance should assert Gemini 4 `reasoning_effort: "none"` yields exactly `{ thinkingLevel: "low" }`, retain Gemini 2.5/3 expected configs, and assert Zed uppercases a string level without altering unrelated config. Do not extend this to hypothetical aliases or new catalog entries.
- **#19458 — Partial narrow gap; schema type pruning is already present, but numeric-bound conversion is not present in the cleaner.** Keep the existing pruning and literal property-name behavior. The narrowly scoped delta is to coerce only finite, nonblank numeric strings in `minimum`, `maximum`, `minProperties`, and `maxProperties` at schema-node positions, preserving other values and all property-name-map keys. Ordinary offline acceptance should call the installed Antigravity cleaner and the ordinary request path with nested bounds, then verify numeric values become numbers, nonnumeric strings and numeric-looking property names remain unchanged, and `items`/`properties`/`required` are pruned only when invalid for the node type. Keep an object-typed `allOf` merge assertion alongside the post-pruning array case.

No product code or tests were changed for this audit. The scope is limited to installed translator behavior and ordinary fixtures; no live provider or account paths were used.
