## Local behavior and fixture evidence

* The local `pipeWithDisconnect` in [`open-sse/utils/streamHandler.js`](../../../open-sse/utils/streamHandler.js) owns bounded first-byte and inter-chunk stall timers. It classifies a stall from accumulated raw `totalBytes`, so empty chunks do not claim readiness. The wrapped controller clears both watchdogs on completion, error, disconnect, and abort. These timers cover a different ownership boundary than OmniRoute's response-header readiness helper; the local code does not expose OmniRoute's `anyByteAt` timestamp/header contract.
* The local [`open-sse/utils/emptyStreamTerminal.js`](../../../open-sse/utils/emptyStreamTerminal.js) holds an empty success terminal for a bounded 1000 ms grace period, then decides at flush whether to replace it with an error. It clears the timer on release and flush. The ordinary offline [`tests/unit/empty-stream-terminal-1073.test.js`](../../../tests/unit/empty-stream-terminal-1073.test.js) verifies empty success replacement, preserved content/thinking/tool/usage, upstream errors, native tool-only output, and prompt cancellation while a terminal is held. [`tests/unit/omni-passthrough-empty-keepalive-block.test.js`](../../../tests/unit/omni-passthrough-empty-keepalive-block.test.js) verifies #1146: empty provider keepalive blocks are dropped while data-bearing keepalive/status frames, subsequent output and terminal frames remain. Readiness changes must preserve these data-bearing frames.
* Local Codex prefix inspection in [`open-sse/executors/codex.js`](../../../open-sse/executors/codex.js) races `reader.read()` against its existing bounded deadline and removes the timeout and abort listener in `finally`. Its replay stream preserves the consumed prefix and original reader. [`tests/unit/codex-sse-capacity.test.js`](../../../tests/unit/codex-sse-capacity.test.js) exercises bounded chunk parsing, replay, upstream read errors and downstream cancellation. The local Codex implementation uses this HTTP/SSE prefix-read ownership, not the PR's Responses-over-WebSocket lifecycle. Thus the PR's `terminalReceived` simplification and socket-listener behavior do not directly transfer. No evidence here proves a local stale Codex timer or listener leak.
* Local deferred Responses completion in [`open-sse/utils/stream.js`](../../../open-sse/utils/stream.js) uses `completionFlushTimer` while awaiting trailing usage. The timer is cleared by translated finalization, terminal error, oversized-line failure and transform flush; the callback nulls its handle before work. A thrown flush is passed to `controller.error`. [`tests/unit/openai-responses-completed-usage.test.js`](../../../tests/unit/openai-responses-completed-usage.test.js) covers completion waiting for trailing usage and completion when usage is absent, but does not inject a failure in the deferred flush callback. Local ownership is an OpenAI Responses-to-Chat translator stream, while #19548 concerns a Responses live-stream path. The shared requirement is visible failure on a deferred completion error; the upstream fixture's timer/error test is not evidence that the local callback path is independently exercised.

## Dispositions

1. **OmniRoute #18586 — no port.** The inspected head is a readability-only refactor of an existing zero-byte versus post-byte readiness log distinction. Local bounded raw-byte/idle timers already classify their own stream-readiness boundary. The PR adds no behavioral fix to port. If a future change adds a distinct readiness timestamp/header contract, accept it only with ordinary offline zero-byte and post-byte-silence fixtures that also retain #1146 data-bearing frames.
2. **OmniRoute #18669 — no port from this PR.** The scoped Codex lifecycle changes are for a WebSocket executor, unlike local Codex's HTTP/SSE prefix reader, whose bounded timeout and abort listener already clean up in `finally`. The final PR head also trims broader module timer-stop helpers and retains the relevant rate-limit cooldown `unref`/`resetAll()` behavior; those module-owned timers are outside the requested stream-readiness and Codex stream lifecycle comparison. Existing offline Codex fixtures cover reader cancellation/error, but not a socket lifecycle the local route does not own. No narrow local gap is proven.
3. **OmniRoute #19548 — narrow acceptance candidate, not an unconditional code port.** The local deferred timer already clears on its terminal paths and errors the stream when the callback's flush throws. The identified narrow evidence gap is an ordinary offline fixture that makes the local deferred callback throw and asserts that the client read rejects, while also verifying normal trailing-usage completion and cancellation cleanup. This is test acceptance for the current local ownership path; keep the existing bounded grace period and terminal cleanup, and do not alter #1146 filtering. The existing completion-usage fixture alone does not prove this failure branch. No test was added or run for this report-only task.

## Acceptance boundary

Any follow-up for the narrow #19548 evidence gap should use the local `createSSEStream` Responses-to-Chat path and deterministic ordinary offline fixtures (fake timers or equivalent bounded control), covering deferred callback failure, successful trailing usage, and client cancellation. Assert no clean completion after callback failure and no timer work after cancellation. Keep first-byte/stall classification based on actual raw bytes, preserve data-bearing #1146 frames, and avoid provider traffic or unbounded waits.
