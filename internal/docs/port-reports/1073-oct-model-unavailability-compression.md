## [OmniRoute #15474](https://github.com/cheaper-inference/OmniRoute/pull/15474) — eligible narrow gap

Merged as `71cc6360c5336f070b1cfccc502c3c3f0c88b90d`. The added first OpenCode-family rule matches HTTP **400 or 429** and case-insensitive `endpoint is unavailable` in the serialized body. It returns `model_capacity`, model scope and 300,000 ms. The upstream family is `opencode`, `opencode-zen`, `opencode-go`, and `opencode-cli`; the 429 precheck gives this body marker priority over the generic 429/header path. The upstream tests also pin a conflicting exhausted-account header, a header without the marker, unrelated providers, other bodies and wrong status. This is not a general five-minute rule for all errors or all providers.

Locally, `open-sse/config/providerErrorRules.js` has no OpenCode rule. `checkFallbackError` in `open-sse/services/accountFallback.js` already performs provider-rule matching and generic fallback; `src/sse/services/auth.js` already persists bounded model locks, with account-wide rules, configured static retry, and reset evidence affecting the final result. A direct offline probe with `Endpoint is unavailable` returned request-scoped/no cooldown for 400 and generic 2,000 ms backoff for 429 at level zero for each locally registered `opencode`, `opencode-zen`, and `opencode-go`. A 503 remained the generic 30,000 ms path. Thus 400 needs the specific classification; 429 already falls back, but lacks the specific rule's duration and precedence. Do not introduce a new general fallback mechanism. `opencode-cli` is not a local registry entry and is not an eligible new provider in this unit.

Candidate for a separate product change: add only the marker/status rule for the existing three provider IDs, integrated with existing model-scope persistence and existing precedence. Account for the local reset and static-retry policy explicitly rather than assuming a rule return alone guarantees the stored duration. Ordinary offline fixtures should cover each local provider at 400 and 429 with `Endpoint is unavailable`, mixed case and the nested error message; assert model scope and 300,000 ms at classification and an exact-model lock for a known model with default settings. Include 429 plus an exhausted-account header and the same header without the marker, an unrelated provider, 503 with the marker, and unrelated 400/429 text as negative controls. Verify that another model remains usable and that existing configured/reset precedence is deliberately preserved or explicitly specified. These are proposed fixtures, not tests added here.

## [OmniRoute #15557](https://github.com/cheaper-inference/OmniRoute/pull/15557) — structural exclusion

Merged as `ea48360aad1befb343a89edb1b50056dc2e60420`. OmniRoute adds traced JavaScript placeholders, chooses TypeScript in the source tree instead of the placeholder, bundles the real standalone compression worker over it with an ESM package scope, and removes an optional LLMLingua placeholder when dependencies or bundling fail. It also reports worker errors/exits with pending requests. Its standalone integration test actually starts the bundled worker and checks a compression result.

DurinDoor does **not** spawn an equivalent bundled compression worker: `open-sse/handlers/chatCore.js` calls `runCompressionSeam`, whose `compressionHook.js` directly awaits registered engine `apply` functions. `open-sse/services/compression/index.js` registers local implementations in-process; LLMLingua is metadata only and is not dispatched. There is no compression worker pool, worker placeholder, or standalone colocation script for this mechanism in this tree. The unrelated worker in `scripts/smoke-installed-artifact.mjs` is a smoke-test worker, not the runtime compression path. Therefore worker resolution, placeholder replacement, and worker failure notifications have no direct eligible target. This is a structural exclusion, not a claim that the two standalone build artifacts are equivalent.
