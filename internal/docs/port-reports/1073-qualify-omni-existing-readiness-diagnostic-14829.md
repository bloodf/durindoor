The PR patch changes `open-sse/utils/streamReadiness.ts` to give the readiness timer a dedicated error class. A rejected `reader.read()` then produces a sanitized upstream diagnostic while retaining `STREAM_READINESS_TIMEOUT`, `stream_timeout`, HTTP 504 and the existing retry class; only the actual timer expiration uses timeout wording. Its fixture injects an upstream rejection after a keepalive and checks those fields and sanitization. This review uses the PR head-to-base patch, not the enclosing merge, whose other changes are unrelated.

## Current local behavior and evidence

DurinDoor does not have the same readiness gate or `streamReadiness.ts` boundary. Its corresponding pre-content stream path uses `pipeWithDisconnect` in [streamHandler.js](../../../open-sse/utils/streamHandler.js). A watchdog expiration explicitly creates `stream ttft timeout (...)`; an ordinary rejected upstream read instead propagates through the stream pipeline to `createDisconnectAwareStream`'s catch. That catch calls `handleError(error)` and, absent a network-close/terminal-recovery condition, errors the stream with the original error. The controller logs a sanitized message. Thus an ordinary upstream read rejection is not converted to the TTFT timer message.

The local mapping is intentionally distinct from the OmniRoute patch: [streamLifecycle.js](../../../open-sse/utils/streamLifecycle.js) classifies only watchdog messages beginning `stream ttft timeout` as `ttft_timeout`; ordinary read failures remain `stream_error` (and transport-reset messages retain existing close handling). Existing cases in [stream-first-chunk-timeout.test.js](../../../tests/unit/stream-first-chunk-timeout.test.js) establish that a no-byte timer expiry is `stream ttft timeout (...)`, while byte arrival clears that timer. [stream-request-scoped-errors.test.js](../../../tests/unit/stream-request-scoped-errors.test.js) establishes `read ECONNRESET` and `socket hang up` as `stream_error`. [omni-early-stream-midstream-error-framing.test.js](../../../tests/unit/omni-early-stream-midstream-error-framing.test.js) verifies early-keepalive read errors use a generic sanitized error frame after a complete SSE boundary, and fail closed on incomplete frames; they do not claim timer expiry or disclose private upstream detail.

The early keepalive wrapper's read catch is framing logic, not readiness classification: it emits a generic in-band frame when safe, or errors the stream when an event is cut. It does not expose the upstream error text. The regular stream path preserves its existing sanitized diagnostic logging and terminal behavior. No new public error code, timeout status, retry trigger, admission decision, or runtime behavior is needed here.

## Disposition

- **OmniRoute #14829 — already covered by the local boundary; no port.** The pinned patch addresses a real distinction in OmniRoute's readiness reader, but no corresponding local pre-content ordinary-read rejection is mislabeled as timer expiry. Local timeout wording is generated by the TTFT watchdog only; a normal read rejection remains an ordinary stream failure. Existing status/retry/client-versus-internal mappings therefore remain unchanged.
- **Narrow gap / acceptance:** none demonstrated. No additional acceptance fixture is warranted because the proposed mislabeling does not occur in the local boundary. Existing offline fixtures cover the timer and rejected-read/framing branches separately.
