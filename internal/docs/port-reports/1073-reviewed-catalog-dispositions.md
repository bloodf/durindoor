## OpenCode version

Header synthesis initiates refresh outside test runners; configured user-agent overrides retain precedence. Its stated purpose is maintaining a synthesized CLI identity accepted by the free tier.

Local `open-sse/providers/registry/opencode-zen.js` and `open-sse/providers/registry/opencode.js` pin `opencode/1.18.31`; `open-sse/executors/opencode.js` instead uses a separate v2 identity `opencode/latest/2.0.26/cli` on its route and may preserve a valid client header. These are distinct routes and formats, not proof of equivalent refresh behavior. **Disposition: out of scope.** Automatically refreshing a synthesized client identity is novel polling and version advertising for an impersonated client; neither it nor a version bump to bypass access restrictions is an accepted gap here. No test acceptance is proposed.

## Xiaomi discovery

[OmniRoute #15308](https://github.com/cheaper-inference/OmniRoute/pull/15308), merged `111140b98a2a7628d12da10e1fac56b2cdc8d0d6`, PR head `8afdbf8358d8f8f131c2dfe82b8afb6d076ce00e`: upstream adds `xiaomi-mimo` and `xiaomi-mimo-token-plan` to its existing named OpenAI-style discovery set. Its route tests exercise each keyed catalog and a local-catalog fallback on upstream failure. This is an existing model-import operation, not background polling or provider registration.

Local `src/app/api/providers/[id]/models/modelsConfig.js` already configures both endpoints; `fetchConnectionModels.js` uses the selected connection token and proxy. `tests/unit/xiaomi-mimo-signin-parity.test.js` checks mocked successful discovery for both and the separate regional `xiaomi-tokenplan`, including credentials and proxy, and rejects a session-only cloud request. **Disposition: discovery already present; fallback semantics differ.** The local generic path returns the upstream error on non-OK responses and reports invalid JSON as 502 rather than returning the static catalog as upstream does. This is a verified behavioral gap, not evidence that a fallback is always preferable: auth errors and stale catalogs must remain distinguishable.

Offline acceptance for a future fallback correction: mock both existing keyed connections and proxy; verify successful responses return parsed live IDs with the correct connection credential; simulate a transient 502 and a rejected fetch and assert a nonempty provider-specific local catalog, explicitly labeled as degraded/local, without persisting it as a fresh live catalog. Assert invalid credentials remain an actionable authentication error and session-only credentials are never sent to the cloud endpoint. Preserve regional `xiaomi-tokenplan` selection and existing tests. No live calls or new endpoints are required.
