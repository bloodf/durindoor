## Claude history: #12917 and #19403

[OmniRoute #12917](https://github.com/cheaper-inference/OmniRoute/pull/12917), head `7c479c3ea2d4113ffbe2d300cee5723e3298ac4e`, merge `87a753439fdaf15ee0c48e859bd3d518e3de082d`, changes `passthroughHelpers.ts`: for assistant history it removes readable thinking with missing/blank signature and redacted thinking with missing/blank data, drops a turn emptied by that removal, and otherwise preserves signed blocks and input references. Despite the title, this is **request history replay**, not response filtering; the characterization in [the historical tool-pairing report](1073-responses-historical-tool-pairing.md) as response passthrough does not describe this patch.

Local `open-sse/translator/formats/claude.js:569,649` normalizes Claude passthrough history. For provider `claude` it filters readable thinking using local signature validation, also drops blank readable thinking, and can insert a placeholder for an enabled-thinking tool turn. This is not identical to upstream's nonempty-string predicate or its unchanged-reference contract. In particular, lines 668–671 retain redacted thinking verbatim, including missing or empty `data`, and a turn emptied solely by removal of unsigned nonblank thinking is not included in the `emptiedByBlankThinking` removal set. These are **direct differences**, not proof that every request reaches an invalid upstream state: other normalization can affect the resulting history.

Narrow offline acceptance for a future change: with genuine Claude passthrough history containing mixed visible text, signed readable thinking, opaque nonempty redacted data, and missing/empty/whitespace redacted data, assert that only the latter redacted blocks disappear and other content survives. Separately exercise an assistant turn containing only unsigned nonblank thinking between user turns and assert the intended nonempty history shape; include an enabled-thinking tool turn to preserve the fork's placeholder policy. Pin the #12917 merge above; do not infer a requirement to replace the fork's stricter signature validation or mutate signed content.

[OmniRoute #19403](https://github.com/cheaper-inference/OmniRoute/pull/19403), head `b8705ef21a1cf8b52d9f396a7e0fb6bb08db2056`, is a separate, previously reviewed open change. The existing [disposition](1073-october-post-intake-dispositions.md) retains local non-streaming unsigned thinking shape for compatibility; translated streaming starts in `open-sse/translator/response/openai-to-claude.js:232` and `gemini-to-claude.js:44` include an empty signature. Request-side replay filtering is a distinct contract and does not establish that translated or native response output is dropped. Claude-native buffered output retains native blocks (`sseToJsonHandler.js:289`); same-format JSON returns its provider body in `nonStreamingHandler.js:295`. The prior #19403 non-streaming decision remains unchanged.

## DeepSeek DSML: #13345

[OmniRoute #13345](https://github.com/cheaper-inference/OmniRoute/pull/13345), head `5bb61119fc5d26be65c931a4b5b28211578f9d67`, merge `3fd15a7b324361998e35f20487d43405c8cc7249`, adds DeepSeek **Web** parsing to `deepseekWebTools.ts`: wrapped or root invokes, permissive closers and parameter text/content fallback, requested-tool name resolution, and hybrid markup handling. Its parser requires at least one nonempty argument and treats parameter bodies as strings. The fork has no corresponding DeepSeek Web translator or registry entry; provider/sign-in work remains outside this comparison. This row is **not an identical Web port**, and #2080 does not prove that Web-specific contract is present.

The fork has separately shipped shared DeepSeek-family DSML: `cada72827` and `35fa73690`, integrated in `4bf0cd56b` (#2080). `open-sse/utils/dsmlToolCalls.js` accepts wrapped and root invokes, ASCII/full-width pipe markers and loose closers, parses `string=true` as text and other values as JSON, releases invalid frames unchanged and bounds buffering. It requires complete parseable frames; this is narrower than upstream's missing-closer/content-attribute fallbacks and differs for empty or non-string arguments. `translator/concerns/dsml.js` preserves existing calls and maps decoded calls; `tests/unit/dsml-tool-calls-port.test.js` and `dsml-concern-port.test.js` describe parser and translated-stream fixtures.

`streamingHandler.js:93` routes OpenAI-wire DeepSeek-family streams through translation even for same-format Chat; other translations use the OpenAI pivot (`translator/index.js:376,412`). Ordinary same-format non-OpenAI streams can take passthrough and are not thereby proven to decode DSML. `sseToJsonHandler.js:561` normalizes accumulated OpenAI completion and native Claude message bodies before projection; `nonStreamingHandler.js:272,432` handles buffered provider JSON, including Responses projection and native Claude. `tests/unit/deepseek-dsml-buffered-response-review.test.js` covers split frames, existing calls, invalid text, non-DeepSeek model, reasoning/usage, and buffered Claude and client SSE examples. These are fixture descriptions, not fresh execution evidence.

The family gate in `dsmlToolCalls.js:11` accepts provider `deepseek`/`ds` **or** a matching model name; the non-DeepSeek test uses both a different provider and model. It does not establish a blanket exclusion for every other provider carrying a DeepSeek-named model. No direct existing-provider requirement for the Web-only permissive forms was established; do not expand the shared parser solely from this Web patch.
