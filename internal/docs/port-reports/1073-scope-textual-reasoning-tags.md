# 1073: Scope textual reasoning tags

Compared OmniRoute #5224 head `0b124e27fd5ec269c1e40a040de1060f1fe2c1e2` and merge `5f4cd53b6e6266eb30a1eac92a98dd3d4c4ba342` against this integration. The upstream change gates textual extraction in its sanitizer and Responses streams using DeepSeek R1, R1 distill and QwQ name patterns, excluding Antigravity. It also touches unrelated context, media and native thinking paths, outside this port's scope.

Here the existing explicit contract is `quirks.inlineThinking` for `MiniMax-M3` on the OpenAI transports of `minimax` and `minimax-cn`. The nonstream handler and SSE-to-JSON handler normalize using that contract; OpenAI passthrough has a split-tag-aware per-choice extractor. The Responses translator now uses the same selected provider and requested model, including split tags, while other routes preserve textual tags as visible text. The standalone Responses transformer has no selected transport/model context and preserves literal text. Structured reasoning continues through its existing handling. The separate MiniMax passthrough sanitizer and native provider thinking paths are unchanged.

Offline coverage: `unit/omni-scope-textual-reasoning-tags.test.js` checks generic literal and split tags, native reasoning, exact provider/model/transport selection, nonstream normalization, configured split-tag extraction and the standalone transformer. Related existing tests run: `unit/minimax-inline-thinking-stream.test.js`, `unit/responses-transform-stream.test.js`, `unit/omni-responses-mixed-reasoning.test.js`, `unit/openai-responses-terminal-event.test.js`, and `unit/omni-nov20-response-and-reasoning.test.js`.

Disposition: adapted, not a literal port. Unlike upstream, this integration does not infer tag-native behavior from DeepSeek/QwQ names or from an upstream chunk's model; no corresponding route contract was established here. The standalone transformer lacks routing metadata and does not extract tags. No provider traffic or unrelated media/context changes were used.
