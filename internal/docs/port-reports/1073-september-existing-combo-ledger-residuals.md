## Current behavior and fixture evidence

### Request-scoped fallback and installed combo behavior

`open-sse/services/accountFallback.js` distinguishes whether an error should cool/rotate an account from whether it rejects only the current request. It marks selected client/request failures as `requestScoped`; `open-sse/services/combo.js` consumes that result to advance to another combo member without imposing an account cooldown and retains a request-scoped response when no member serves. Model locks are checked per requested model and account-wide locks independently; `countEligibleAccounts` excludes inactive, reauth-required, excluded, and model-locked connections. These are existing per-request eligibility rules, not a generalized account breaker.

The local fixtures establish these behaviors:

- [`port-5cdcddf5-combo-request-scoped-4xx.test.js`](../../../tests/unit/port-5cdcddf5-combo-request-scoped-4xx.test.js) checks request-scoped classification, advances from a validation 400 to a successful next member, returns the first rejected response if all members reject, and stops on terminal 499.
- [`omni-combo-nonjson-error-classification.test.js`](../../../tests/unit/omni-combo-nonjson-error-classification.test.js) compares equivalent plain-text and JSON errors and verifies request-scoped body preservation and bounded classification.
- [`account-fallback-request-errors.test.js`](../../../tests/unit/account-fallback-request-errors.test.js) checks deterministic request 400/422 versus account-rotating auth/quota/transient outcomes.
- [`combo-smart-scoring.test.js`](../../../tests/unit/combo-smart-scoring.test.js) proves existing combo `smart-scoring` feeds quota failure and success back into later member order. This is combo-level scoring, distinct from #14533's per-provider account-selection strategy.
- [`combo-access-control.test.js`](../../../tests/unit/combo-access-control.test.js) verifies a key without the requested combo grant is rejected before the combo engine runs. [`combo-connection-allow-list.test.js`](../../../tests/unit/combo-connection-allow-list.test.js) exercises connection allow-lists across routed handlers. Static source review confirms combo dispatch still applies these ownership/admission checks; no breaker or scoring change should bypass them.

### Per-PR detail

**#14530 — connection circuit breaker and model access denial.** The merge adds breaker keys scoped to provider connection except for network failures, which remain provider-wide, and factors shared model-denial patterns into a leaf module. DurinDoor's request-scoped combo path is already exercised by the fixtures above. A per-connection breaker would change account health and fallback admission beyond that contract. No parity claim is made for connection-breaker isolation: it is not required to establish the requested combo behavior, so it remains a separate provider/account feature review.

**#14533 — expiry-first account rotation.** Upstream scores cached quota by remaining fraction per hour until the nearest reset, with tie-band, LRU and backoff rules, then adds `expiry-first` as a provider-account strategy. DurinDoor already has provider selection after its existing credential, quota preflight, eligibility, model-lock, allow-list and quota-ranking gates (`src/sse/services/auth.js`); its configured strategies include fill-first, round-robin and quota-weighted. The combo's `smart-scoring` fixture demonstrates a different layer. Adding this new selector would alter account strategy and is not an existing-combo fallback residual. Preserve quota reservation/admission as implemented; do not infer a request to alter them from this PR.

**#14542 — naive Z.AI/GLM reset timestamps.** The upstream change interprets offset-free reset prose for Z.AI and GLM as `+08:00`, recognizes the provider quota codes and carries provider identity into parsing. DurinDoor already defines `NAIVE_RESET_TIMEZONES` for `zai`, `glm`, `glm-cn`, and `glmt` in `open-sse/config/naiveResetTimezones.js`; `open-sse/utils/error.js` passes that provider-specific suffix into `absoluteResetFromText` while retaining UTC (`Z`) as the default. The generic exhausted-quota persistence and capped cooldown path is in `accountFallback.js`. Existing offline quota fixtures include [`apikey-429-quota-exhausted.test.js`](../../../tests/unit/apikey-429-quota-exhausted.test.js) and [`port9r-image-quota-reset-5782.test.js`](../../../tests/unit/port9r-image-quota-reset-5782.test.js), while the timezone map and parser branch are direct source evidence for this provider case. No demonstrated narrow residual remains, so no new fixture or implementation is warranted.

**#14551 — output-styles Auto-Clarity toggle.** Its merge changes compression style application and chat-core integration. It does not affect member selection, fallback classification, or account eligibility. DurinDoor's compression configuration currently has `DEFAULT_CAVEMAN_OUTPUT_MODE_CONFIG.autoClarity` in `open-sse/services/compression/types.js`, but that alone is not evidence of parity for the upstream output-styles path. This is separate compression behavior, not an existing combo/fallback row; no port is recommended here.

**#14586 — dead-code and stale-reference cleanup.** The pinned head is the integrity-review follow-up; the enclosing merge removes unused helpers, repairs remaining references, and prunes lint suppressions. It contains no distinct new combo fallback/scoring control. Its cleanup should not be mistaken for a missing runtime behavior.

**#14599 — failure usage closure scope.** Upstream hoists `providerResponse` so a failure-usage closure can read it. In DurinDoor's `open-sse/handlers/chatCore.js`, `let providerResponse` is already declared at handler scope before response parsing and failure handling (including the 401/403 refresh path). Thus this particular block-scope failure is not present in the inspected source. No source-only conclusion is made about unobserved runtime paths, and no test is added without a reproduced gap.

## Disposition

No narrow request-scoped fallback or installed-combo gap is demonstrated by these six PRs against current source and offline fixtures. No implementation or test change is proposed. Provider account rotation, connection breaker health, compression behavior, integrity cleanup and failure-usage bookkeeping remain distinct concerns; none authorizes changing model ownership, tenant/key access, admission, existing quota reservations, or combo grants. Static review was used for access boundaries; no secrets, live provider traffic, or external services were accessed.
