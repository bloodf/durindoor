## Current behavior and fixture evidence

- **Responses sequence numbers:** [`earlyStreamKeepalive.js`](../../../open-sse/utils/earlyStreamKeepalive.js) puts `sequence_number: 1` on its synthesized Responses error frame. By contrast, [`stream.js`](../../../open-sse/utils/stream.js) builds the generic synthetic `response.failed` with sequence number `0`. Ordinary coverage in `tests/unit/keepalive-error-frame-status.test.js` asserts `1` for keepalive errors, while `tests/unit/stream-terminal-outcome.test.js` covers terminal outcomes without asserting the generated failure sequence. The source synthetic value of 1 versus local 0 does not by itself demonstrate client failure or establish what number should follow already emitted chunks. Preserve the current contract unless a failing ordinary existing path is demonstrated; do not change the live Responses emitter or replay tracker based only on this difference.
- **Codex reasoning replay:** [`codex.js`](../../../open-sse/executors/codex.js) already detects a 400 encrypted-reasoning rejection and performs its bounded one-time stale-reasoning recovery. The ordinary fixtures in `tests/unit/azure-codex-request-compat-1072.test.js` preserve that recovery and request behavior; `tests/unit/upstream-ports-batch2.test.js` checks that `invalid_encrypted_content` does not trigger account fallback. The stable public error classification in #14636 is already represented by existing handling. Preserve request replay integrity: only the recognized rejection path may strip stale encrypted reasoning, and unknown or unclassified reasoning stays intact.
- **Antigravity upload replay:** the shared [`base.js`](../../../open-sse/executors/base.js) serializes the finite request payload to `bodyStr` and reuses that string on retry. The transport therefore already has a replayable JSON body; no stream upload or `duplex` option is introduced for streaming responses. Current executor architecture does not have the upstream patch's dedicated `executeAttempt.ts` or its 403/credits retry path, so do not transplant those unrelated retry branches.
- **Model and provider scope:** Codex GPT-6 Sol/Luna names and effort levels already appear in the local provider registry and reasoning metadata. The supplied #14677 patch is a Codex catalog/model-scope expansion, not a generic executor fix. Keep model-specific effort ceilings and provider routing within their current scope; do not infer a new holder or route from this inventory.
- **Project selection and recovered fetch logging:** the supplied Antigravity project-sentinel/bootstrap behavior and per-URL recovered-fetch logging are not present as corresponding current local flows. Project provisioning/selection belongs to its own project-holder/route feature scope. The current shared executor owns retry dispatch and failure handling; the PR's per-URL telemetry policy is specific to its upstream loop. Neither establishes a narrow local executor residual here.

The focused Vitest command could not start because this checkout has no root `node_modules/vitest/vitest.mjs` installed. The fixture references above are static evidence, not a claim that the tests ran. The ordinary offline acceptance for the one demonstrated gap is specified above; no product or test files are changed in this report-only task.
