## Local behavior and fixture evidence

- **Qwen discovery setting (#14273):** the upstream change adds the token-plan `/compatible-mode/v1/models` URL to that provider's listing configuration; it does not add model IDs. Local `open-sse/providers/registry/qwen-cloud-token-plan.js` already pins that endpoint as both `transport.validateUrl` and `modelsFetcher.url`, and already owns the curated model IDs. Discovery/listing behavior is separately exercised by `tests/unit/omniroute-missing-api-cloud-providers.test.js` and generic registry fetcher coverage. The upstream setting is already represented; no inventory gap is shown.
- **Provider/model inventory:** #14310 has no catalog change. #14316 changes DeepSeek's default transport from Responses to Chat Completions and retains Responses as an alternate; it does not add catalog entries. Local `open-sse/providers/registry/deepseek.js` already defaults to `https://api.deepseek.com/chat/completions`, exposes the Responses route as an alternate transport, and retains canonical local IDs/aliases. Its transport behavior is covered by local DeepSeek and alternate-format fixtures. No absent model or provider addition is demonstrated by these PRs.
- **Cheaper Inference discovery (#14347 context):** the enclosing merge adds an explicit models-list URL to Cheaper Inference, but that change is not in #14347's named head diff. Local `open-sse/providers/registry/cheaperinference.js` already has `transport.validateUrl: https://api.cheaperinference.com/v1/models`; `tests/unit/cheaperinference-provider.test.js` asserts it. This is an existing discovery setting, not a missing catalog row.
- **Vertex (#14383):** the named patch only changes a test from substring matching to exact hostname matching. Local Vertex endpoint fixtures pin `aiplatform.googleapis.com` in `tests/unit/vertex-eu-endpoint.test.js`, `tests/unit/vertex-service-account-import.test.js`, and `tests/unit/gemini4-vertex-argon.test.js`. This is discovery-host verification, not an inventory fix. The stricter assertion itself could be added to the applicable local route test, but the pinned PR contributes no production behavior change and reveals no catalog discrepancy.
- **Sign-in/auth (#14415):** the merged change relaxes `/v1/models` auth only for loopback requests on installs with no configured password, OIDC, initial password, or API keys. That is a sign-in/access policy change. Local `src/app/api/v1/models/buildModelsList.js` already includes keyless provider models alongside unrelated active connections, with `tests/unit/build-models-list-noauth.test.js` covering visibility and no duplicate/premium leakage. That fixture is not evidence of the upstream auth predicate, and this inventory report does not recommend porting auth behavior as a catalog fix.
- **No-auth catalog-only sync (#14448):** the merged upstream behavior treats a no-auth provider with no remote models endpoint as an intentional local-catalog source, allowing model sync to consume its curated rows rather than classify the absence of an endpoint as degraded discovery. Locally, static/keyless catalog assembly is present in `src/app/api/v1/models/buildModelsList.js` and covered by `tests/unit/build-models-list-noauth.test.js`; the provider-specific sync route is `src/app/api/providers/[id]/models/fetchConnectionModels.js`, where only selected providers (for example Reka) explicitly return `source: "local_catalog"`. The existing tests do not establish that every no-auth, catalog-only provider's connection sync follows the same rule. This is the sole narrow existing-catalog residual demonstrated here; it concerns sync source classification, not absent model IDs.
