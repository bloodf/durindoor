## Current behavior and fixture evidence

DurinDoor's [Quota Tracker guide](../../../docs/features/quota-tracking.mdx) distinguishes provider-reported snapshots from locally counted usage. It documents bounded/unlimited/unknown states, 60-second default freshness, stale-data fail-open behavior, preflight account skipping, and the existing account fallback flow. Current ingestion is through the shared bounded tracker and explicit provider adapters in [`open-sse/config/providerQuota.js`](../../../open-sse/config/providerQuota.js) and [`open-sse/services/quota/`](../../../open-sse/services/quota/). `PROVIDER_QUOTA_DEFAULTS` bounds requests to 10 seconds and responses to 1 MiB; unknown or absent provider data does not become exhaustion.

- **#14442 — Tavily.** The exact PR head is a formatting-only edit to `parseTavilyCreditUsage`; the enclosing merge adds the Tavily quota fetcher, usage dispatcher case, provider registration, and fixtures. Current DurinDoor has no Tavily entry in the explicit provider quota configuration or usage dispatcher. That is a new provider quota/usage fetcher and registry capability, not a missing parser rule for an already supported provider. Existing documented policy intentionally leaves providers without an implemented quota source unknown; no Tavily request is justified by this inventory.
- **#14454 — Context7.** The exact head hardens an already-added upstream Context7 fetcher: it requires a key, switches to a keyed GET probe, adds global throttling and an 8-second timeout, avoids anonymous-limit attribution, sanitizes errors, and tests those cases. Its enclosing merge introduces Context7's fetcher and usage registration. DurinDoor has no Context7 quota adapter/configuration or usage dispatcher entry. This is a new provider fetcher that makes a real upstream search call (and consumes a unit of the measured quota), not a residual in local metadata parsing. It is excluded from a metadata-only port.
- **#14555 — quota park bound and healthy override.** The pinned change caps a trusted exhausted-account park at 30 minutes and lets a recent successful dispatch override a quota cutoff. DurinDoor's preflight instead evaluates persisted snapshots only while they are fresh; the default freshness and cache lifetime are 60 seconds, stale evidence is nonblocking, and selection refresh is covered by [`provider-quota-preflight-selection.test.js`](../../../tests/unit/provider-quota-preflight-selection.test.js). The ordinary fixtures cover an exhausted first account selecting the second, a sole exhausted account with retry metadata, and refresh failure/abort boundaries. The local freshness contract already bounds the stale-exhaustion case more tightly than the upstream long-park condition, while its explicit snapshot state remains the quota source. No separate healthy override or park-cap gap is demonstrated.
- **#14739 — 422 request failures.** The exact head is a comment-only line-wrap change; the enclosing PR changes 422 classification so request-shape errors do not cool down an account. DurinDoor already returns unmatched request-scoped 4xx errors without account cooldown in [`accountFallback.js`](../../../open-sse/services/accountFallback.js). [`account-fallback-request-errors.test.js`](../../../tests/unit/account-fallback-request-errors.test.js) and [`account-fallback-request-scoped-4xx.test.js`](../../../tests/unit/account-fallback-request-scoped-4xx.test.js) exercise 400/422, including the distinction that quota-like matched rules retain fallback behavior. No residual metadata change is shown.
- **#14759 — Xiaomi MiMo Token Plan.** The pinned change wires `xiaomi-mimo-token-plan` into usage dispatch and keeps its self-tracked monthly token totals separate from `xiaomi-mimo`. The local dispatcher/fetcher inventory has no Token Plan entry. The change adds an account/provider capability and usage reporting for a new provider variant, rather than correcting metadata for a current quota fetcher. This review does not add the provider or change sign-in/account capability.
- **#14848 — Antigravity verification.** The enclosing PR is an account-handling change for Cloud Code/Antigravity 403 `VALIDATION_REQUIRED`; it changes how an account needing verification is classified and retained. It is not quota parsing, preflight metadata, or fallback reset metadata. The local [`accountFallback.js`](../../../open-sse/services/accountFallback.js) explicitly treats verification/identity failures as account failures, and [`antigravity-tos-cooldown-port.test.js`](../../../tests/unit/antigravity-tos-cooldown-port.test.js) fixtures the 24-hour cooldown for `VALIDATION_REQUIRED`. Sign-in and account capability changes are outside this inventory.
- **#15019 — breaker recovery.** The pinned head updates provider-level circuit-breaker state when a connection-scoped probe succeeds. This concerns fallback health/recovery state, not quota metadata or quota preflight. DurinDoor's quota selection keeps persisted quota snapshots and circuit/fallback health as distinct inputs; no quota row, reset, or parser changes in this patch call for a port. It does not establish a quota-metadata residual.

The quota fixture set also includes explicit unknown/malformed handling and deterministic offline response cases in [`quota-documented-snapshot-1110.test.js`](../../../tests/unit/quota-documented-snapshot-1110.test.js), plus state/freshness/preflight cases in [`provider-quota-preflight.test.js`](../../../tests/unit/provider-quota-preflight.test.js). These exercise ordinary fixtures without credentials or live providers.
