## Current behavior and evidence

**Identity and caller-owned continuity.** The local Responses request translator preserves the incoming `previous_response_id` when present and `ensureResponsesInputOrContinuity` injects a placeholder only when `input` is empty and there is no nonempty `previous_response_id`, `conversation_id`, or `prompt`. `tests/unit/port-14673-responses-empty-input-continuity.test.js` covers system-only, empty-message, orphan-tool-result, existing-ID, and nonempty-input cases. State policy in #14673 that conditionally disables automatic ID stripping when input is empty is a separate source-side policy; this tree has no corresponding policy module/path. Do not import it as a protocol repair or alter provider/client ownership of continuity state.

**Local terminal replay.** The generic stream transformer in `open-sse/transformer/responsesTransformer.js` holds terminal emission for trailing usage, then unconditionally emits `response.completed` with status `completed`. That leaves a narrow caller-visible terminal-status gap for Chat Completions `finish_reason: "length"` and `"content_filter"` when this transformer is used. In contrast, the registered Responses response translator already uses `responsesTerminalFromChatFinish` and emits `response.incomplete` (or `response.failed` on an upstream error), while the reverse Responses-to-Chat mapper retains existing `response.incomplete` reasons. `tests/unit/omni-existing-response-stop-reasons.test.js` covers existing native incomplete/completed/failed statuses and content-filter mapping; `tests/unit/responses-transform-stream.test.js` and `tests/unit/responses-usage-trailing-6965.test.js` cover transformer output and deferred trailing usage. Thus #14806's registered-translator portion is already represented locally; the transformer path still completes every finish reason as success.

**Review 12 identity safeguards.** `tests/unit/responses-history-tool-identity-15974.test.js` documents the current history-based namespace recovery, current-declaration precedence, and ambiguous-history behavior. Preserve that request-derived identity and collision safety; neither September patch justifies inferring or transferring tool identity from provider response state.
