## Current stream behavior and fixture evidence

- **Readiness has two separate meanings.** `pipeWithDisconnect` in [`open-sse/utils/streamHandler.js`](../../../open-sse/utils/streamHandler.js) starts a first-byte deadline and switches to the inter-chunk stall deadline after the first raw upstream bytes. This is transport activity, including bytes that contain no useful content. The stream content tracker and [`open-sse/utils/emptyStreamTerminal.js`](../../../open-sse/utils/emptyStreamTerminal.js) make the later content-based decision: empty success terminals are held until completion, replaced with a format-specific error if no content/tool result/usage appears, and useful terminals are preserved. `tests/unit/empty-stream-terminal-1073.test.js` covers zero-content terminals, content, reasoning, tool-only output, usage trailers, preserved upstream error, and prompt cancellation. Thus zero bytes versus byte activity, and byte activity versus user-visible content, are not conflated.
- **Early keepalive** uses [`open-sse/utils/earlyStreamKeepalive.js`](../../../open-sse/utils/earlyStreamKeepalive.js). The slow path commits SSE with the no-buffer header and forwards the eventual body; the fast path returns the handler response verbatim. Once 200 is committed, a later failure is converted to the client wire format while carrying status and retry information where supported. `tests/unit/omni-stream-buffering-response-headers.test.js` covers slow/fast paths and header/body preservation; `tests/unit/keepalive-error-frame-status.test.js` covers Responses, Chat, Claude, thrown failures, retry-after parsing, and fast-path status.
- **Finalization and accounting** retain the gateway's existing terminal and lifecycle ownership. The stream classifier in [`open-sse/utils/streamLifecycle.js`](../../../open-sse/utils/streamLifecycle.js) distinguishes first-byte timeout, content stall, transport termination, and generic stream error for abandon detail. Cancellation is separately classified as local lifecycle behavior. `tests/unit/stream-request-scoped-errors.test.js`, `tests/unit/stream-midstream-failure-status.test.js`, and the cancellation case in `tests/unit/empty-stream-terminal-1073.test.js` cover these boundaries. Responses terminal synthesis, including one completed event and usage/trailing-event handling, is exercised by `tests/unit/responses-transform-stream.test.js` and `tests/unit/responses-usage-trailing-6965.test.js`.
- **Responses event handling** remains source-format aware: output deltas feed content, and `response.completed` is terminal/final snapshot input, not another text delta. Existing ordinary fixtures include `tests/unit/responses-transform-stream.test.js`, `tests/unit/responses-usage-trailing-6965.test.js`, `tests/unit/stream-midstream-failure-status.test.js`, and `tests/unit/omni-passthrough-empty-keepalive-block.test.js` (including delta then completed, and provider keepalive filtering).

The offline fixtures are acceptance evidence for the behavior inspected; this report does not claim a full test-suite run. There is no demonstrated narrow residual that warrants a source or test change, so no new acceptance test is proposed.
