## Current request/response behavior and fixture evidence

- **Kiro effort selection and request translation.** The current [`getThinkingLevelsFromCapabilities`](../../../open-sse/providers/thinkingLevels.js) explicitly removes both `ultra` and `max` for Kiro-family providers. The `claude-opus-5` Kiro catalog is generated by [`buildKiroModelVariants`](../../../open-sse/providers/models/kiroVariants.js), and [`kiro-opus5.test.js`](../../../tests/unit/providers/kiro-opus5.test.js) locks its four base/thinking/agentic IDs. The exact #14284 source patch adds a Kiro Opus 5 `max` effort option and its corresponding synthesized effort variant. The current picker hides `max` and the Kiro catalog has no max-suffixed effort variant. Kiro request translation already maps explicit effort levels through `resolveKiroThinkingBudget`; the narrow gap is the declared selectable option/configuration, not a replacement wire format. Generic Claude capability data containing `max` does not override the Kiro-family filter. Keep the existing non-Kiro vocabulary, other Kiro IDs and supported thinking behavior intact.
- **Claude URL images.** The current direct Claude-to-Gemini request translator maps Claude URL image blocks to Gemini `fileData.fileUri`; the Claude-to-OpenAI path maps URL sources to `image_url`. This covers top-level content and image blocks inside `tool_result`. [`claude-url-image-source.test.js`](../../../tests/translator/claude-url-image-source.test.js) asserts both request paths and both placements using an HTTPS fixture. The #14460 behavior is already represented for the supported HTTPS case; no different image-fetch policy is implied by this row.
- **Namespaced Gemini tools through Responses.** The local request path tracks declared tool names/namespace identities and aliases, and the response path restores `{name, namespace}` for Responses events. [`openai-responses-tool-name-map-4200.test.js`](../../../tests/unit/openai-responses-tool-name-map-4200.test.js) covers alias restoration, provider-added prefixes, and Gemini-family non-streaming namespace restoration; [`port-3241-namespace-tools.test.js`](../../../tests/translator/port-3241-namespace-tools.test.js) covers namespace flattening and Responses event identity. The #14751 patch preserves the independent namespace and alias ledgers across request extraction and restores namespace metadata in streaming Responses output. Current fixtures establish the relevant request/response identity behavior, so the row does not demonstrate an additional local protocol gap.
- **Claude tool input shape.** In [`openai-to-claude.js`](../../../open-sse/translator/request/openai-to-claude.js), OpenAI tool-call `arguments` are parsed with `safeParseJSON(value, value)` and passed directly as Claude `tool_use.input`. Consequently, valid object arguments work, but JSON scalars/arrays and malformed raw argument strings can still produce a non-object `input`. The #14814 patch normalizes every non-object parse result to `{}`. Existing [`bugs-openai-to-claude-tools-no-type.test.js`](../../../tests/translator/bugs-openai-to-claude-tools-no-type.test.js) covers declaration shape, not this argument invariant; the listed ordinary fixtures do not establish this PR behavior.
- **Stream readiness diagnostics.** The #14829 patch distinguishes an actual stream-reader rejection before the first non-ping event from expiration of the readiness timer, while retaining the timeout route classification and surfacing a sanitized upstream diagnostic. The current tree has no `streamReadiness` helper or matching source-reader readiness test. [`stream-first-chunk-timeout.test.js`](../../../tests/unit/stream-first-chunk-timeout.test.js) proves the no-byte timeout and timer cleanup; [`stream-request-scoped-errors.test.js`](../../../tests/unit/stream-request-scoped-errors.test.js) covers in-band error envelopes and abandon classification. Neither exercises an errored response body during a readiness read, so the diagnostic difference remains unrepresented. Keep HTTP 504 / timeout code and fallback classification unchanged; the diagnostic should not trigger a same-connection retry.
- **Stream timing.** The current [`stream.js`](../../../open-sse/utils/stream.js) sets `ttftAt` when the transform receives its first provider chunk, before identifying whether that chunk carries content, reasoning, or a tool call. [`streamingHandler.js`](../../../open-sse/handlers/chatCore/streamingHandler.js) records that timestamp relative to request start. Thus role-only, ping/lifecycle, or otherwise non-output chunks can establish TTFT prematurely. The #14919 patch adds a user-visible-output probe capped at 64 chunks and keeps inter-chunk samples capped at 32; it reports first output from request start while retaining the stream-relative first-byte signal and existing fallback when no output is observed. Existing [`stream-completion-chunks.test.js`](../../../tests/unit/stream-completion-chunks.test.js) covers first-chunk timestamp propagation and completion snapshots, and [`stream-first-chunk-timeout.test.js`](../../../tests/unit/stream-first-chunk-timeout.test.js) covers the transport timeout. Neither proves output-aware TTFT or bounded output probing. Preserve timeout behavior, token/usage accounting, client wire output and no-output fallback.
