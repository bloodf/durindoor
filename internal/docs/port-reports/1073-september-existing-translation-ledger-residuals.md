## Current request/response behavior and fixture evidence

- **Kiro effort selection and request translation.** The current [`getThinkingLevelsFromCapabilities`](../../../open-sse/providers/thinkingLevels.js) explicitly removes both `ultra` and `max` for Kiro-family providers. The `claude-opus-5` Kiro catalog is generated by [`buildKiroModelVariants`](../../../open-sse/providers/models/kiroVariants.js), and [`kiro-opus5.test.js`](../../../tests/unit/providers/kiro-opus5.test.js) locks its four base/thinking/agentic IDs. The exact #14284 source patch adds a Kiro Opus 5 `max` effort option and its corresponding synthesized effort variant. Kiro request translation already maps explicit effort levels through `resolveKiroThinkingBudget`; this row is a new selectable effort option/model variant, not a demonstrated failure on an existing supported path. It falls outside the owner's existing-fixes scope. Preserve the current Kiro-family filter and catalog absent an existing-path failure.
- **Claude URL images.** The current direct Claude-to-Gemini request translator maps Claude URL image blocks to Gemini `fileData.fileUri`; the Claude-to-OpenAI path maps URL sources to `image_url`. This covers top-level content and image blocks inside `tool_result`. [`claude-url-image-source.test.js`](../../../tests/translator/claude-url-image-source.test.js) asserts both request paths and both placements using an HTTPS fixture. The #14460 behavior is already represented for the supported HTTPS case; no different image-fetch policy is implied by this row.
- **Namespaced Gemini tools through Responses.** The local request path tracks declared tool names/namespace identities and aliases, and the response path restores `{name, namespace}` for Responses events. [`openai-responses-tool-name-map-4200.test.js`](../../../tests/unit/openai-responses-tool-name-map-4200.test.js) covers alias restoration, provider-added prefixes, and Gemini-family non-streaming namespace restoration; [`port-3241-namespace-tools.test.js`](../../../tests/translator/port-3241-namespace-tools.test.js) covers namespace flattening and Responses event identity. The #14751 patch preserves the independent namespace and alias ledgers across request extraction and restores namespace metadata in streaming Responses output. Current fixtures establish the relevant request/response identity behavior, so the row does not demonstrate an additional local protocol gap.
- **Claude tool input shape.** In [`openai-to-claude.js`](../../../open-sse/translator/request/openai-to-claude.js), OpenAI tool-call `arguments` are parsed with `safeParseJSON(value, value)` and passed directly as Claude `tool_use.input`. Consequently, valid object arguments work, but JSON scalars/arrays and malformed raw argument strings can still produce a non-object `input`. The #14814 patch normalizes every non-object parse result to `{}`. Existing [`bugs-openai-to-claude-tools-no-type.test.js`](../../../tests/translator/bugs-openai-to-claude-tools-no-type.test.js) covers declaration shape, not this argument invariant; the listed ordinary fixtures do not establish this PR behavior.
- **Stream readiness qualification.** The #14829 patch distinguishes an actual stream-reader rejection before the first non-ping event from expiration of the readiness timer. The current tree has no `streamReadiness` helper or matching source-reader readiness test. [`stream-first-chunk-timeout.test.js`](../../../tests/unit/stream-first-chunk-timeout.test.js) proves the no-byte timeout and timer cleanup; [`stream-request-scoped-errors.test.js`](../../../tests/unit/stream-request-scoped-errors.test.js) covers in-band error envelopes and abandon classification. Neither exercises an errored response body during a readiness read. Record this as an evidence qualification item; it does not establish an existing failure or justify a new public error diagnostic.
- **Stream timing behavior difference.** The current [`stream.js`](../../../open-sse/utils/stream.js) sets `ttftAt` when the transform receives its first provider chunk, before identifying whether that chunk carries content, reasoning, or a tool call. [`streamingHandler.js`](../../../open-sse/handlers/chatCore/streamingHandler.js) records that timestamp relative to request start. The #14919 patch distinguishes first user-visible output from first provider chunk and adds a bounded output probe. This changes the definition of the already-used first-provider-chunk latency metric and introduces an output timing distinction. Existing [`stream-completion-chunks.test.js`](../../../tests/unit/stream-completion-chunks.test.js) covers first-chunk timestamp propagation and completion snapshots; [`stream-first-chunk-timeout.test.js`](../../../tests/unit/stream-first-chunk-timeout.test.js) covers the transport timeout. No existing failure is established. Report the behavior difference and exclude changing the metric contract absent an existing failure.
