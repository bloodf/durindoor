## Current tree evidence

- MiniMax usage is implemented in [`open-sse/services/usage/minimax.js`](../../../open-sse/services/usage/minimax.js). It branches count interpretation by endpoint (`/coding_plan/remains` means remaining; token-plan counts mean used), computes `used`/`remaining`, honors provider percentages, and supports the newer percent-only M-series buckets. The dashboard helper `ProviderLimits/utils.js` rounds displayed percentages. Existing offline fixtures in [`tests/unit/minimax-usage.test.js`](../../../tests/unit/minimax-usage.test.js) cover token-plan used counts, coding-plan remaining counts, percent-only M-series buckets, and their display names. [`tests/unit/provider-quota-normalizers.test.js`](../../../tests/unit/provider-quota-normalizers.test.js) also covers MiniMax count consistency, representative quota selection, and invalid/ambiguous values.
- The current MiniMax quota normalizer in [`open-sse/services/quota/providers/codingPlans.js`](../../../open-sse/services/quota/providers/codingPlans.js) has offline fixtures in [`tests/unit/provider-quota-normalizers.test.js`](../../../tests/unit/provider-quota-normalizers.test.js) for used and remaining semantics, supplied remaining percentages, and rejecting ambiguous counts. This newer normalized display path is distinct from the legacy provider usage response.
- Current legacy Copilot parsing in [`open-sse/services/usage/github.js`](../../../open-sse/services/usage/github.js) assigns `limited_user_quotas` directly to `used` and derives no remaining count in its Free/limited branch. By contrast, current normalized dashboard parsing in [`open-sse/services/quota/providers/github.js`](../../../open-sse/services/quota/providers/github.js) treats those values as remaining; [`tests/unit/provider-quota-normalizers.test.js`](../../../tests/unit/provider-quota-normalizers.test.js) verifies chat total 50 / remaining 5 / used 45 and completions total 100 / remaining 90 / used 10. Thus the field meaning is represented correctly in the normalized path, but a demonstrable inversion remains in the legacy response parser. No live provider request was made.
- The confirmed retirement record in [`1072-retired-model-catalog-5781.md`](1072-retired-model-catalog-5781.md) remains untouched. These quota patches establish no retirement facts or plan limits; do not infer or alter retirement data, limits, or billing from them.
