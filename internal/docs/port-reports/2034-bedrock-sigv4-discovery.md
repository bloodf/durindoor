## Gap evidence

Before this change the local executor already used the real runtime SDK with the
selected region, `buildBedrockClientAuth`, and a routed request handler. The
helper selects profile, static keys or bearer credentials, and reads a temporary
session token only from the encrypted top-level field. No tracked SigV4 model
discovery existed. The private embedding discovery is bearer-only and not
equivalent. Discovery was therefore missing, and this unit implements it.

## Behavior

- **Operations.** Discovery calls `ListFoundationModels` with
  `byOutputModality=TEXT`. It then pages `ListInferenceProfiles` with
  `typeEquals=SYSTEM_DEFINED` and `maxResults=100`, for at most 10 pages. Page
  tokens are limited to 4096 characters and may not repeat. These are read-only
  control-plane calls, so nothing is invoked or billed. Calls do not take a quota
  dispatch ticket. The SDK serializes `typeEquals` as the `type` query key, which
  follows the AWS API reference. The source's `typeEquals` query key is not copied.
- **Credentials.** Discovery reuses `detectBedrockCredentialMode` and
  `buildBedrockClientAuth` without changing them.
  - *Bearer:* the API key is sent only as `Authorization: Bearer`. The SigV4
    identity is replaced by a refusing provider.
  - *Static and profile:* requests use SigV4 only (`authSchemePreference:
    ["sigv4"]`). The bearer identity is replaced by a refusing provider, so the
    action client cannot switch to `AWS_BEARER_TOKEN_BEDROCK`. A named profile
    still uses its configured credential chain; this is not a restriction on that chain. The secret access key is never sent.
  - *Session token:* the token comes only from the encrypted top-level
    `sessionToken`. A session token without an access key id is refused as a
    configuration error. It is never treated as a key pair.
  - *Profile:* the shared helper uses `fromIni`. The source has no profile mode,
    so this is a local extension. Discovery now refuses effective proxy, relay and
    strict routes before constructing the provider; effective direct remains supported.
- **Origin.** The endpoint is pinned to
  `https://bedrock.<region>.amazonaws.com`. The region comes from
  `resolveBedrockRegion`, which accepts only a valid region and ignores arbitrary
  base URLs. FIPS and dual-stack are disabled, and `AWS_ENDPOINT_URL*` is ignored
  because the endpoint is explicit. The request handler refuses any other origin
  before sending, including STS/SSO hosts. The separate profile credential chain
  does not share this action-transport boundary.
- **Redirects.** Requests use `redirect: "manual"`. A 3xx response, an opaque
  redirect, or an answer from another origin is refused without being followed.
- **Proxy.** The default transport is `proxyAwareFetch` with
  `resolveCredentialProxyOptions(credentials, proxyOptions)` for Bedrock actions.
  Profile credential networking has no selected-proxy guarantee; bound routes
  are refused using the existing merged route helpers.
- **Abort and deadline.** The caller's `AbortSignal` and a single total deadline
  are applied. The deadline defaults to 30 seconds, is capped at 60 seconds, and
  bounds caller wait, including while credentials resolve. It does not cancel
  separate profile credential networking or credential processes. The action
  handler applies cancellation and a 2 MiB body cap to Bedrock responses only;
  those guarantees do not cover profile credential responses.
- **Validation.** A foundation list that is missing or has a malformed row fails
  as `invalid_response`. Inference-profile failures follow the source: auth
  failures are fatal, and other failures keep the foundation models and add a
  warning. Refusals, aborts and timeouts are also fatal.
- **Errors.** Each `BedrockDiscoveryError` has a fixed message, a `kind`
  (`auth`, `quota`, `config`, `upstream`, `refused`, `unavailable`,
  `invalid_response`, `aborted` or `timeout`), a `status` and a sanitized
  `code`. Upstream bodies, credential-provider output and secrets are never
  included. Errors have no `cause`.
- **Normalization.** Results are sorted and de-duplicated. Capabilities are
  reported only where AWS declares them. The source set `supportsStreaming:
  true` on profiles and ARN-derived models; here those values are `null`. No
  token limits or prices are produced, because the source's limits came from a
  model-spec table that DurinDoor does not carry.

## Evidence

All commands ran under `env -i` with a private HOME/DATA_DIR/TMPDIR/cache/store
under `/var/tmp/bedrock2034.Ws407B`, an explicit PATH, `LANG=en_US.UTF-8`,
`CI=true`, `AWS_EC2_METADATA_DISABLED=true`, `timeout 300` and
`--maxWorkers=2`. No provider credentials were set. Test dependencies were
installed with `pnpm install --frozen-lockfile --ignore-scripts` into the
private copy's `tests/`. No shared graph was borrowed, repaired or relinked.

- New discovery suite plus the untouched AWS credentials suite:
  2 files and 61 tests passed (35 + 26).
- The same pair plus `native-bedrock-embedding` and
  `bedrock-credential-boundaries`: 4 files and 128 tests passed.
- `eslint` on the new module and test reported no findings.
- Mutation checks were run on the private copy and then restored. Each one made
  tests fail:
  - removing the pinned endpoint: 8 tests failed (ambient `AWS_ENDPOINT_URL_BEDROCK`);
  - removing the mode guard: 7 failed (the ambient bearer token is preferred
    over SigV4);
  - following redirects: 2 failed;
  - removing the outer deadline race: 1 failed (a hung profile resolver);
  - allowing FIPS: 8 failed.

Test boundaries: the real `@aws-sdk/client-bedrock` serializer, SigV4/bearer
signers and deserializer run. Only `proxyAwareFetch` (network) and `fromIni`
(profile credential provider) are mocked. Ambient `AWS_*` variables are set to
decoy values in every test, and the AWS config and credentials files point to
nonexistent paths. Fixtures cover two synthetic accounts in two regions, static
IAM keys, a temporary encrypted top-level session token, and the mocked profile
resolver. They also cover abort, deadline, redirect, foreign origin, auth, quota,
config, upstream, transport, invalid, oversized and pagination cases. Signatures
are checked for structure (credential scope, signed headers, hex signature) and
for sensitivity to the secret. They are not checked against an independent SigV4
oracle.

**Not proven:** no request was sent to AWS. Live AWS calls are prohibited for
this unit. Accepting the SDK's real wire format against the Bedrock control
plane still depends on the SDK itself and needs a later authorized live check.
The local run is not the exact-head isolated native gate.
