### Executor repair

Scope: `open-sse/executors/blackbox-web.js` only. `chatCore.js`, `src/**`, the shared web-session base, the global retry policy and the shared fixture are unchanged.

- Session check. A non-success `/api/auth/session` answer is handled before `sendBillable`, and its body is discarded. A redirect, 401 or 403 becomes the existing 401/403 expired-session refusal, and 429 becomes the rate-limit refusal; both keep ordinary sibling fallback. Every other status, and a 2xx answer that is HTML, malformed JSON, not an object or `null`, or unreadable within the body deadline, becomes a redacted 502 (504 at the deadline) carrying the existing `claudeRequestScoped` marker. Nothing was billed. The marker exists because the outer single-model transient retry would otherwise repeat a session 502 three times, which the pinned 502 assertion forbids. The consequence is that an unexplained session failure does not rotate to a sibling. The session document is passed on unchanged, and no identity field is synthesized. An unreadable optional subscription answer leaves the cache unset, as a non-ok one already did.
- After the chat send. A transport rejection, an HTTP status other than 401, 403, 429 or a redirect, a 2xx HTML body (typed or untyped), an empty body and a body deadline all return a redacted `upstream_outcome_unknown` error with `claudeRequestScoped` and `upstreamPartialOutput`. Both markers already stop account fallback (`singleModel/postProcess.js`) and the outer transient retry, the same path used by Z.ai and DeepSeek. A body that fails mid-read rethrows its original error with `claudeRequestScoped` attached, because `web-session-executor-base.test.js` requires the throw and a `transport_error` settlement. A client abort after dispatch throws a request-scoped `AbortError`. A local quota denial is rethrown unchanged. Explicit 401/403/429 answers, and the existing login, rate-limit and upgrade text answers, keep ordinary fallback. No success completion or `[DONE]` is emitted for unproven work.

Acceptance added to the existing suite (46 cases): stored client-key authorization across both imported accounts with strict proxies, for OpenAI and Anthropic, buffered and streamed. A request without a key is refused before any network call, and a successful turn records a non-error usage row for the admitted key. Session HTML, malformed JSON, array JSON and 503 each stop before the chat with exactly one session call. Chat 401/403/429 and session 429 fall back to the second account. Eight uncertain chat outcomes, each across the four dialect/stream combinations, make exactly one session/chat pair on the selected account and proxy: reset, 500, 502, typed HTML, untyped HTML, empty, partial-then-reset, and a stalled body at the 100 ms fixture deadline (504). Two cases cover a client abort after dispatch, with a controlled promise signalling when the chat body opens. These cases check cookie, provider-body and partial-text redaction, and check that no row is a success and at most one row exists.
