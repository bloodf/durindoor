**Status: NOT PARITY; focused test not run locally.** The real registry's `webLogin` contract names `https://www.perplexity.ai`, `__Secure-next-auth.session-token` and its numbered chunk prefix. It declares no optional cookies or localStorage keys. The extension uses the same profile. The registry's auth hint also mentions `__Secure-pplx.session.<UUID>` and `pplx.session-id`, but neither name is in this capture/import allowlist. A header containing only those names is refused because the required legacy cookie is absent. This is a bounded reproduction of a contract mismatch, not evidence that the newer cookies currently work for live sign-in. A later single-owner repair would need to reconcile the registry, extension allowlist and importer validation with the actual provider session contract, then test the executor's outbound credential handling; this unit does not enable that path.

The new focused file joins the real profile to extension capture, pairing/import and storage, then passes the retrieved connection to the existing executor using a mocked upstream response. It also exercises the real parser for Cookie, cURL and HAR and checks selected-update isolation, rejection and redaction. All credentials and network/browser boundaries are synthetic. The management guard and SQLite adapter boundary are mocked; the actual repository and in-memory SQLite migrations are used.

The test is intended to cover legacy contiguous chunks and a single legacy cookie. It does not prove live authentication, the current provider's actual sign-in behavior, proxy routing, full account selection through the gateway, or the upstream response protocol. Browser execution and provider network access were not performed. No upstream source was consulted or upstream behavior claimed.
