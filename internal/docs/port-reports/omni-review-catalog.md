## Verified candidate gaps in open pull requests

The following 5 open pull requests represent verified gaps in DurinDoor's provider catalogs, model metadata, or model routing. Each has been validated against local source code and upstream PR diffs.

### 1. Liquid AI API endpoint migration and model refresh

- **Pull request:** [OmniRoute #21343](https://github.com/cheaper-inference/OmniRoute/pull/21343) (`fix(providers): move Liquid AI to api.liquid.ai/openai/v1`)
- **Exact upstream head:** [`fd6446baa7c47d33d9c7e09eaae90445a498b898`](https://github.com/cheaper-inference/OmniRoute/commit/fd6446baa7c47d33d9c7e09eaae90445a498b898)
- **Local target file:** [open-sse/providers/registry/liquid.js](../../../open-sse/providers/registry/liquid.js)
- **Evidence:** Liquid AI's official documentation defines its active OpenAI-compatible endpoint at `https://api.liquid.ai/openai/v1`. The legacy host `https://api.liquid.ai/v1` returns HTTP 401 `Could not validate credentials` when queried with current API keys. In DurinDoor, `open-sse/providers/registry/liquid.js` still configures `baseUrl: "https://api.liquid.ai/v1/chat/completions"` and `validateUrl: "https://api.liquid.ai/v1/models"`, and pins the retired model `liquid-lfm-40b`. Upstream moves `baseUrl` to `https://api.liquid.ai/openai/v1/chat/completions`, `modelsUrl` to `https://api.liquid.ai/openai/v1/models`, and refreshes the default chat catalog to `lfm3-1.7b`, `lfm3-vl-2b`, and `lfm2.5-24b-a2b` while dropping `liquid-lfm-40b`. Any user configuring Liquid AI in DurinDoor currently fails connection validation and inference.
- **Porting scope:** Update endpoints and default model list in `open-sse/providers/registry/liquid.js`, run `pnpm run gen:registry-index`, and add a unit test in `tests/unit/` verifying Liquid AI endpoint resolution.

### 2. Route advertised Claude reasoning-effort variants to live base model

- **Pull request:** [OmniRoute #21347](https://github.com/cheaper-inference/OmniRoute/pull/21347) (`fix(sse): route advertised Claude effort variants through their live base model (KEA-9625)`)
- **Exact upstream head:** [`a50680baf8f237f3747fa3ceee397faee7c8b0fe`](https://github.com/cheaper-inference/OmniRoute/commit/a50680baf8f237f3747fa3ceee397faee7c8b0fe)
- **Local target file:** [src/sse/services/model.js](../../../src/sse/services/model.js)
- **Evidence:** When `/v1/models` advertises Claude reasoning effort variants (such as `cheaperinference/claude-haiku-4.5-high` or `cheaperinference/claude-haiku-4.5-low`) for third-party connections with live model discovery, incoming inference requests specifying these suffixed model IDs fail with HTTP 400 because only the unsuffixed base model (`claude-haiku-4.5`) exists in the synced catalog table. Upstream strips effort suffixes (`-low`, `-medium`, `-high`, `-max`), matches the live base model, and sets `resolvedThinkingEffort` on the request context. DurinDoor's `src/sse/services/model.js` lacks this resolution branch for synced third-party providers.
- **Porting scope:** In `src/sse/services/model.js`, resolve suffixed Claude effort variant IDs against the active synced catalog's base model and forward `resolvedThinkingEffort`.

### 3. Expose OpenRouter decision models in System One catalog

- **Pull request:** [OmniRoute #21302](https://github.com/cheaper-inference/OmniRoute/pull/21302) (`fix(api): list OpenRouter decisions models in the decision catalog`)
- **Exact upstream head:** [`6e4202849f5fc706ff77864fceb15cb26ee701ba`](https://github.com/cheaper-inference/OmniRoute/commit/6e4202849f5fc706ff77864fceb15cb26ee701ba)
- **Local target files:** [open-sse/services/openrouterCatalog.js](../../../open-sse/services/openrouterCatalog.js), [src/app/api/v1/systemone/route.js](../../../src/app/api/v1/systemone/route.js)
- **Evidence:** OpenRouter hides its decision models (e.g. `openrouter/typesafe/jev-1.13`) from default `GET /api/v1/models` responses unless the client queries with `?output_modalities=decisions`. Upstream queries both unparameterized and parameterized endpoints and merges the results so that `GET /v1/systemone/models` populates OpenRouter decision models when an OpenRouter connection has synced models. DurinDoor's `open-sse/services/openrouterCatalog.js` only fetches the unparameterized endpoint, leaving OpenRouter decision models omitted from the catalog.
- **Porting scope:** In `open-sse/services/openrouterCatalog.js`, fetch `?output_modalities=decisions` alongside the default listing and retain decision model IDs in the synced models catalog.

### 4. TrustedRouter API-key provider registration

- **Pull request:** [OmniRoute #21364](https://github.com/cheaper-inference/OmniRoute/pull/21364) (`feat(providers): add TrustedRouter API-key provider`)
- **Exact upstream head:** [`91b54071eeec9c5c6d306c90c7738a2999f6b11d`](https://github.com/cheaper-inference/OmniRoute/commit/91b54071eeec9c5c6d306c90c7738a2999f6b11d)
- **Local target files:** `open-sse/providers/registry/trustedrouter.js` (new), [open-sse/providers/capabilities.js](../../../open-sse/providers/capabilities.js)
- **Evidence:** Upstream adds TrustedRouter (`trustedrouter`) as an OpenAI-compatible API-key provider with base URL `https://api.trustedrouter.com/v1`, live model discovery, default embedding models, and UI metadata. DurinDoor currently has no configuration or registry file for `trustedrouter`.
- **Porting scope:** Add `open-sse/providers/registry/trustedrouter.js`, configure discovery in `src/app/api/providers/[id]/models/modelsConfig.js`, regenerate registry indexes, and add acceptance test.

### 5. Liquid AI native System One decisions API routing

- **Pull request:** [OmniRoute #21338](https://github.com/cheaper-inference/OmniRoute/pull/21338) (`feat(api): route liquid/<model> decisions to Liquid AI's native System One API`)
- **Exact upstream head:** [`9bcaa77898e644255949ce94123a6899fc0e2dd0`](https://github.com/cheaper-inference/OmniRoute/commit/9bcaa77898e644255949ce94123a6899fc0e2dd0)
- **Local target files:** [src/app/api/v1/systemone/route.js](../../../src/app/api/v1/systemone/route.js), `open-sse/config/systemOneRegistry.js`
- **Evidence:** Upstream routes `liquid/<model>` (`liquid/d1`, `liquid/d1.2`, `liquid/d1.2-ultra`) decisions requests directly to Liquid AI's native decisions API (`https://api.liquid.ai/decisions/v1/systemone`) authenticated using the configured `liquid` connection key. DurinDoor's System One router only recognizes `typesafe`, `cloudflare-ai`, and `ollama-local`, returning HTTP 400 for any `liquid/*` decision model.
- **Porting scope:** Register `liquid` backend in System One router and dispatch decisions payloads to `https://api.liquid.ai/decisions/v1/systemone`.
