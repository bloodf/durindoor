# Port batch 1: open upstream PR candidates

Source: [open-prs-nov25-01.md](open-prs-nov25-01.md). The work order asked for port candidates 1–8. The report has seven, so all seven are listed. All are `decolua/9router` PRs. On 2026-11-25 each was still open, and its diff was read with the GitHub API at the head SHA in the source report. No live provider was called.

Two rows are marked **not ported (declined)**. That is deliberately outside the other three dispositions: the behaviour is missing locally and could be written, but it was not.

| Source row | PR | Final disposition | Evidence |
|---:|---:|---|---|
| 1 | [#5840](https://github.com/decolua/9router/pull/5840) | ported in this change | [sttCore.js](../../../open-sse/handlers/sttCore.js) merges both field spellings into `timestamp_granularities[]`, drops duplicates and values other than `word` or `segment`, and omits the field unless `response_format` is `verbose_json`. This changes earlier behaviour, which forwarded the fields unchanged. The registry providers on this path are Groq, local Whisper, NaN, OpenAI and Together. Gemini, Deepgram, Cloudflare and the native speech formats use other paths and are unchanged. Test: [port9r-stt-timestamp-granularities-5840.test.js](../../../tests/unit/port9r-stt-timestamp-granularities-5840.test.js). |
| 3 | [#5838](https://github.com/decolua/9router/pull/5838) | already present | The upstream bug comes from restricting TLS to `X25519`, which this PR widens. DurinDoor never sets `ecdhCurve`: a search of `open-sse`, `src`, `cli` and `custom-server.js` finds no `ecdhCurve` or curve override. Outbound TLS therefore keeps the Node default, which is `auto` on the required Node 24.22.2 and is not limited to one curve. The source report read the missing setting as a gap. No AWS handshake was made. |
| 4 | [#5837](https://github.com/decolua/9router/pull/5837) | ported in this change | Cookie-Editor arrays, bare or under `cookies`, are now parsed by [gemini-web.js](../../../open-sse/executors/gemini-web.js). Entries for other domains and entries that are unsafe in a Cookie header are dropped. Test: [port9r-gemini-web-cookie-export-5837.test.js](../../../tests/unit/port9r-gemini-web-cookie-export-5837.test.js). The other two parts are not ported. Rotated `__Secure-1PSID*` cookies are already written back after a successful response (`persistRotatedCookies`, covered by [gemini-web-provider.test.js](../../../tests/unit/gemini-web-provider.test.js)). Upstream also merges every other `google.com` cookie and writes back after failed requests; the local code deliberately keeps only the three auth cookies. The failed-image fast-fail is not applicable: the local provider serves only `llm` and has no `open-sse/executors/gemini-web/imageGen.js`. |
| 20 | [#5733](https://github.com/decolua/9router/pull/5733) | not ported (declined); the rest already present | The dual-use sentence, both pasted-content forms and the bare and CLI identity lines are already rewritten in [appConstants.js](../../../open-sse/config/appConstants.js), covered by [port-5847-antigravity-system-prompt.test.js](../../../tests/unit/port-5847-antigravity-system-prompt.test.js). One difference remains, for the identity line with the Agent SDK suffix: the local rule rewrites the first part and leaves the suffix. Closing it only serves to stop Antigravity's backend from recognising which client is calling, that is, to get past a third party's check. It was left unchanged. |
| 22 | [#5730](https://github.com/decolua/9router/pull/5730) | ported in this change | [capabilities.js](../../../open-sse/providers/capabilities.js) now marks `@cf/mistralai/mistral-small-3.1-24b-instruct` as vision-capable. The other half was already present: [paramSupport.js](../../../open-sse/translator/concerns/paramSupport.js) leaves content parts alone for vision models. Image support on Workers AI rests on the upstream PR's statement and was not checked live. Test: [port9r-cloudflare-mistral-vision-5730.test.js](../../../tests/unit/port9r-cloudflare-mistral-vision-5730.test.js). |
| 26 | [#5725](https://github.com/decolua/9router/pull/5725) | not ported (declined) | The PR adds tool-name aliases so that other applications pass the gates on OpenCode's free tier, and splits upstream sessions by calling application so that each gets its own anonymous quota pool. Both exist to get past a third party's access and quota controls. Nothing from the PR was ported, including its unrelated development-only `allowedDevOrigins` setting. Existing local OpenCode behaviour is unchanged. |
| 27 | [#5712](https://github.com/decolua/9router/pull/5712) | already present | The `launcherProcess.js` cleanup helpers the PR edits (`stopRecordedInstance`) do not exist locally. In [processScan.js](../../../cli/src/lib/processScan.js), `collectAppPids` excludes the current process and every ancestor (`ownProcessChain`), and `portOccupantToKill` applies the same rule to the port owner. That covers more than upstream's self and parent. Test: "never targets our own process or any ancestor" in [process-scan.test.js](../../../tests/unit/process-scan.test.js). |
