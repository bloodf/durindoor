## Found while porting, not changed

Deleting a combo on the Combos page still removes its `comboStrategies` entry by leaving the key out of the PATCH. Because the settings store merges that map by key, the stored entry survives while any other key remains, and a new combo with the same name would pick it up. This is a separate defect from the eight rows. An existing assertion in [combos-page-delete-feedback.test.js](../../../tests/unit/combos-page-delete-feedback.test.js) expects the current request body, so a fix must change that expectation.
