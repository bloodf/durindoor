## 4472 breakdown

Parts of this PR that were not ported:

- **Tool-name restoration across translation pivots and namespaces — already present.** The probe saw both same-named namespace children sent under distinct names, and the reply restored `name: "js"`. DurinDoor returns `namespace` as its own field and uses its own alias names, so upstream's exact-name assertions do not apply.
- **Native Codex CLI terminal validation — already present.** The passthrough branch in [stream.js](../../../open-sse/utils/stream.js) adds `response.failed` when no successful terminal arrives, and [emptyStreamTerminal.js](../../../open-sse/utils/emptyStreamTerminal.js) failed upstream's reasoning-only case. Upstream's "valid answer" fixture, with no text delta and no output in the completed snapshot, was also judged empty here. Real Codex streams send text deltas, so no change was made.
- **`length` and `content_filter` as `response.incomplete` — already present.** Upstream's two cases passed unchanged.
- **Failing reasoning-only or unknown-finish Chat streams inside the Responses translator — not taken.** Here the translator completes unknown finish reasons (#1331), and empty-output handling belongs to the pipeline guard, which counts reasoning as output. Changing that is a routing policy change.
- **Item ordering and unusable tool calls — not taken.** DurinDoor keeps a message open until `finish_reason` so interleaved tool calls cannot close it. A call with a blank name is still emitted, and an unannounced partial call still ends as completed.
- **Buffered JSON converter changes** (`nonStreamingHandler.js`, `sseToJsonHandler.js`, `streamToJsonConverter.js`) **and the OpenCode fingerprint edits — not evaluated case by case.** Upstream's tests for these paths extend files that have diverged here and were not run. They remain open for a later pass.
