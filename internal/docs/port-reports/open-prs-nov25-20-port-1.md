# Port report — open PR batch 20, port candidates

Scope: the port candidates of [the batch 20 dispositions](open-prs-nov25-20.md). That report has seven port-candidate rows, so this change covers seven, not eight. On 2026-11-25 each PR was open and its current diff was fetched with `gh api`. Each head matched the SHA in its source row. All seven are OmniRoute PRs.

An earlier commit on this branch names one of these PR numbers: `8f7f353489d` (`#20993`). It does not cover the gap in row 781.

| Row | PR | Final disposition | Evidence |
|---:|---|---|---|
| 762 | OmniRoute [#21084](https://github.com/cheaper-inference/OmniRoute/pull/21084) | ported in this change | [The session manager](../../../open-sse/utils/sessionManager.js) now keys a Codex conversation on its connection, model, system prompt and first user message. A client session id still wins. A request without a user turn keeps the old fallbacks, and other providers are unchanged. The key is used for `prompt_cache_key`, the `session_id` header and the request log tag. It now comes before the assistant-text hash, so it stays the same from the first turn to later turns. A client that changes its system prompt or first user message between turns gets a new key. A Gemini-shaped body (`contents`) keeps the old fallbacks. Not adopted: upstream also reads the `x-opencode-session` and `x-claude-code-session-id` headers for Codex, and does not treat an opaque `metadata.user_id` as a session id. DurinDoor still does, so a client that sends one such id for all conversations still shares one key. Test: [conversation key](../../../tests/unit/portor-codex-conversation-cache-key-21084.test.js). |
