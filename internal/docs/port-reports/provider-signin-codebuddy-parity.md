# CodeBuddy CN sign-in comparison (#2034)

This comparison records supported paths and remaining integration gaps; it is not a claim of complete parity. No live accounts or provider calls were used. Sources are MIT-licensed projects at the pinned commits: [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI/tree/dbe641f286a489ecb39e3c041c554371e6add864), [EasyCLIProxyAPI](https://github.com/router-for-me/EasyCLIProxyAPI/tree/29567ead8164a00724dfdc2087f02a23895636ee), and [OmniRoute](https://github.com/cheaper-inference/OmniRoute/tree/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523).

## Production

For CodeBuddy China, select CodeBuddy CN and start OAuth in the dashboard, open the returned authorization URL, and approve it. The existing provider object sends a POST to `/v2/plugin/auth/state?platform=CLI`, then polls `/v2/plugin/auth/token?state=...`; code 11217 is pending. The existing route owns the flow and omits PKCE for this provider. Refresh uses `/v2/plugin/auth/token/refresh` with `X-Refresh-Token`, retaining the old refresh token if rotation is absent. API-key and auth-token modes are also exposed in the registry. Chat uses the China host, bearer authorization and forced streaming. The registry model list is static; the per-connection models endpoint rejects CN discovery without making a provider request. A rejected usage credential is reported without its HTTP body.

The pinned OmniRoute [CN adapter](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/src/lib/oauth/providers/codebuddy-cn.ts) delegates to [device auth](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/src/lib/oauth/providers/codebuddyDeviceAuth.ts). It sends `{}` for the state body, while production sends `{"platform":"CLI"}`. Both use the platform query and accept `authUrl` or `url`. Its [refresh implementation](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/open-sse/services/tokenRefresh/providers/codebuddyShared.ts) uses the same refresh header and retention rule. The [registry](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/open-sse/config/providers/registry/codebuddy-cn/index.ts) describes authenticated `/v3/config` discovery; it is not implemented in this change.

The pinned CLIProxyAPI tree has no CodeBuddy-named source path; its [executor registration](https://github.com/router-for-me/CLIProxyAPI/blob/dbe641f286a489ecb39e3c041c554371e6add864/sdk/cliproxy/service_executors.go) includes generic and plugin mechanisms, so the filename inventory does not rule out operator-defined support. EasyCLIProxyAPI also has no CodeBuddy-named source path; its [management API](https://github.com/router-for-me/EasyCLIProxyAPI/blob/29567ead8164a00724dfdc2087f02a23895636ee/src-tauri/src/management_api.rs) delegates OAuth and import requests to a core. Neither path establishes a CodeBuddy wire contract. OmniRoute's [CLIProxy import route](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/src/app/api/oauth/cliproxy-import/route.ts) is a generic importer, not evidence of a CodeBuddy-specific CLI credential format. Local CN `import-token` and authorization-code exchange are rejected before a provider request; no CN session or CLI import contract was identified.

CodeBuddy International is a separate local API-key provider; users supply its key through its own connection UI. Do not send that key to the China host. The pinned OmniRoute tree includes a separate [International adapter](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/src/lib/oauth/providers/codebuddy-intl.ts); it is not registered locally as an OAuth provider. Local device flow lookup rejects it before network access.

## Staged integration and remaining work

`src/lib/oauth/providerParity/codebuddy/state.js` exports `codebuddyStateBody`, `codebuddyStateFailure`, `codebuddyPollFailure`, and `codebuddyUsageFailure`; `registration.json` identifies the provider-object integration slot. Neither export is registered in production. The helper changes the state body to match the pinned source and supplies fixed state, poll, and usage failures. Production currently includes upstream text in state errors and can expose provider messages in poll and usage errors; the helper alone does not fix those paths. Integration slots are recorded in the manifest. The route uses a five-minute maximum flow lifetime; cancel invalidates the storage claim but the provider poll does not receive an abort signal.

The focused test exercises real provider entry points, refresh, the executor and usage handler with mocked transports and synthetic credentials. It checks concurrent state/proxy separation, pending and successful polls, refresh rejection and retention, distinct chat credentials, forced streaming and stream normalization, the local catalog, expired usage credentials, flow ownership, duplicate polls, cancellation and expiry. It does not establish live authenticated discovery, transport cancellation, or comprehensive production error redaction. Existing regression files are unchanged.
