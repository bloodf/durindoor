# #2034 Copilot sign-in comparison

## Source and scope

- CLIProxyAPI (MIT), [internal/auth/copilot/client.go at dbe641f286a489ecb39e3c041c554371e6add864](https://github.com/router-for-me/CLIProxyAPI/blob/dbe641f286a489ecb39e3c041c554371e6add864/internal/auth/copilot/client.go): GitHub public device grant, account and session exchange, `read:user`, `copilot/1.0.114` editor identity, and an allowlist of public Copilot API hosts. Its model requests add `Copilot-Integration-Id: copilot-sdk` and `X-GitHub-Api-Version: 2026-09-21`. It bounds polling by device expiry, refuses redirects, and rejects missing or expired session tokens. Request and stream source is `internal/runtime/executor/copilot_executor.go` and `copilot_executor_response.go`; this is not a GHE contract.
- EasyCLIProxyAPI (MIT), [src-tauri/src/agents/copilot/setup.rs at 29567ead8164a00724dfdc2087f02a23895636ee](https://github.com/router-for-me/EasyCLIProxyAPI/blob/29567ead8164a00724dfdc2087f02a23895636ee/src-tauri/src/agents/copilot/setup.rs), configures a VS Code integration and secret reference; `detection.rs` locates VS Code. These files do not implement GitHub device sign-in or inference transport. Treating them as that protocol would invent a source contract.
- OmniRoute (MIT), [src/lib/oauth/providers/ghe-copilot.ts at b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/src/lib/oauth/providers/ghe-copilot.ts) uses guarded outbound fetch and refuses redirects. It also has a GHE Cloud `/api/v3/copilot_internal/user` fallback that uses the OAuth token at the returned API endpoint; that fallback is not implemented here because this unit cannot establish the host trust boundary required before sending that credential. [src/lib/oauth/providers/copilot-m365-web.ts](https://github.com/cheaper-inference/OmniRoute/blob/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523/src/lib/oauth/providers/copilot-m365-web.ts) supplies the supported M365 native-client PKCE flow, not GitHub device OAuth.

## Current production behavior

- **GitHub:** choose GitHub Copilot, visit the displayed device URL and enter the code. The device grant uses client `Iv1.b507a08c87ecfe98` and `read:user`; the OAuth API profile uses `GitHubCopilotChat/0.26.7` and API version `2022-11-28`. Gateway request headers use `vscode/1.110.0`, `copilot-chat/0.38.0`, and API version `2025-04-01`. The CLI now uses the returned polling interval and expiry, stops after success, supports cancellation and does not expose upstream error bodies. It exchanges the OAuth credential for a separate Copilot session token. Session refresh and request routing remain in the existing gateway; see `tests/unit/github-copilot-parity-pass.test.js`, `copilot-refresh-proxy-1472.test.js`, and `copilot-endpoint-contract-1073.test.js`.
- **GHE:** enter the enterprise HTTPS origin and complete its device grant. Its host and proxy options remain attached to that flow; the adapter sends OAuth and session exchange to that origin and records returned endpoints. It now disables automatic redirects and filters poll responses. Existing `ghe-copilot-signin-parity.test.js`, `ghe-copilot.test.js`, and `ghe-copilot-route.test.js` cover parts of sign-in, refresh and discovery. HTTPS normalization alone does not protect DNS resolution or validate token-supplied endpoints; full host safety and the source's GHE Cloud fallback are unresolved and must not be presented as parity.
- **M365:** select Microsoft 365 Copilot, authenticate a work or school account and paste the full native-client callback URL. The existing adapter binds state and PKCE to the shared flow, uses `openid profile offline_access https://substrate.office.com/sydney/M365Chat.Read https://substrate.office.com/sydney/sydney.readwrite`, and rejects consumer identities. `tests/unit/copilot-m365-signin.test.js` exercises sign-in, refresh and mocked Chathub requests. No live tenant was contacted.

## Staged integration and limitations

`src/lib/oauth/providerParity/copilot/index.js` exports `decodeCopilotPollResponse`; `registration.json` identifies the future central slot `src/lib/oauth/providers.js` → `github.pollToken` response decoding. The enterprise adapter already uses the decoder; the public web provider is not registered to it. The decoder preserves known device states and token fields while dropping upstream descriptions and unrelated fields. The existing OAuth provider object, shared flow ownership, and storage remain authoritative.

The configured GHE host and returned endpoint still need a connection-aware outbound guard compatible with DNS rebinding protection and proxy dispatch before GHE host safety can be claimed. CLIProxyAPI's public API allowlist cannot simply be applied to arbitrary enterprise deployments. Source-wide request/stream and session-expiration parity has not been fully proved, and this change does not claim it. Existing tests above are useful evidence, not substitutes for that comparison.
