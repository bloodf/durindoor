## DurinDoor paths

The active dashboard provider object in `src/lib/oauth/providers.js` uses Google's authorization-code flow and existing state/ownership flow store. It requests offline consent and cloud-platform, email and profile scopes using the operator-configured `GEMINI_OAUTH_CLIENT_ID` and `GEMINI_OAUTH_CLIENT_SECRET`; it exchanges the code, fetches user info and attempts `loadCodeAssist`. Project lookup failure is tolerated. It does not use PKCE or perform onboarding during this post-exchange step. Device authorization is unsupported. The Gemini CLI runtime can discover models with `fetchAvailableModels`, refresh tokens, send Cloud Code requests and stream responses; quota preflight can reject an exhausted model. The new closed-network tests exercise the real route, database, executor, refresh service, catalog resolver and quota policy using synthetic credentials. They cover concurrent state-bound flows and account-specific requests, replay and expiry, unsupported device initiation, model discovery, refresh rejection and aborted dispatch. Translator implementation and its replay coverage belong to the separate CPA replay unit.

The current model discovery refresh path reads `GEMINI_CLIENT_ID` and `GEMINI_CLIENT_SECRET` rather than the sign-in configuration and passes its proxy as the logger argument. The current OAuth exchange includes upstream failure text in its error. Neither web path is changed by this unit. `src/lib/oauth/providerParity/gemini-cli/index.js` stages `exchangeGeminiCode` and `refreshGeminiDiscoveryToken`; `registration.json` names the exact slots for the ordered web batch. The first rejects missing client configuration before transport and returns only the HTTP status on upstream failure. The second uses the same supplied configuration and forwards the selected proxy in the refresh service's fifth argument. The batch must retain the existing flow store, ownership checks, proxy selection and connection persistence. These staged helpers are not active until registered.

The standalone `src/lib/oauth/services/gemini.js` has no production caller found in this checkout and imports the absent `src/lib/oauth/config/index.js`, so it cannot be treated as an operational CLI path. Its callback code generates state without validating it; do not wire it into production without correcting and testing that issue. Neither pinned core defines a supported Gemini CLI onboarding protocol; adding one here would invent a contract. Runtime project discovery and translator behavior have existing separate implementations and are not changed by this unit.

For the active dashboard path, select Gemini CLI, start authorization, sign in to Google and complete the callback. The stored connection may lack a project if discovery fails. CLIProxyAPI users need the separately supplied plugin and its instructions; EasyCLIProxyAPI's Gemini API-key setup is a different mode. OmniRoute's cited revision reports this provider discontinued. These steps and limitations are based on source inspection, not live accounts.
