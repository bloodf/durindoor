## Local production

Choose **Qoder** for global or **Qoder CN** for China in the dashboard, start device sign-in, and authorize the generated link in that region. The existing provider handlers generate a verifier, S256 challenge, nonce and machine ID per flow, poll the matching regional endpoint, and store the resulting token and identity in the existing connection model. The existing route owns flow validation and persistence. A device token is not refreshed by the Qoder executor; reconnect when expired. PATs use the existing job-token exchange path. Model discovery and signed chat use the regional resolver and executor. They are existing local behavior, not claimed to match OmniRoute's experimental OAuth.

The service now rejects already-expired issued tokens, returns only HTTP status for rejected device polls and a fixed error for malformed JSON, because upstream bodies can contain credentials. Profile lookup remains best effort. The focused contract checks concurrent regional flows, PKCE binding and ownership, replay, rejection, expiry, request timeout, no device-token refresh, regional model and chat identity, proxy routing and stream unwrapping. Existing Qoder regression files cover further catalog, request and stream behavior; they were not changed here.

## Shared wiring

The staged `assertQoderWebAction` export rejects authorization-code and token-import actions for both variants. Its integration slot is the existing OAuth POST dispatcher, before flow creation or network calls; see `src/lib/oauth/providerParity/qoder/registration.json`. Until integrated, `authorize` returns a device flow record with a null authorization URL rather than rejecting it. Invalid exchange and import requests are rejected without network access. Do not enable OmniRoute's experimental authorization-code flow without a supported configured contract and the existing ownership/state guards. Session login and CLI import have not been established by the inspected sources and are not added.
