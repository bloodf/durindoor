# Trae sign-in comparison, issue #2034

Sources: MIT-licensed [OmniRoute](https://github.com/cheaper-inference/OmniRoute/tree/b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523) `b15b2ee6ac0f57af254be4a3cc60ba8a6cc9a523`, [CLIProxyAPI](https://github.com/router-for-me/CLIProxyAPI/tree/dbe641f286a489ecb39e3c041c554371e6add864) `dbe641f286a489ecb39e3c041c554371e6add864`, and [EasyCLIProxyAPI](https://github.com/router-for-me/EasyCLIProxyAPI/tree/29567ead8164a00724dfdc2087f02a23895636ee) `29567ead8164a00724dfdc2087f02a23895636ee`. Recursive GitHub trees for both CLIProxy projects were not truncated and contain no Trae-named paths; a text search of the pinned sources finds only external Quotio Desktop references in CLIProxyAPI README translations and generic plugin snapshot comments in `sdk/cliproxy/model_registration_issue6718_test.go`, not an implementation; EasyCLIProxyAPI has no matching Trae, Cloud-IDE-JWT, or MarsCode text. The referenced Trae plugin is not present in these trees. No CLI import, device, PKCE, or code-exchange contract is established by that evidence.

DurinDoor production registers `trae` as `import_token` in `src/lib/oauth/providers.js`. Sign into the Trae web client, copy the Cloud-IDE-JWT from its authorization header and import it through the provider connection form. Optional identity, region, and timezone fields feed the SOLO request. The pasted session has no refresh token; re-import on expiry. `open-sse/executors/trae.js` creates a chat session and reads its event stream. Models are a static registry, not remote discovery. `tests/unit/trae-signin-parity.test.js` covers the existing import and translation behavior.

Request errors (production, this change): `open-sse/executors/trae.js` used to copy the create-session response body, a rejected create payload and the provider's error-event message into the client error, so upstream text could reach callers. It now returns only fixed text. Create-session and events-stream HTTP 401 and 403 stay 401 and 403 (re-import the session), and 429 stays 429 with a numeric `Retry-After`. Any other upstream failure becomes 502. An error event keeps only a code that looks like an opaque identifier. Caller aborts, local quota gates and transport failures classified by DurinDoor are rethrown so the gateway keeps their provenance. A streaming response has already sent its 200 header, so a later events-stream failure appears as an SSE error chunk whose `code` holds the upstream status. This changes an obsolete DurinDoor contract and departs from OmniRoute `b15b2ee6` `open-sse/executors/trae.ts`, which returns 502 for every case with sanitized upstream text. The source does not define a quota-specific error-event code, so none is mapped. `tests/unit/provider-signin-trae-parity.test.js` covers these cases through the executor and the real `handleChatCore` gateway, using a mocked transport.

OmniRoute's `src/lib/oauth/providers/trae.ts` and `src/app/api/oauth/trae/import/route.ts` implement session import. Its distinct desktop-style browser callback uses `src/app/api/oauth/trae/authorize-state/route.ts`, `src/lib/oauth/traeLoginState.ts`, `src/app/authorize/handleCallback.ts`, and `src/app/authorize/parseCallback.ts`: the user signs into Trae in the same browser, approves the authorization popup, and the loopback `/authorize` callback receives credentials. Its one-use state is consumed before storage. `open-sse/executors/trae.ts` refreshes callback credentials through `ExchangeToken`, with host validation in `open-sse/utils/traeHost.ts`; its `open-sse/config/providers/registry/trae/index.ts` lists static models. This callback and refresh do not exist in DurinDoor production. There is no separate authorization-code exchange or device polling in this implementation.

The staged `src/lib/oauth/providerParity/trae/callback.js` exports `parseTraeApiHost`, `parseTraeCallback`, `refreshTraeCallbackCredentials`, and `requireTraeImportMode`. The earlier `traeRequestFailure` export is removed because the executor now handles errors itself. `registration.json` names the central integration slots: issue and claim the existing owned OAuth state, consume it before the connection is created, bind refresh to the connection proxy and abort signal, and guard generic unsupported actions before any upstream work. Current generic authorize can create a null-URL flow, so the staged guard is needed before that route is considered supported. The helper neither registers a route nor stores credentials. The ordered auth batch must complete and verify those slots before exposing the callback; until then the browser steps above apply only to OmniRoute. Imported sessions must not be treated as callback credentials.
