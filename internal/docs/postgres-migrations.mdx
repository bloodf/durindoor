description: SQLite-to-PG generation, reserved and shared migrations through 025, DML rewrite, and the synchronous worker.

The main SQLite schema is the baseline for the parallel PostgreSQL migration set under `src/lib/db/migrations/postgres/`. PostgreSQL-specific tables, including the cutover log and proxy timeline, have explicit generator cases. Operator cutover, rollback, and compose profiles are on [Postgres](../../docs/operations/postgres.mdx). Add a shared SQLite migration, then regenerate the PG files.

The PG engine is DurinDoor-owned. Do not send a PR to `decolua/9router` for it.

## Startup mode invariant

Packaged startup calls `normalizeProcessEnv()` before app imports and removes exact empty environment values. A nonempty `DURINDOOR_PG_URL` or `DURINDOOR_DATABASE_ENGINE=postgres` selects explicit PostgreSQL. The explicit engine selector remains fail-closed with a missing or empty URL. `src/lib/db/driver.js` uses a presence check internally, so direct module tests that bypass normalization can observe different empty-value behavior. Preserve the entrypoint ordering and test it with `tests/unit/normalize-env-6828.test.js`; an empty shipped Compose value is compatible with SQLite startup.

## Layout

```text
src/lib/db/
  schema.js                         TABLES, the declarative SQLite schema
  migrations/                       SQLite set (001-018 and 020-025)
  migrations/postgres/              generated PG set (do not hand-edit)
  dialects/postgres/translate.js    SQLite DDL -> PG DDL (generate time)
  dialects/postgres/dmlRewrite.js   SQLite DML -> PG DML (request time)
  dialects/postgres/mirror.js       TRUNCATE, quoted idents, COUNT(*)
  dialects/postgres/snapshot.js     currentDataFile() -> currentBackupsDir()
  dialects/postgres/cutoverLog.js   pgCutoverLog writer
  adapters/pgAdapter.js             same run/get/all/exec/transaction surface
  adapters/pgSyncWorker.cjs         worker thread; pg.Pool max 1
  cutover.js                        test, migrate, snapshot, mirror, flip
  cutoverLock.js                    in-process mutex; freeze live HTTP writes
  postgresFallback.js               explicit PG boot and legacy SQLite fallback
  postgresCapabilityGate.js         per-version feature map
  secrets.js                        encrypted postgresUrl on the settings row
```

Both engines reach version 25 (`025-proxy-timeline.js`). Shared versions must use the same `{version,name}` pair. Additive main-database tables in `schema.js` `TABLES` (including `apiKeyGroups`) come from PG `001-initial.js` on a fresh cluster. The PostgreSQL timeline tables come from migration 025; SQLite 025 is a version stamp because SQLite keeps its existing timeline sidecar.

## Numbering

`pgCutoverLog` is a PG-only **version**, not a special-cased 018.

- SQLite 018 is `api-key-groups`.
- PG 018 is the same name (no-op; tables already come from 001).
- PG 019 creates `pgCutoverLog`. The generator always emits that file.

The checker compares `{version,name}` for every SQLite entry and permits reserved PG-only versions. PG 019 remains reserved for the cutover log; do not reuse it or renumber an applied migration. Shared migrations 020-024 re-export dialect-aware implementations for token-saver and usage schema changes. Migration 025 shares its identity but emits PostgreSQL timeline DDL through the generator.

## Add a migration

<Steps>
<Step>
Add `00N-name.js` under `src/lib/db/migrations/` and export `{ version, name, up(db) }`. Append it to `migrations/index.js`. `up` receives the SQLite adapter.

</Step>
<Step>
If the change is a new column on an existing table, add the column to the `TABLES` entry in `schema.js` as well. PG `001-initial.js` is generated from `TABLES`, so a column that exists only in a later SQLite file never appears on a fresh PG install.

</Step>
<Step>
Regenerate the PG set:

```bash
node scripts/migrate-sqlite-ddl-to-pg.mjs
npm run check:postgres-migrations
```

`check:postgres-migrations` is `node scripts/check-postgres-migrations.mjs`. It runs the generator with `--check` (byte-identical files) and then compares `{version,name}` across the two `index.js` registries. Exit 1 on drift or a name mismatch. Extra PG-only versions (currently 019 `pg-cutover-log`) pass.

</Step>
<Step>
Most additive SQLite files become version-stamp stubs on PG because bootstrap already created the table. The generator's `NO_OP_MIGRATIONS` set lists those filenames. `009-encrypt-credentials.js` is a separate no-op (rows mirrored from SQLite are already encrypted; new writes go through `columnCrypto`). `018-api-key-groups.js` is emitted as a no-op the same way. `019-pg-cutover-log.js` is always emitted as the PG-only log table.

Unhandled numbered SQLite files are not emitted. Put a true no-op in `NO_OP_MIGRATIONS`, or add a special case next to `009` / `017`, then re-run the generator.

</Step>
</Steps>

Do not edit files under `migrations/postgres/` by hand. Change their generator case or shared implementation, regenerate, and run the drift checker.

## DML rewrite

The DDL translator runs at generate time. Repos still emit SQLite DML. `src/lib/db/dialects/postgres/dmlRewrite.js` rewrites those shapes inside the PG adapter before placeholders become `$1, $2, …`:

| SQLite | Postgres |
| --- | --- |
| `INSERT OR IGNORE INTO …` | `INSERT INTO … ON CONFLICT DO NOTHING` |
| `INSERT OR REPLACE INTO …` | `INSERT INTO … ON CONFLICT (<pk>) DO UPDATE SET …` |
| `datetime('now')` | `CURRENT_TIMESTAMP` |
| `col = ? COLLATE NOCASE` | `LOWER(col) = LOWER(?)` |
| camelCase identifiers | quoted (`"isActive"`) so PG does not fold them |

`INSERT OR REPLACE` takes the declared primary key from `TABLES`, including composite keys (`kv` is `("scope", "key")`). Naming only the first column is not unique; PG rejects that with `42P10`.

Extend `dmlRewrite.js` when a repo grows a SQLite idiom this file does not cover. Add a case in `tests/unit/db/dmlRewrite.test.js`. Do not teach the generator to rewrite request-time DML.

## DDL translator

`src/lib/db/dialects/postgres/translate.js` runs at generate time, not at request time.

| SQLite | Postgres |
| --- | --- |
| `INTEGER PRIMARY KEY` / `AUTOINCREMENT` | `BIGSERIAL PRIMARY KEY` |
| `INTEGER DEFAULT 0/1` boolean-looking columns | stays `INTEGER` so repos can keep `=== 1` checks |
| `TEXT`, `TEXT NOT NULL`, `TEXT PRIMARY KEY` | unchanged |
| `REAL` | `DOUBLE PRECISION` |
| `datetime('now')` | `CURRENT_TIMESTAMP` |
| `PRAGMA table_info(name)` | `information_schema.columns` query |
| `INSERT ... ON CONFLICT(...) DO UPDATE` | unchanged (PG 9.5+) |
| `CREATE INDEX ... COLLATE NOCASE` | `CREATE INDEX ... LOWER(col)` |

`last_insert_rowid()` is not rewritten in SQL. `pgAdapter` appends `RETURNING id` on `INSERT` for `BIGSERIAL` tables.

The translator does not convert JSON columns to JSONB (they stay `TEXT` for `columnCrypto`). It does not encode PG 17/18 features in DDL. The capability gate turns those on at runtime.

## Sync worker

Production `pgAdapter` does not talk to `pg.Client` on the Next.js event loop. A worker thread (`src/lib/db/adapters/pgSyncWorker.cjs`) owns a `pg.Pool` with `max: 1`. The parent blocks on `Atomics.wait` so `get` / `run` / `all` stay synchronous, matching better-sqlite3. Tests inject `clientFactory` and stay async.

The initial shared buffer is 8 MiB. Larger results use an exact-size secondary buffer while preserving success/error status. The parent rejects serialized results above 32 MiB before allocating that secondary buffer. A rejected result must leave the next query usable.

`next.config.mjs` traces `pgSyncWorker.cjs` into the standalone output (`outputFileTracingIncludes` for `/api/**/*` and `/*`). `pg` is in `serverExternalPackages`. Operators on Docker or the npm CLI do not configure this. Contributors packaging a custom Next standalone build must keep that include, or production `get`/`run`/`all` cannot start the worker.

## Capability gate

`src/lib/db/postgresCapabilityGate.js` reads `server_version_num` and computes effective state for every key in `DEFAULT_FEATURES`. Defaults target PG 18. Entries that `require: ">=19"` stay off.

To add a toggle:

1. Add `{ enabled, requires: ">=N" }` to `DEFAULT_FEATURES`.
2. Update `CapabilityMatrix` in `src/app/(dashboard)/dashboard/settings/database/components/CapabilityMatrix.jsx` if the UI needs a new column.
3. Add a case in `tests/unit/db/postgresCapabilityGate.test.js` for majors 16, 17, 18, and 19.

## Adapter contract

`src/lib/db/adapters/pgAdapter.js` matches the SQLite adapters:

- `run` / `get` / `all` rewrite DML, then `?` to `$1, $2, ...`.
- `exec` splits on `;` plus newline.
- `transaction` uses `BEGIN` / `COMMIT` / `ROLLBACK` with savepoints.
- `close` is idempotent. `flush` and `checkpoint` are no-ops.
- `capabilities.isPostgres` is `true`. `sharedFileTransactions` is `true` (quota reservations use `SELECT … FOR UPDATE` via `QUOTA_WRITE_LOCK_SQL_PG`).
- `serverVersionNum` / `serverVersion` come from `SHOW server_version_num` / `SHOW server_version`.

## Cutover lock and secrets

`cutoverLock.js` is the in-process mutex. `wrapCutoverGuard` on the live adapter rejects mutating SQL while the lock is held. Fresh adapters opened by cutover itself are not wrapped. A second cutover returns HTTP 503 with `Retry-After: 5` from `POST /api/settings/database/cutover`.

`src/lib/db/secrets.js` is the only sanctioned reader of the Postgres URL. New writes go to `settings.postgresUrl` (AES-256-GCM, AAD `postgres-url`). `DURINDOOR_PG_URL` wins at boot. `DATA_DIR/durindoor-secrets.json` (mode `0600`) is a read-only legacy fallback. `GET /api/settings` and `GET /api/settings/database/engine` must not return the password or `postgresUrl`.
