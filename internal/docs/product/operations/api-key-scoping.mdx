Zero relation rows mean unrestricted account access. Key and relation replacement are transactional; deleting the last scoped connection is refused so it cannot silently widen access. Native resources retain creator identity for ownership/accounting, and pins cannot fall back. Media billing units remain outside token/USD limits.

## Preserved pre-rewrite snapshot

Baseline `0e7307831`, captured 2026-10-07. All original prose, examples, tables, and technical material are retained below, with relative links relocated. Historical deployment examples and fixed line numbers may be stale.


Each API key can be limited to named provider-connection rows. A key with no join rows stays unrestricted, including legacy `sk-<8 hex>` keys. You opt in by assigning at least one connection.

The join table is `apiKeyProviderConnections(apiKeyId, connectionId)` (migration 014). `apiKeys.policy.allowedModels` is a separate allowlist. The two stack. There is no `apiKeys.scope` or `apiKeys.connections` column.

Minting and expiry stay on [API keys](../../../../docs/guides/api-keys.mdx). Dashboard **API Keys** (`/dashboard/keys`) exposes the same list as **Provider accounts**. The field hint is "Leave empty for unrestricted access." An empty selection shows "No scoped accounts" and "This key can route through every provider account."

## Zero-row rule

Zero relation rows means every provider account. Sending `providerConnectionIds: []` deletes the rows and restores that default. Omitting the field on `PUT /api/keys/[id]` leaves the current scope.

Ids are a deduplicated array of live `providerConnections.id` values. A bad shape, a missing id, or a duplicate returns HTTP 400 and writes nothing.

## Atomic write

`createApiKey` and `updateApiKey` accept `providerConnectionIds`. When the field is present, the key row and the join replace run in one SQLite transaction. Missing connections abort before commit.

## Deletion guard

Deleting a provider connection (or a provider node, which cascades) that is the last scoped account for a key would silently widen that key. The repo rejects the delete with HTTP 409 and `API_KEY_SCOPE_WOULD_BROADEN`.

Clear the restriction first: dashboard keys UI, or `PUT /api/keys/[id]` with `providerConnectionIds: []`. Then retry the delete. The guard runs inside `deleteProviderConnection` and `deleteProviderConnectionsByProvider`, so single, bulk, and node deletes all hit it.

## HTTP

| Method | Behaviour |
| --- | --- |
| `GET /api/keys` | Each key includes `providerConnectionIds`. The payload also has `providerConnections`: `{ id, name, provider }` options. No credentials. |
| `GET /api/keys/[id]` | Same shape for one key. |
| `POST /api/keys` | Optional `providerConnectionIds`. Secret mint and machine id are unchanged. |
| `PUT /api/keys/[id]` | Optional `providerConnectionIds`. Omit to keep, `[]` to clear. |
| `DELETE /api/keys/[id]` | Removes the key. Join rows cascade (`ON DELETE CASCADE`). |

Dashboard **API Keys** is the usual editor. Use one key per tool so a scoped leak cannot ride every account on the box.

## Native inference and resources

Native HTTP and WebSocket routes enforce model scope after alias resolution and apply the selected provider-account scope. Nested execution models receive the same checks. Account-bound operations require `x-connection-id`; failed pins cannot select a sibling account.

Tracked native resources store the creator's stable API-key id with the provider, connection, resource id, and creation model. Completion usage belongs to that creator, not to an operator or another polling key. GET/cancel/delete ownership checks precede vendor dispatch. Missing/deleted creator keys cannot transfer completion charges to the polling key. Local/operator-owned resources do not charge an unrelated key.

Native Anthropic file/batch operations and MiniMax voice-category lists retain vendor account-wide semantics. Assign those accounts only to clients you trust with the account's resources.

Keys with usage/rate limits cannot submit native background/batch inference or mint direct ephemeral sessions. Those paths can continue outside the gateway's observable response. Gateway-relayed WebSockets can account for reported terminal usage.

Reported token usage commits before a terminal HTTP/SSE/WS result becomes usable. A request that spends the last allowance keeps its successful output; the next admission fails. Unsupported media billing units remain outside token/USD accounting: text-input estimates do not measure charges per character, image, second, or generation. Set vendor-side budgets for those products.
