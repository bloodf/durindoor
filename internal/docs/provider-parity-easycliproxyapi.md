## How to read the upstream contract

EasyCLIProxyAPI is a desktop management client around a separately versioned CLIProxyAPI core. Its UI defines guided OAuth and API-key setup, while core credential files/configuration define runtime routing and model discovery. OAuth providers below are built-in UI flows. Plugin OAuth is extensible and delegated to installed core plugins; the source does not provide a closed inventory of third-party plugin providers. “OpenAI-compatible” is a user-supplied endpoint/protocol, not a finite vendor catalog.

Public source: [README OAuth and API provider overview](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md), [guided setup provider definitions](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx), [management OAuth provider normalization and callbacks](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs), [provider groups/config editing](https://github.com/router-for-me/EasyCLIProxyAPI/tree/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/core_config).

## Runtime boundaries and non-provider surfaces

- **Outbound native vs delegated:** The desktop UI owns OAuth initiation/callback collection, connection editing, and generic API-key endpoint/model configuration. Actual upstream request dispatch, protocol conversion, credentials on disk, and the canonical `v1/models` catalog are delegated to the embedded CLIProxyAPI core. Core plugin OAuth/providers are delegated again to installed plugins. Desktop `src-tauri/src/provider_health.rs` probes configured endpoints and reads the local core model catalog; that is management behavior, not a separate upstream executor.
- **API-key-only / endpoint configuration:** Gemini, Gemini Interactions, Vertex AI, DeepSeek, Meta API, and arbitrary OpenAI-compatible entries are guided API-key configuration choices. Codex, Claude, and xAI expose both OAuth and API-key choices; OAuth-only guided choices are Antigravity, Kimi, Devin, and Muse/Meta. This describes the app forms, not all core-supported auth modes.
- **Network/local:** Provider API entries can specify a custom base URL and proxy. The local CLIProxyAPI server is the inbound gateway, not an upstream provider. Local model servers are reachable when entered as compatible endpoints; the current setup page does not define a dedicated Ollama/LM Studio provider selector. Do not count arbitrary LAN URLs as individually native provider integrations.
- **Inbound compatibility:** The local gateway accepts supported OpenAI, Claude/Anthropic, Gemini, and compatible protocol shapes and converts requests/responses for configured upstreams. These are inbound client protocols, not provider identities. Compatibility claims in README are broad; exact route/model coverage depends on core version and provider executor.
- **Client setup:** EasyCLIProxyAPI also configures local agents/clients (including Claude Code, Codex, Pi and others) to use the local gateway. Those clients are inbound callers, not upstream providers. See [README client configuration overview](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md).

## Antigravity observations (no implementation changes)

Both projects have Antigravity as an explicit OAuth provider identity. DurinDoor has a dedicated registry entry and provider-scoped capability handling. EasyCLIProxyAPI’s UI lists Antigravity OAuth, while runtime execution/catalog belongs to the embedded core. Repository `source:omniroute` leads #20342/#20314 cover native reasoning-family models and effort tiers; #20559/#20547/#20001 include remote-image handling among mixed protocol changes; #20428/#19807/#19621 include an age-verification challenge/unlock item among mixed provider fixes; #20433/#20317 are Gemini-related, not proof of Antigravity changes. The cited inventory is issue/PR-title evidence only. No live provider access was attempted and no Antigravity source was edited.
