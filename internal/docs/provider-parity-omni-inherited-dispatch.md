## Pinned comparison

- DurinDoor `main`: [`8f93eadf5e506baea4b386937764a668d45acf55`](https://github.com/bloodf/durindoor/tree/8f93eadf5e506baea4b386937764a668d45acf55).
- OmniRoute `release/v3.8.55`: [`4624250231f49ed118fb4522a9d735e4894322c6`](https://github.com/cheaper-inference/OmniRoute/tree/4624250231f49ed118fb4522a9d735e4894322c6).
- Tracking request: [DurinDoor #2034](https://github.com/bloodf/durindoor/issues/2034).

This inventory follows the composed provider registry, shared OpenAI-compatible executor defaults, connection-key validation and catalog path. No live endpoint, account, paid service, credential, browser session, or credential extraction was used. “Inherited” is resolved from source rather than treated as anonymous. “Active gap” means the exact upstream provider identity/endpoint contract is absent from the pinned DurinDoor registry; generic OpenAI-compatible support is transport capability, not an equivalent provider registration.

## Runtime trace

On OmniRoute, [`providers/index.ts`](https://github.com/cheaper-inference/OmniRoute/blob/4624250231f49ed118fb4522a9d735e4894322c6/open-sse/config/providers/index.ts) composes each identity module. [`shared.ts`](https://github.com/cheaper-inference/OmniRoute/blob/4624250231f49ed118fb4522a9d735e4894322c6/open-sse/config/providers/shared.ts#L324-L335) makes `buildOpenAiCompatibleRegistryEntry` default to `format: openai`, `executor: default`, `authType: apikey`, and `authHeader: bearer`. The registry adapter and request dispatch are in [`providerRegistry.ts`](https://github.com/cheaper-inference/OmniRoute/blob/4624250231f49ed118fb4522a9d735e4894322c6/open-sse/config/providerRegistry.ts) and [`DefaultExecutor`](https://github.com/cheaper-inference/OmniRoute/blob/4624250231f49ed118fb4522a9d735e4894322c6/open-sse/executors/default.ts). For these entries, configured API keys are sent as Bearer credentials. `modelsUrl` and static `models`/`passthroughModels` define catalog discovery; an absent or empty static catalog does not mean the provider is absent.

On DurinDoor, [`registry/index.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/providers/registry/index.js) composes entries and [`schema.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/providers/schema.js) defines transport defaults. [`DefaultExecutor`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/executors/default.js#L640-L665) inserts a configured key as `Authorization: Bearer …`; [`base.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/executors/base.js#L200-L225) provides shared request headers. Connection testing is routed by [`src/app/api/providers/[id]/test/testUtils.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/src/app/api/providers/%5Bid%5D/test/testUtils.js#L600-L625), and models use [`open-sse/services/model.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/services/model.js) and the provider model map. The API-key default means wiring a provider row to the existing executor supplies standard Bearer insertion; it does not by itself prove the provider's validation endpoint or catalog behavior.
