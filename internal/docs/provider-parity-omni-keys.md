The merged OmniRoute inventory's 69 unmatched IDs are the candidate universe, not proof of missing functionality. The existing inventory at DurinDoor `56f92efac8a0b00918b7b26dce5423877d53d2b9` and its grouped missing-provider table are leads only: that report used OmniRoute `ab180e32fcdf1f78c96f98a617e17c86e34bf5aa`, so its auth labels and paths were rechecked at the requested revision. No open/closed qualification report was present in this checkout. DurinDoor registration is composed by `open-sse/providers/registry/index.js`; IDs alone are not runtime proof. Its schema and selected provider executors are in `open-sse/providers/schema.js` and `open-sse/executors/`. OmniRoute registration is composed by `open-sse/config/providers/index.ts`, whose entries under `open-sse/config/providers/registry/<identity>/index.ts` select the format/executor and endpoint. All links below are revision-pinned.

Scope includes API-key, anonymous/optional, inherited-auth and explicitly configured local transports. OAuth, device, cookie, browser and session-backed candidates are listed separately and left to the session inventory. “Gap” means no same-identity contract in DurinDoor's composed registry at the pinned revision; a generic OpenAI-compatible endpoint is not vendor identity, catalog or protocol parity. A “candidate equivalent” is explicitly limited to the described transport and does not establish full contract equivalence.

## Scoped candidates

Each gap's acceptance outline is deterministic and offline: register a synthetic connection, inject a fake fetch/server, capture request URL, headers and body, then assert expected model mapping, normalized response and error path. It must assert that no external request occurs. For `auth=inherit`, acceptance must first establish whether the composed shared executor requires, forwards or omits credentials; that contract is not guessed from an omitted registry field.
