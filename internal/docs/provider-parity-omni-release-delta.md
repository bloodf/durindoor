## Routing and credentials contract files

No newly added OAuth callback, token refresh, sign-in state, provider credential, executor registration, or quota implementation was found in the provider-relevant commits between the pins. The concrete source paths to re-check if that conclusion is revisited are the pinned OmniRoute paths above and, in DurinDoor, [`open-sse/providers/registry/index.js`](../../open-sse/providers/registry/index.js), provider executor dispatch in `open-sse/executors/`, and OAuth/refresh dispatch in `src/lib/oauth/` and `open-sse/services/tokenRefresh/`. These are navigation points, not evidence of a new contract in this range.

The other provider-related commits in the range are catalog/metadata compatibility changes (including model aliases, effort-tier exposure, and context-window handling). Provider-health/cache, Responses streaming identity, and unrelated request correctness fixes are excluded as generic upstream bug-fix work. No new provider delta overlaps the unchanged CLIProxyAPI or EasyCLIProxyAPI pins; their lack of newer revisions does not prove parity with OmniRoute.

## Evidence limits

The comparison is pinned to the exact source revisions above and the checked DurinDoor `origin/main` head `8f93eadf`. The API compare includes release merge commits and many non-provider files; classification here is restricted to provider registry composition, OAuth, executor, model catalog/capability, request, and quota surfaces. No live-provider behavior, credential acceptance, pricing availability, or account quota was validated. All proposed acceptance checks use local deterministic fixtures and closed network mocks.
