Snapshot date: 2026-11-20. DurinDoor `main` is pinned at [`8f93eadf5e506baea4b386937764a668d45acf55`](https://github.com/bloodf/durindoor/tree/8f93eadf5e506baea4b386937764a668d45acf55). OmniRoute `release/v3.8.55` is pinned at [`4624250231f49ed118fb4522a9d735e4894322c6`](https://github.com/cheaper-inference/OmniRoute/tree/4624250231f49ed118fb4522a9d735e4894322c6). Public repository sources, public vendor docs and recorded issue dispositions only.

## Dispatch rules used

An exact ID match is not required for equivalent behavior. DurinDoor’s **Custom Providers (OpenAI/Anthropic Compatible)** connection mode dispatches a configured OpenAI-compatible endpoint, while generated provider IDs and aliases resolve through the registry and executor map. OAuth/account imports, browser-cookie scraping, local app-server subprocesses and provider-specific wire formats are distinct transports and are not equivalent merely because they eventually produce chat completions. DurinDoor’s current registry is composed in [`open-sse/providers/registry/index.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/providers/registry/index.js); provider schema and default dispatch live in [`schema.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/providers/schema.js) and [`default.js`](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/open-sse/executors/default.js). The UI and connection path are documented in [OpenAI-compatible nodes](https://github.com/bloodf/durindoor/blob/8f93eadf5e506baea4b386937764a668d45acf55/docs/providers/openai-compatible-nodes.mdx).

The OmniRoute links below point to each provider’s composed registry contract at the pinned SHA. The module’s `executor`/`format`, endpoint and auth fields determine dispatch; names and aliases alone do not. Statuses mean: **active gap** = supported documented contract with no equivalent path; **existing equivalent** = DurinDoor already dispatches the same usable contract through another ID/mode; **retired** = issue disposition or public evidence says do not port; **unresolved** = source advertises a route but current vendor documentation, terms, or supported endpoint evidence is insufficient. “Retired” is a disposition on the candidate as reviewed, not a claim that an entire vendor has shut down.

## Follow-up boundary

Only `zed-hosted` is classified as a documented first-party active endpoint gap in this candidate set. `gisoo`, `grokified`, `megabrain` and `runcrate` require documentation/ownership evidence before they can be promoted from compatible-mode/unresolved to supported vendor integrations. The remaining rows have recorded declines or a meaningful existing connection mode. This is an inventory and disposition, not provider implementation or live acceptance. The focused test paths above are acceptance proposals for any later authorized implementation; they were not created or run in this documentation-only change.
