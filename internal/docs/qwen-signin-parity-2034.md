# Qwen sign-in comparison (#2034)

## Upstream status

At the requested snapshots, [CLIProxyAPI `6eb8554f0ede`](https://github.com/router-for-me/CLIProxyAPI/tree/6eb8554f0ede) and [OmniRoute `5ffa68e83544`](https://github.com/cheaper-inference/OmniRoute/tree/5ffa68e83544) no longer contain the legacy Qwen OAuth implementation to compare. Both snapshots descend from their respective removal commits:

- CLIProxyAPI [removed Qwen support in `8fac29631db5`](https://github.com/router-for-me/CLIProxyAPI/commit/8fac29631db5cbcd69f396592f4718e165464724), deleting its authenticator, token handling, login and executor. The commit describes removing support and cleaning up references, but does not state a more specific reason.
- OmniRoute [removed the deprecated OAuth provider in `65e0aeda79f7`](https://github.com/cheaper-inference/OmniRoute/commit/65e0aeda79f7a9ea21cf0450e5ddda3df361ae37). Its [PR #7866](https://github.com/cheaper-inference/OmniRoute/pull/7866) calls the provider discontinued and explains that the legacy CLI integration was coupled to obsolete configuration; it replaced the CLI integration with a separate API-key configuration.

OmniRoute's remaining Qwen Cloud and Token Plan providers are separate API-key products, not a continuation of the removed OAuth provider. These removals do not establish whether Qwen's own device endpoint remains available.

Snapshot heads resolved 2026-11-20: [CLIProxyAPI `6faa8d20b2673404cff70a2f2d9537ae0d0e684d`](https://github.com/router-for-me/CLIProxyAPI/tree/6faa8d20b2673404cff70a2f2d9537ae0d0e684d), [EasyCLIProxyAPI `e4223d5eefa22a3301ca7e2a28d05897432b07f9`](https://github.com/router-for-me/EasyCLIProxyAPI/tree/e4223d5eefa22a3301ca7e2a28d05897432b07f9), and [OmniRoute `e3c1531afd07d5e06f7ffab658584a7ae2e3627e`](https://github.com/cheaper-inference/OmniRoute/tree/e3c1531afd07d5e06f7ffab658584a7ae2e3627e). GitHub recursive tree inventories contain no Qwen-named source in either CLIProxyAPI or EasyCLIProxyAPI at these heads. CLIProxyAPI's `sdk/cliproxy/service_executors.go` and `internal/registry/model_definitions.go` inventory its current executors and catalogs; they provide no current Qwen OAuth device, refresh, model, quota, or streaming contract. EasyCLIProxyAPI `src-tauri/src/management_api.rs` delegates OAuth start and status to the core management API; its current guided provider inventory has no Qwen option. Delegation does not establish a Qwen contract in a different core version.

OmniRoute's `src/lib/db/migrations/130_remove_unregistered_qwen_data.sql` and its current registry inventory show no Qwen Code OAuth provider; `docs/providers/ALIBABA-QWEN-PROVIDER-FAMILIES.md` and `open-sse/config/providers/registry/qwen-cloud{,-token-plan}/index.ts` describe separate API-key products. `open-sse/services/qwenTokenPlanQuotaFetcher.ts` and `open-sse/services/usage/qwen-token-plan.ts` implement token-plan quota, not OAuth quota. This comparison does not establish that Qwen itself has withdrawn the device endpoint or that any historical credentials remain valid. No logic was ported from these snapshots.

DurinDoor retains the hidden legacy OAuth provider and existing credentials. `src/lib/oauth/providers.js` starts and polls PKCE device authorization, mapping expiry and `resource_url`; the dashboard route `src/app/api/oauth/[provider]/[action]/route.js` binds the device code and verifier to an expiring server-side flow. The separate CLI service has its own polling loop. `open-sse/services/tokenRefresh/providers.js` retains an existing refresh token if a response does not rotate it. `open-sse/executors/qwen.js` uses the saved resource host and selects SSE or JSON accept headers; `open-sse/providers/registry/qwen.js` supplies a static model list. `open-sse/services/usage/misc.js` reports a usage message, not a provider quota response. The `qwen-cloud` and `qwen-cloud-token-plan` registries remain separate API-key identities; token-plan quota is covered by `tests/unit/qwen-token-plan-quota.test.js`.

`tests/unit/qwen-signin-parity.test.js` uses fake credentials and closed mocks for start, poll, expiry errors, refresh, request construction and usage messages. These fixtures characterize local behavior only: they do not validate live sign-in, server-side session expiration, actual SSE response processing, upstream availability, or the completeness of model catalogs. No live provider requests were made.
