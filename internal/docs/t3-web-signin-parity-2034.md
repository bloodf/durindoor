Work order #2034 uses the following pinned source snapshots.

- **CLIProxyAPI `6faa8d20`** has no built-in T3 Chat session, catalog, or executor in the inspected source. OAuth and compatible or plugin executors are extensible. [OAuth handlers](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/api/handlers/management/auth_files_provider_oauth.go) and [executor registration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/cliproxy/service_executors.go).

The desktop revision does not establish installed plugin support. [Guided setup](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx), [management bridge](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs), and [core overview](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md).
- **OmniRoute `e3c1531a`** accepts an existing authorized session as a cookie credential. Its validator probes the site root, its executor posts the selected model, messages, and stream preference to `https://t3.chat/api/chat`, and its connection model route uses the registry catalog. Sign-in is a provider connection flow using a pasted session. [Web provider validation](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/lib/providers/validation/webProvidersB.ts), [executor](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/executors/t3-chat-web.ts), [registry](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/config/providers/registry/t3-web/index.ts), and [model route](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/app/api/providers/%5Bid%5D/models/route.ts).

DurinDoor's existing `t3-web` cookie connection accepts a Cookie header with a nonempty `convex-session-id`. The API also accepts two lines containing `cookies=<header>` and `convexSessionId=<id>`. The provider validation and saved-connection test use a read-only HEAD probe. A 2xx probe establishes reachability with syntactically valid input. The chat request is the check for actual session acceptance. A 401 or 403 rejects the session. Redirects and transport failures give an unavailable result. The models endpoint returns the curated catalog without using the credential.

Use the existing `/v1/chat/completions` route with a model such as `t3/claude-opus-4`. The executor sends the session only as a Cookie header to the fixed T3 Chat endpoint. Redirects and HTTP relays are rejected. Translator previews and request telemetry receive public headers. HTTP error bodies and Set-Cookie headers are discarded. Mock coverage checks request isolation across concurrent connections, JSON, OpenAI SSE, and newline-delimited text events, including OmniRoute's typed text envelope.

Live endpoint availability, session acceptance and model entitlements remain unverified. Deployment-specific server functions, binary TSS framing, tool emulation, media and session renewal are outside the covered contract. SSE passthrough requires a streaming request. The local catalog represents curated model IDs and may differ from an account's actual availability.
