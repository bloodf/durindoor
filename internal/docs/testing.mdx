The suite lives in `tests/`, its own npm package (`9router-tests`). Root `package.json` has no `test` script. Install root, CLI (`cli/`), and test (`tests/`) dependencies. The root/CLI advisory compatibility suite loads the real CLI-only `nodemon` dependency.

## Setup

Node at the repo root is `24.22.2` (`.nvmrc`; engines `>=24.22.2 <25`) and pnpm `12.18.0`.

```bash
pnpm install --frozen-lockfile
pnpm -C cli install --frozen-lockfile
cd tests
pnpm install --frozen-lockfile
```

Set disposable `HOME` and `DATA_DIR` for commands that can touch runtime storage. CI does the same (`HOME` and `DATA_DIR` under the runner temp directory).

## Focused runs

Run from `tests/` so Vitest loads `vitest.config.js`. From the repo root, pass `--config tests/vitest.config.js`.

```bash
cd tests
npx vitest run --config vitest.config.js unit/example.test.js
npx vitest run --config vitest.config.js translator/example.test.js
```

`include` is `**/*.test.js`. The config pins `LANG` and `LC_ALL` to `en_US.UTF-8`, `maxWorkers` to 4, `testTimeout` to 15000, and `maxConcurrency` to 60. It skips `**/.omc/**`, `**/.claude/**`, `**/omp-extension/**`, and `**/*.live.test.js`. Live `*.live.test.js` files hit real upstreams; they are not part of the default or CI run.

Translator tests that call `translateRequest` or `translateResponse` must import `translator/registerAll.js` at the top of the file. `open-sse/translator/index.js` uses `require()` that no-ops under Vitest ESM, so a missing import can produce a false pass.

## Full suite

From `tests/`:

```bash
pnpm exec vitest run --reporter=verbose
```

This runs Vitest directly. The CI and baseline gate is:

```bash
cd tests && pnpm run test:ci
```

`test:ci` runs `tests/__baseline__/run-ci.mjs`. That script:

1. Deletes stale `.test-results.json` and `.test-results.junit.xml`.
2. Runs Vitest with `--reporter=json` and `--outputFile=./.test-results.json`.
3. Writes `.test-results.junit.xml`.
4. Fails closed on missing, stale, or unparseable reports, empty collection, collection failures, runtime errors, and exit/report mismatches.
5. Feeds the JSON report to `tests/__baseline__/verify-no-regression.mjs`.
6. Runs `tests/__baseline__/verify-baseline-diff.mjs` when `BASELINE_BASE_REF` is set (CI sets it to `HEAD^`).

`verify-no-regression.mjs` compares failed assertions against `tests/__baseline__/known-fails.txt`. That file is empty in this tree, so every failing assertion is a regression. Do not add entries. Remove an entry only when a listed failure is fixed. `verify-baseline-diff.mjs` refuses any added line in that file versus `BASELINE_BASE_REF`.

A checked-in `baseline-results.json` is an old report from another tree. It is not a live count for this checkout.

Offline translator tests need no credentials.

## Test groups

- `unit/`: application, API, database, provider, executor, CLI, security, and build contracts.
- `translator/`: offline request/response translation and bug-exposure tests.
- `translator/real/`: credential-backed provider smoke tests. Enabled only with `RUN_REAL=1`.
- `functional/` and route-specific suites: end-to-end behaviour where present.

Bugs that still exist in the app use `it.fails(...)` in `tests/translator/bugs-*.test.js`. After a fix, switch that row to `it` and run the file.

## Real provider tests

```bash
cd tests
RUN_REAL=1 npx vitest run --config vitest.config.js translator/real/
```

Optional filter: `REAL_PROVIDERS=gemini,kiro,codex`.

These tests require `DATA_DIR` to point to a disposable copy of your data directory; they never fall back to `~/.9router`. They consume quota. Run them only with credentials you intend to spend.

`describe.skipIf(!RUN_REAL)` wraps the suites. Account, plan, and quota errors (HTTP 401, 402, 403, 429, and matching error text) are skipped with `console.warn`. Protocol and translation failures remain failures.

Dashboard Playwright is on [Local development](./local-development.mdx).

## Local workflow coverage

See [local CI](./local-ci.md) for the one-command full run, workflow coverage, manual fallbacks and external owner verification. Full runs require registry-index, docs and catalog checks even without a website change, plus standalone and packed CLI smoke checks. Website selection includes shared dashboard/runtime/build inputs. The trigger migration cannot merge until its exact reviewed head passes the externally frozen full gate.

Report acceptance and JUnit generation share terminal-state validation for the locked Vitest 4.1.12 JSON schema. Suites must be `passed` or `failed`; assertions must be `passed`, `failed`, `skipped` or `todo`. Explicit skipped/todo assertions remain valid. Pending, unknown, missing and malformed states fail before aggregation or JUnit output; diagnostic infrastructure failures remain failures.

## V5 Storybook browser evidence

Use a private, disposable environment with synthetic fixture data only. Keep `HOME`, `DATA_DIR`, browser caches and reports private, and exclude provider and publisher credentials from the process. Install the root and test dependencies with their frozen lockfiles, build Storybook with `pnpm run storybook:build`, and install the Playwright browsers matching the test package (for example, `cd tests && node node_modules/playwright/cli.js install chromium firefox webkit`). Browser system libraries must be provided by the environment; do not use sudo from the test run.

From `tests/`, select one engine per run and a registered fixture route, for example:

```sh
RUN_V5_EVIDENCE=1 V5_BROWSER_ENGINE=chromium V5_EVIDENCE_ROUTES=dialog/Modal V5_EVIDENCE_REPORT=/private/path/chromium.json node node_modules/vitest/vitest.mjs run unit/v5-route-evidence.browser.test.js --maxWorkers=2
RUN_V5_EVIDENCE=1 V5_BROWSER_ENGINE=firefox V5_EVIDENCE_ROUTES=dialog/Modal V5_EVIDENCE_REPORT=/private/path/firefox.json node node_modules/vitest/vitest.mjs run unit/v5-route-evidence.browser.test.js --maxWorkers=2
RUN_V5_EVIDENCE=1 V5_BROWSER_ENGINE=webkit V5_EVIDENCE_ROUTES=dialog/Modal V5_EVIDENCE_REPORT=/private/path/webkit.json node node_modules/vitest/vitest.mjs run unit/v5-route-evidence.browser.test.js --maxWorkers=2
```

Omitting `V5_BROWSER_ENGINE` selects Chromium; other names fail validation. `V5_STORYBOOK_DIR` can point to a private built Storybook. Reports identify the engine per case. Screenshots retain the existing Chromium path under `.impeccable/review/v5/production/<route>/`; Firefox and WebKit use `<engine>/<route>/` beneath that directory. Keep these artifacts private and inspect them for sensitive data before sharing.
