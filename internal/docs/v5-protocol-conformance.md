# V5 protocol conformance: issue #1089, evidence units 1 and 2

## Scope and evidence limits

Parent reports the real registered matrix produced three passes and two expected failures, reproducing T7 (`parallel_tool_calls:false` loss) and N1 (Chat JSON leaking into a Gemini reply). This unit repairs those two paths and promotes their `it.fails` assertions to `it`. Those repairs were executed by an independent verifier; no tests, gates, formatters, commits, subagents, live-provider calls, or deployments were run by the writer.

**Verified result.** An independent verifier ran the 12-file acceptance set against a private candidate holding three production fixes and 10 boundary cases: **69 tests, 69 passed, 0 failed, 0 pending, exit 0**, one invocation. The three fixes are N5 (Gemini stream/JSON reasoning parity), T8 (shared Chat→Claude `parallel_tool_calls:false`) and T12 (nested `tool_result` document). Chronology of that set: before the three fixes it was 59 tests with 55 passing and 4 RED (N5 twice, T8, T12); after the fixes and the 10 boundary cases, 69/69. Scope of the claim is exactly those 12 files. It is **not** a full-CI result, not a UI result, and not a live-provider result. U1–U3 remain upstream-pending and this unit closes no issue.

The [issue](https://github.com/bloodf/durindoor/issues/1089) records baseline `93f6de64c69b17d52f790d6f14d09a74cffc7fa5` and OmniRoute snapshot `61e07fb7e0d4e1e76111495d3718c9e4d06d2a62`. Links below describe the checked-out source, not a verified equality between this worktree and either snapshot. Per the parent instruction, fixes on #1075–#1084 branches are not merged here. Their results require integration evidence; this unit neither imports nor duplicates them.

Classification:

- **Already-present (source-supported)**: an implementation or existing assertion represents the stated behavior. It does not mean the test passed, or that all routes support it.
- **Failing expected**: an existing baseline `it.fails` contract. T7 and N1 were reproduced by the parent and are now repaired in source. N5, T8 and T12 were ordinary assertions that went RED in the 12-file acceptance set (55/59) and were repaired in source in a later unit; all three pass in the 69/69 verification above.
- **Unsupported**: the named representation has no supported equivalent in the reviewed contract. Omission is not proof of safe rejection, and this label never excuses silent loss.
- **Upstream-pending**: an open upstream report cited by #1089; no merged upstream fix or local equivalence is claimed.

Coverage is bounded to the four protocol families, their Chat pivot edges, and the named risky features. It is not a claim of all 16 format pairs, every provider, every modality, or HTTP end-to-end conformance. Gaps within a source-supported row remain explicit.

## Repair contract and verification handoff

### Unit 1 (T7, N1) — five paths

1. `open-sse/translator/request/openai-responses.js`: copy defined `parallel_tool_calls`, including false; preserve strict mappings.
2. `open-sse/handlers/chatCore/nonStreamingHandler.js`: repair the actual complete-JSON dispatch, not the streaming translator. Reuse `projectCompletionToClientFormat`; unwrap only Chat→native Gemini and restore tool IDs plus cache/reasoning usage omitted by that shared projector.
3. `tests/translator/v5-protocol-tool-flags.test.js`: promote parent-reproduced T7 to `it`.
4. `tests/translator/v5-protocol-reply-boundaries.test.js`: promote parent-reproduced N1 to `it`; reject both Chat and wrapped envelopes and cover two distinct tool IDs, usage, and native passthrough.
5. `internal/docs/v5-protocol-conformance.md`: record parent evidence, repair scope, and pending verification.

Native Gemini JSON contract: top-level `{ candidates, usageMetadata, modelVersion, responseId }`, never `{ response: ... }` or Chat `choices`. Candidate content uses `{ role: "model", parts }`; tool parts use `{ functionCall: { name, args, id } }` when an ID exists. Arguments are parsed by the existing projector. Finish mappings remain `length`→`MAX_TOKENS`, `content_filter`→`SAFETY`, otherwise `STOP`. Usage retains prompt/completion/total counts, plus `cachedContentTokenCount` and `thoughtsTokenCount` when supplied, including zero. Same-format Gemini bodies return untouched; Gemini CLI, Vertex, Antigravity, streaming, and other upstream paths are unchanged.

Parent verified the repaired assertions and the added identity/usage case. Unit 1's own baseline evidence was three passes and two expected failures; that is unit 1's starting point, not a post-repair pass claim and not the current status. No #1075–#1084 branch fix was copied. Native Gemini streaming wrapper parity, shared Claude parallel limits, and buffered failure HTTP classification remain explicit evidence gaps; of those, shared Claude parallel limits were closed by unit 2 below.

### Unit 2 (N5, T8, T12) — three production paths

1. `open-sse/translator/response/openai-to-antigravity.js`: after `thoughtsTokenCount` is set from `reasoning_tokens`, clamp `candidatesTokenCount` by the same amount with a floor of 0, matching the JSON projector. `promptTokenCount`, `totalTokenCount` and `cachedContentTokenCount` are untouched; the raw upstream total is never recomputed. A usage object with no reasoning detail emits byte-identical output to before.

3. `open-sse/translator/request/claude-to-openai.js`: in the nested `tool_result` loop, a nested `document` with a `http(s)` source contributes a bounded label carrying its URI verbatim; any other source, including a non-`http(s)` URI scheme, throws an `UNSUPPORTED_DOCUMENT` error with `statusCode` 400 rather than being silently dropped or labelled as if it had content.
