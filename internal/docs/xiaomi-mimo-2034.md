Comparison uses the same pins as `antigravity-2034.md`. No live provider calls or real credentials were used.

- [CLIProxyAPI 6faa8d2 configuration](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/config.example.yaml) and [OpenAI-compatible executor](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/internal/runtime/executor/openai_compat_executor.go) provide generic configured API-key routing. The pinned repository tree has no Xiaomi or MiMo named files; this does not prove absence of every generic configuration. No Xiaomi-specific account login, refresh, discovery or quota contract was established there.
- [EasyCLIProxyAPI e4223d5 README](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/README.md) describes a console managing the CLIProxyAPI core and lists its OAuth providers without Xiaomi. It offers generic OpenAI-compatible provider configuration; the README does not establish an independent Xiaomi account flow.
- OmniRoute fbd3396 declares [MiMo API-key transports](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/xiaomi-mimo/index.ts) and a [separate token-plan transport](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/config/providers/registry/xiaomi-mimo-token-plan/index.ts). [#15307's discovery regression](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/tests/unit/xiaomi-mimo-models-fetch-15307.test.ts) exercises their `/v1/models` endpoints. Its [quota service](https://github.com/cheaper-inference/OmniRoute/blob/fbd339668384803bc3a9d42370fc413a55e013d5/open-sse/services/usage/xiaomi-mimo.ts) uses a console session or a tracked monthly fallback; it is not the local Desktop weekly quota flow. These files do not establish Xiaomi account OAuth or session refresh support.

DurinDoor's `src/lib/mimoLoginSession.js` and `open-sse/shared/mimoAccount.js` implement account sign-in and a cached service-cookie handshake; `open-sse/executors/xiaomi-mimo.js` refreshes after a 401 and routes eligible models to the account service. API keys use cloud transports; `open-sse/executors/xiaomi-tokenplan.js` selects a regional token-plan host. `open-sse/services/usage/xiaomi-mimo.js` uses account weekly quota and has an API-key fallback. Existing login redaction and proxy gates remain in place. The discovery change ports the endpoint concept from OmniRoute #15307, preserving local proxy routing and region selection. Unlike OmniRoute's tested fallback, this endpoint returns its upstream error on discovery failure; static registry catalogs remain separate.

Mock tests do not establish live account acceptance, quota accuracy, refresh behavior against Xiaomi, or full request/response parity. They do not justify changing key formats based on synthetic upstream test keys. Session-only rows have no cloud API key and cannot use cloud model discovery.
