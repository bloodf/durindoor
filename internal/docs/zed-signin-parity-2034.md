# Zed sign-in comparison for #2034

This is a source comparison, not an implementation of hosted Zed. The comparison uses CLIProxyAPI `6faa8d20b2673404cff70a2f2d9537ae0d0e684d`, EasyCLIProxyAPI `e4223d5eefa22a3301ca7e2a28d05897432b07f9`, and OmniRoute `e3c1531afd07d5e06f7ffab658584a7ae2e3627e`.

OmniRoute's [`zed-hosted` registry](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/config/providers/registry/zed-hosted/index.ts) explicitly distinguishes its hosted aggregator from `zed` IDE credential import. DurinDoor's `open-sse/providers/registry/zed.js` describes only the latter, with no transport or models. `zed-hosted` must not be aliased to `zed` or reuse unrelated imported provider credentials.

OmniRoute's [OAuth provider](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/src/lib/oauth/providers/zed-hosted.ts) and [shared authentication code](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/shared/zedAuth.ts) generate an RSA keypair for native sign-in, decrypt the callback token, retain the user ID and long-lived access token, resolve an organization, and exchange those credentials for an LLM token. The LLM token authenticates model and completion requests and is reacquired after an expiry signal. The [executor](https://github.com/cheaper-inference/OmniRoute/blob/e3c1531afd07d5e06f7ffab658584a7ae2e3627e/open-sse/executors/zed-hosted.ts) uses a provider-specific request envelope and translates streamed events; it is not a generic bearer-auth chat endpoint. The executor attributes its original port to decolua/9router PR #2328, `open-sse/executors/zed.js`.

CLIProxyAPI's pinned [executor dispatch](https://github.com/router-for-me/CLIProxyAPI/blob/6faa8d20b2673404cff70a2f2d9537ae0d0e684d/sdk/cliproxy/service_executors.go) and `sdk/auth/` have no dedicated Zed hosted executor or sign-in. EasyCLIProxyAPI's pinned [guided selector](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src/pages/EasyModePage.tsx) does not expose Zed hosted; its [management API](https://github.com/router-for-me/EasyCLIProxyAPI/blob/e4223d5eefa22a3301ca7e2a28d05897432b07f9/src-tauri/src/management_api.rs) delegates core operations. Neither establishes a native hosted Zed contract.

DurinDoor does not yet implement this hosted flow. Closed-mock entry-point regressions, credential isolation, request/stream translation and expiry handling remain to be implemented and verified; no live sign-in, endpoint, catalog, quota or streaming behavior was validated in this comparison.

`tests/unit/zed-signin-parity.test.js` records the current unsupported hosted sign-in and checks that the two identities and synthetic flow secrets stay separate. Its passing result is not hosted sign-in or request parity evidence. Replace the rejection assertion when the hosted contract is implemented, and add closed-mock lifecycle and request coverage before claiming parity.
