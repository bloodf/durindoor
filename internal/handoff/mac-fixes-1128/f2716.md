## Goal
These are the findings in the MiniMax review on PR #2716 (`gh pr view 2716 --comments`).
1. **MEDIUM:** `open-sse/utils/sseFrames.js:186` builds the client-observation dispatcher with `preserveWire: true`. `createSseFrameReader` resets its pending buffer only on a blank-line delimiter, so an NDJSON client stream (Ollama, `ollamaTransform.js:87`) accumulates up to 64 MiB, yields 0 frames, and then throws `invalid_sse_payload`. Make the observation path O(1) for line-delimited formats. Either use the shared reader only for blank-line-delimited formats, or give it a line-scoped pending buffer when the timeline format is `ndjson` or `sse-lines`. That restores the per-line behavior of `proxyTimelineFrame.js:78-81`.
2. **LOW:** `streamingHandler.js:252` and `:256` call `clientTap?.onClientEnd()` and `onClientAbort()` without the final batch from `streamHandler.js:187-191`. A stream that ends in a truncated multi-byte character loses its U+FFFD timeline record. Pass the final flush through.
3. **LOW:** `timelineFrameObserver.js:14-19` records a trailing `\n` in the `sse` format (`"data: x\n"`), which the legacy framer dropped. Trim it the way the legacy framer did.

Client bytes must stay byte-identical. Every existing test and assertion is kept.
